# 章节生成与质量检查

## 生成前

在内部写出本章任务卡：

- 本章视角人物与起止地点
- 本章显性目标
- 主要阻力与冲突来源
- 要推进的主线、支线或伏笔
- 本章回报、代价或状态变化
- 章末留下的新问题
- 本章禁止违反的连续性事实

任务卡用于控制创作，不默认展示给用户，也不写进小说正文。

## 场景结构

优先使用有因果关系的场景链：

1. 进入场景时立即建立目标、异常或压力。
2. 让角色采取行动，而不是依靠旁白解释问题。
3. 通过对抗、信息差或资源限制抬高难度。
4. 兑现部分预期，同时制造新的代价或认知变化。
5. 用选择、发现、威胁或不可逆动作结束章节。

每个场景都应改变至少一项状态；删除只重复信息、展示氛围但不推进任何内容的场景。

## 爽感与可信度

爽感由“压制或期待 → 有准备的行动 → 可见结果 → 他人或局势反馈”构成。兑现越大，所需铺垫和代价越充分。

避免：

- 为让主角获胜而让对手忘记已有能力或常识。
- 所有人使用同一种震惊反应。
- 每章重复身份揭露、排名打脸或临时赠宝。
- 只增加数值，不改变主角可完成的事情。
- 主角因作者需要突然失去判断力。

## 对话与叙述

- 让对话承担行动、试探、隐瞒、关系变化或冲突，不让角色轮流讲设定。
- 根据年龄、身份、欲望和关系区分词汇、句长和回避方式。
- 重要情绪优先通过动作、选择和感官细节呈现，再用少量内心说明。
- 战斗或高压场景保持空间关系清晰，记录位置、距离、伤势和资源消耗。
- 默认使用自然的现代中文叙事；题材术语保持一致，不堆砌形容词和网络套话。

## 章节文件

正文文件只包含可发布内容：

```markdown
# 第001章 章节名

<小说正文>
```

概要、爽点、情绪曲线、质量检查和状态变化写入记忆或对话说明，不混入正文，除非用户明确要求编辑版格式。

## 交付前检查

逐项确认：

1. **目标**：本章是否有明确欲望或任务？
2. **变化**：结束时至少一项剧情状态是否真正改变？
3. **因果**：关键结果是否来自既有行动、规则或铺垫？
4. **人物**：动机、语气、能力和已知信息是否连续？
5. **时空**：地点、时间、移动和伤势是否成立？
6. **规则**：能力、系统和世界规则是否越界？
7. **重复**：是否复用了最近章节的同类桥段和反应？
8. **钩子**：结尾是否产生具体而自然的继续阅读动力？
9. **语言**：是否删除解释性重复、空泛感叹和无意义过渡？
10. **状态**：正文保存后是否更新摘要、角色、时间线和伏笔？

发现硬冲突时先修复再交付；只有风格偏好不确定时，保留正文并向用户提供可选调整方向。

## 重写规则

用户要求重写时，先确定范围是句段、场景还是整章。保留未要求改变的事实与后续依赖；如果改动会影响后续章节，列出受影响文件并同步修订记忆。不要在没有说明的情况下覆盖原稿，优先写入带版本后缀的文件。
