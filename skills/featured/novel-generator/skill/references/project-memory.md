- 目录规范

## 目录规范

每部小说使用独立目录：

```text
novels/<project-id>/
├── PROJECT.md
├── 创作方案.md
├── 全局大纲.md
├── chapters/
└── memory/
    ├── STORY_BIBLE.md
    ├── CHARACTERS.md
    ├── LOCATIONS.md
    ├── TIMELINE.md
    ├── PLOT_POINTS.md
    ├── CHAPTER_SUMMARIES.md
    └── ERRORS.md
```

使用稳定的 `project-id`，创建后不要随书名调整而改变。所有路径都必须留在当前对话工作区内。

## PROJECT.md

记录项目入口和当前游标：

```markdown
# 项目：<书名>

- 项目 ID：<project-id>
- 题材：<主类型与混合类型>
- 核心卖点：<一句话>
- 目标篇幅：<章节数或字数>
- 叙事视角：<第一/第三人称与聚焦角色>
- 基准风格：<节奏、语言、受众>
- 当前卷：第 N 卷
- 当前章节：第 N 章
- 当前剧情时间：<故事内时间>
- 状态：策划中/连载中/修订中/完结
- 最近更新：<日期或会话内时间>
```

## 记忆文件职责

- `STORY_BIBLE.md`：世界规则、力量体系、社会结构、金手指规则、硬性禁改设定。
- `CHARACTERS.md`：每个角色的身份、目标、关系、能力、当前位置、已知信息和存亡状态。
- `LOCATIONS.md`：地点特征、空间关系、归属、进入条件和已发生事件。
- `TIMELINE.md`：按故事内时间排列关键事件，记录因果和参与者。
- `PLOT_POINTS.md`：主线、支线、伏笔、承诺、谜题及其状态和回收窗口。
- `CHAPTER_SUMMARIES.md`：每章 100—250 字摘要、状态变化和章末钩子。
- `ERRORS.md`：已发现的一致性或质量问题、处理决定和预防规则。

## 每章提交协议

按以下顺序更新，避免正文与记忆错位：

1. 写入完整章节文件。
2. 向 `CHAPTER_SUMMARIES.md` 追加摘要、状态变化和钩子。
3. 更新发生变化的角色、地点、时间线和伏笔。
4. 新规则写入 `STORY_BIBLE.md`。
5. 更新 `PROJECT.md` 的当前章节、剧情时间和更新时间。
6. 发现问题时写入 `ERRORS.md`，包括证据、修复方案和预防规则。

覆盖文件前先读取当前内容；只更新发生变化的条目，不要重写并丢失其他状态。

## 跨对话迁移

新对话不会自动继承旧对话工作区。需要迁移时，至少导出 `PROJECT.md`、`创作方案.md`、`全局大纲.md`、整个 `memory/` 和最近一章；用户要求完整归档时再包含全部 `chapters/`。

导入后先验证项目 ID、当前章节和最近摘要是否一致，再继续创作。
