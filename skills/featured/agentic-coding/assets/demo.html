验证边界：原 LazyMind 会话生成了代码与测试脚本，但没有实际执行 Python。下面的用例结果是设计期望值，不是自动化测试通过记录。
01 / ACCEPTANCE

先锁定业务规则

原价先 ROUND_HALF_UP 归分，应用折扣后再次归分。保留函数名称与参数；返回类型变化单列给评审。

02 / ROOT CAUSE

三个问题叠加

一次 round() 省略了原价归分；默认舍入方式不等于 HALF_UP；二进制浮点数使边界值难以直接推断。

03 / CHANGE

显式 Decimal 计算

把输入转为 Decimal，分两次 quantize，避免把两个业务步骤压进一个表达式。

04 / HANDOFF

交接包含代价

float → Decimal 影响 JSON 序列化与相等比较。还需确认输入范围、负折扣和存量订单差异。

"""Baseline (defective) implementation — copied verbatim from the report.

Never edited. Kept only so the same check can be run before and after the fix.
"""


def final_price(price, discount):
    return round(price * (1 - discount), 2)


"""Contract-preserving fix for final_price.

Business rule (in order):
  1. round the original price to the cent with ROUND_HALF_UP
  2. apply the discount to that already-rounded price
  3. round the result to the cent with ROUND_HALF_UP

The baseline applied a single round() over an unrounded binary-float product,
so both the price pre-rounding and the HALF_UP tie rule were lost.

Minimal-change notes:
- same module, same function name, same positional signature as baseline
- baseline raised TypeError for None / str input; that failure class is kept
  (no new silent-None semantics were invented by this fix)
- the ONE intentional widening: str and Decimal inputs are now accepted
  (baseline raised TypeError for str and used banker's rounding for Decimal).
  Delete the two branches marked WIDENING to restore strict baseline parity.
"""

from decimal import ROUND_HALF_UP, Decimal

_CENT = Decimal("0.01")
_ONE = Decimal(1)


def _to_decimal(value, *, name):
    """Coerce one input to Decimal without inheriting binary float error."""
    if isinstance(value, Decimal):
        # WIDENING: baseline fed Decimal straight into round() -> banker's rule.
        result = value
    elif isinstance(value, int):
        result = Decimal(value)
    elif isinstance(value, str):
        # WIDENING: baseline raised TypeError (str * float).
        result = Decimal(value.strip())
    elif isinstance(value, float):
        # repr() is the shortest literal that round-trips to the same float,
        # i.e. the number the caller wrote, not its binary expansion.
        result = Decimal(repr(value))
    else:
        raise TypeError(
            f"{name} must be int, float, str or Decimal, got {type(value).__name__}"
        )

    if not result.is_finite():
        raise ValueError(f"{name} must be finite, got {value!r}")
    return result


def final_price(price, discount):
    """Return the discounted price rounded to the cent (ROUND_HALF_UP).

    Step 1 rounds price to the cent, step 2 discounts it, step 3 rounds again.
    Returns Decimal so no downstream binary-float error is reintroduced.
    """
    rounded_price = _to_decimal(price, name="price").quantize(
        _CENT, rounding=ROUND_HALF_UP
    )
    rate = _ONE - _to_decimal(discount, name="discount")
    return (rounded_price * rate).quantize(_CENT, rounding=ROUND_HALF_UP)

#!/usr/bin/env python3
"""PACT evidence runner: the SAME check against baseline and against the fix.

Stdlib only, no pytest needed:
    cd pact-price-fix && python3 run_checks.py

RED / GREEN CONTRACT  (assertions written before the fix existed)
  baseline : the 3 RED rows MUST fail   -> the reproduced defect
             the 5 GREEN rows MUST pass -> behaviour that was already correct
  fixed    : every row MUST pass        -> proof of fix + proof of no regression

Expected values were derived by exact integer-cent arithmetic, NOT by running
the buggy code.  Example: 10.005 -> 1001 cents; 1001 * 9 = 9009 tenths-of-cent
= 9.009 -> ROUND_HALF_UP -> 9.01.
"""

import importlib
import sys
from decimal import Decimal

# price, discount, business-rule expectation, label
CASES = [
    ("10.005", 0.1, "9.01", "RED-A1 reported defect 10.005 @ 10% off"),
    ("2.675", 0.0, "2.68", "RED-A2 price pre-rounding HALF_UP"),
    ("1.0", 0.875, "0.13", "RED-A3 final tie HALF_UP (12.5 cent)"),
    ("10.05", 0.1, "9.05", "GREEN-G1 parity 10.05 @ 10% off"),
    ("10.005", 0.0, "10.01", "GREEN-G2 parity no discount"),
    ("10.005", 1.0, "0.00", "GREEN-G3 parity full discount"),
    ("1234567.89", 0.15, "1049382.71", "GREEN-G4 parity large amount"),
    ("10.0", -0.1, "11.00", "GREEN-G5 guardrail negative discount"),
]

# fixed-only checks: input-type widening and error contract
EXTRA = [
    ("EXTRA int price 10 @ 10%", lambda f: f(10, 0.1), "9.00"),
    ("EXTRA Decimal 10.005 @ 10%",
     lambda f: f(Decimal("10.005"), Decimal("0.1")), "9.01"),
    ("EXTRA str '10.005' @ 10%", lambda f: f("10.005", "0.1"), "9.01"),
    ("EXTRA None price -> TypeError", lambda f: f(None, 0.1), "TypeError"),
    ("EXTRA NaN price -> ValueError",
     lambda f: f(float("nan"), 0.1), "ValueError"),
]


def norm(value):
    """Normalise Decimal('9.010') / 9.01 / '9.01' to one comparable Decimal."""
    return Decimal(str(value)).normalize()


def evaluate(fn, price, discount):
    """Return (normalised result, None) or (None, 'ErrorType: msg')."""
    try:
        return norm(fn(float(price), discount)), None
    except Exception as exc:  # noqa: BLE001 - evidence gathering
        return None, f"{type(exc).__name__}: {exc}"


def run(module_name):
    importlib.invalidate_caches()
    fn = importlib.import_module(module_name).final_price
    is_baseline = module_name.endswith("baseline")
    print(f"\n=== {module_name}.final_price"
          f"{'   (RED rows are EXPECTED to fail here)' if is_baseline else ''} ===")

    passed = failed = 0
    for price, discount, expected, label in CASES:
        got, error = evaluate(fn, price, discount)
        if error:
            ok, detail = False, f"raised {error}"
        else:
            ok = got == norm(expected)
            detail = f"got {got!s} | rule {expected}"
        passed, failed = (passed + 1, failed) if ok else (passed, failed + 1)
        print(f"  [{'PASS' if ok else 'FAIL'}] {label:42s} {detail}")

    if not is_baseline:
        for label, call, expected in EXTRA:
            try:
                got = norm(call(fn))
            except Exception as exc:  # noqa: BLE001
                got = type(exc).__name__
            ok = str(got) == expected or got == norm(expected)
            passed, failed = (passed + 1, failed) if ok else (passed, failed + 1)
            print(f"  [{'PASS' if ok else 'FAIL'}] {label:42s} "
                  f"got {got!s} | want {expected}")

    print(f"  -> {passed} passed, {failed} failed")
    return failed


if __name__ == "__main__":
    sys.path.insert(0, ".")
    base_fail = run("price_baseline")
    fixed_fail = run("price_fixed")
    print("\nSUMMARY")
    print(f"  baseline failures = {base_fail}  (want exactly 3: the RED rows)")
    print(f"  fixed failures    = {fixed_fail}  (want 0)")
    ok = base_fail == 3 and fixed_fail == 0
    print(f"  verdict: {'PROOF OF FIX OK' if ok else 'CONTRACT NOT MET'}")
    sys.exit(0 if ok else 1)

Handoff — final_price 财务舍入缺陷 (ROUND_HALF_UP)

1. Change Summary

final_price 用一次 round() 覆盖了"原价先归分 → 再折扣 → 再归分"的两段规则。 round() 的第二个问题是它做的是银行家舍入（round-half-to-even），而财务规则要求 ROUND_HALF_UP；再加上 price 未经预归分、且参与运算的是二进制浮点数，导致 price=10.005, discount=0.1 得到 9.00 而规则要求 9.01。修复改为用 Decimal 显式三段式：quantize(HALF_UP) → 乘 (1 - rate) → 再 quantize(HALF_UP)， 并用 repr() 把 float 转成调用方书写的那个字面量，避免继承二进制误差。

2. File Impact

  • pricing.py（目标文件，本次未改动）—— 唯一需要落地的行为变更，见 final_price.patch。
  • 沙箱内新增（与本仓库无关，可整目录删除）：
  • price_baseline.py 缺陷实现原样副本，只用于 before/after 对照
  • price_fixed.py 修复实现
  • run_checks.py 同一套检查跑两遍的红/绿证据脚本
  • final_price.patch 最小 diff

Blast radius: 单函数、单文件。签名与调用点不变；返回类型由 float 变为 Decimal 是唯一需要 reviewer 决策的点（见第 4 节与 patch 末尾 VARIANT B）。

3. Validation Evidence

命令：cd pact-price-fix && python3 run_checks.py（标准库，无 pytest 依赖）

期望输出契约： - baseline：5 passed, 3 failed —— 3 个失败就是被复现的缺陷（A1/A2/A3）， 5 个 GREEN 行必须保持绿，否则说明修复改坏了原本正确的行为。 - fixed：13 passed, 0 failed → 退出码 0。

证据等级声明（重要）：本会话无可用的 Python 解释器工具，上述断言值不是运行得来的。 每条期望值改用两条独立通路复核： 1. 精确整数分运算：10.005 → 1001 分，1001 × 9 = 9009（十分之分）= 9.009 → HALF_UP → 9.01； 1.0 @ 87.5% off → 100 × 125 / 1000 = 12.5 分 → HALF_UP → 0.13。 2. IEEE-754 double 语义 + CPython round() 的 half-to-even 行为推导 baseline 值。 运行 run_checks.py 是把它从"算术核验"升级为"执行核验"的唯一动作，请在落地前执行一次。

4. Risk and Rollback

风险 级别 说明 / 处置
返回类型 float → Decimal 中 json.dumps 直接序列化 Decimal 会抛错，== 与 float 比较仍可用（Decimal('9.01') == 9.01 为 False，需注意）。若下游有序列化，改用 patch 末 VARIANT B 包一层 float()，或让调用方边界处转换。
None/NaN 行为变化 低 baseline 下 None 抛 TypeError、NaN 静默返回 nan；修复后 NaN 抛 ValueError。静默 nan 进入财务链路风险更高，建议保留新行为。
str/Decimal 入参被接受 低 属于有意加宽（代码中标注 WIDENING）。需严格对齐 baseline 时删除该两分支。
discount 越界（<0 或 >1） 低 现实现按算术照算（G5 覆盖负折扣）。是否应拒绝属业务规则未定义，需产品确认，本契约不擅自新增校验。
存量数据口径 中 上线前建议按真实订单跑一次 diff 报表，统计新旧结果不一致的条数与金额分布，决定是否需要追溯调整。

Rollback：git checkout -- pricing.py（或 revert 单提交）。无迁移、无状态、无依赖新增，可即时回滚。

5. Follow-ups（建议的下一个契约）

  1. 统一金额入口：收敛到 money 工具层，禁止裸 float 参与金额运算；加 lint 规则。
  2. 税率/运费/优惠券共用同一舍入策略常量，避免各处 round() 口径漂移。
  3. 明确 discount 定义域并补契约测试（0 < d < 1 还是允许负值）。
  4. 若跨币种，把 _CENT 改为按币种小数位（如 JPY 0 位）参数化。
