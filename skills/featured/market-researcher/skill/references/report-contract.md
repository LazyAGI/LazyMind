# 研究报告契约

## 0. 交付方式

默认直接从一句话结论或最终报告开始。不要展示获取 Skill、读取 Reference、调用脚本、建立内部台账或执行质量检查的过程。

使用用户主要语言完成交付。中文请求的标题、正文、表格字段、图后说明和数据边界均使用中文；不得夹带英文计划、英文过渡或英文收尾。不要把同一内容先“总结”后再以“最终输出如下”重复一次，最后一段必须完整落地。

根据研究完成度选择一种交付级别：

- **完整**：关键问题均有足够证据，主要数字和时间敏感事实已核验。
- **阶段性**：部分模块完成，但联网、数据覆盖或口径冲突影响若干结论。
- **受限**：仅依据用户输入、少量资料或封闭数据，不能推广到完整行业判断。

在局限性部分用一句话说明完成度及原因，不用分数伪装精度。

对于用户提供封闭数据集的受控分析，优先使用精简结构：

1. 一句话结论
2. 输入事实与确定性计算
3. 分维度比较：按已提供的经营指标、估值倍数、证据完整度
4. 定性上行与下行条件
5. 数据缺口与结论边界

封闭数据只有少量指标时，“候选排序”固定写为：`综合排序：证据不足，无法形成`；随后可分别列出经营指标顺序和估值倍数顺序，但不得出现“首选”“第二名”“价值重估标的”等综合标签。只有用户明确给出排序口径/权重且相应数据完整时，才能输出清楚标注口径的受限排序，不能包装成综合投资排名。情景中的具体数字必须出现在用户输入或本回合成功计算结果中；没有依据时使用定性条件或 `[待设定]`。

封闭数据回答不得在结尾声称“无假设”或“所有内容均来自输入”，因为用户要求的上行和下行情景本身就是假设。固定区分为：事实与数值来自输入/成功计算，情景属于定性假设，数据缺口均待验证。也不要追加“是否需要继续”等销售式追问。

一句话结论只写样本统计、观察到的差异和结论边界。横截面小样本不得在一句话结论或排序理由中解释“市场为何如此定价”；单期指标不得使用“承压、修复、企稳”等趋势词。

封闭数据中的“估值解读”只允许包含三项内容：脚本统计、EV/Sales 的实际顺序、当前数据无法解释倍数差异原因。不得写“正相关”“市场定价”“估值分层”“估值溢价/折价”“估值中枢”“增长或盈利是定价因素”，也不得用“表现最优、稳健、面临挑战”代替无依据的综合评价。若用户指定“核心发现、公司对比、估值解读、局限与下一步”等标题，可以保留标题，但各标题下仍必须遵守本段限制。

封闭数据情景只能改变用户输入中已经存在的指标。默认句式为：“上行：若已提供的经营指标改善，则经营指标画像改善；估值倍数如何变化无法由当前数据判断。下行：若已提供的经营指标恶化，则经营指标画像恶化；估值倍数如何变化无法由当前数据判断。”

## 1. 默认完整报告结构

按任务需要调整篇幅，但完整研究默认使用：

1. 标题、研究范围和数据截止日期
2. 执行摘要
3. 关键结论与证据
4. 行业定义、规模和增长
5. 细分市场与产业链利润池
6. 增长驱动、周期与主要风险
7. 竞争格局、战略分组和壁垒
8. 可比公司经营与估值
9. 候选标的、观察名单和证伪条件
10. 基准、上行和下行情景
11. 数据缺口、局限性和后续跟踪指标
12. 来源

专题或单点分析可以删除无关章节，但必须保留范围、结论、证据、风险、局限性和来源。

## 2. 执行摘要

执行摘要应独立可读，包括：

- 一句话回答研究问题
- 3—7 条关键发现
- 当前最重要的变化
- 核心候选或战略含义
- 最大不确定性

不要在执行摘要首次引入正文没有证据支持的数字。

## 3. 表格规范

每个表格明确：单位、币种、期间、数据日期和 `N/M` 含义。推荐使用：

- 市场规模与增速表
- 价值链和利润池表
- 公司竞争矩阵
- 财务与估值可比表
- 候选标的评分表
- 催化剂、风险和跟踪指标表

表格后用 2—4 句话解释“这说明什么”，不要让读者自行猜测意义。封闭数据小样本只能说明数值差异、顺序和结论边界，不能借此解释市场行为、公司质量或因果机制。

## 4. 图示规范

需要图示时读取 `references/visualization-guidelines.md`。复杂关系适合使用 Mermaid：

- 产业链：flowchart
- 市场规模和经营趋势：xychart-beta
- 构成或份额：pie
- 竞争结构：quadrantChart 或 flowchart
- 事件与催化剂：timeline
- 研究逻辑：flowchart

不要为了装饰而制图。图中的数字仍需在邻近文字中给出来源，并与邻近表格逐项一致。简单单序列趋势/柱状图或构成图可按可视化规范的固定模板受控直出；象限、结构化转换和超出直出限制的图表才运行 `scripts/build-mermaid-chart.py`。定量图表不得使用文生图模型。同一图表脚本最多调用一次；脚本失败后仅在仍满足受控直出条件时使用固定模板，否则保留同源表格，不声称图表已生成。

## 5. 引用与表述

- 在事实或数字附近放置引用。
- 明确区分来源原始观点和本报告推断。
- 使用绝对日期，避免“最近”“去年”等在未来失去含义的表述。
- 对推断说明传导机制，对预测说明前提。
- 不复制大段来源原文，使用准确概括。
- 不把用户输入描述成已外部核验，不把情景假设描述成事实。
- 不在未生成文件时写“见附件”“已生成报告”或类似表述。
- 联网研究只有在搜索或抓取工具实际成功后，才使用“已联网核验”或“已打开原文”。
- 搜索或抓取技术成功但结果与主题无关时，标为“工具可调用但本题结果无效”，不计入已核验证据；只有窄域工具时不得笼统写成“完全没有联网工具”。
- 来源列表保留标题、发布者、发布日期、数据期间和直接 URL；正文关键事实仍需就近引用。

## 6. 候选标的免责声明

在涉及证券时说明：内容属于一般性研究，不考虑个人财务状况、风险承受能力或投资目标，不构成个性化投资建议。

## 7. 演示材料降级输出

用户要求 PPT 时，默认在报告后增加“逐页演示大纲”，而不是强制生成文件。每页包含：

- 页标题
- 一句话结论
- 3—5 个证据点
- 推荐图表
- 数据来源
- 演讲备注

建议 8—12 页：封面、结论、市场、产业链、竞争、可比公司、候选标的、情景风险、跟踪指标、来源。宿主存在可靠演示文稿工具时，可据此继续生成文件。

逐页大纲使用固定字段，便于未来交给演示文稿工具：

| 字段 | 内容 |
|---|---|
| 页码 | 连续编号 |
| 页标题 | 该页主题 |
| 一句话结论 | 该页希望读者记住的判断 |
| 证据 | 3—5 个事实、计算或明确标注的推断 |
| 推荐图表 | 图表类型、数据字段、单位和期间 |
| 来源 | 直接来源与数据日期 |
| 演讲备注 | 口径、限制和过渡说明 |

图片生成工具可用不代表演示文稿工具可用。没有实际生成并返回 `.pptx` 时，交付名称只能是“逐页演示大纲”，不能称为 PPT 文件或附件。
