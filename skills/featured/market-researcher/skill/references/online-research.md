# 联网研究与证据核验

仅在当前会话真实存在可用的网页搜索、网页抓取或等价检索工具，且用户没有禁止联网时执行本模块。工具不可用或调用失败时，立即转为阶段性研究，不得以模型记忆模拟联网结果。确认通用网页搜索可用后，同时读取 `references/public-web-source-playbook.md`；只有窄域工具或用户给定 URL 时不要读取该手册并假装具备开放网页发现能力。

## 1. 联网能力门

开始检索前同时检查四件事：工具是否存在、调用是否成功、结果是否与本题相关、覆盖是否足以支撑用户要求。技术上能返回内容不等于能够完成本题研究。

能力判断必须发生在任何联网工具调用之前，并先锁定根文档定义的 `OPEN_WEB`、`URL_ONLY` 或 `LIMITED` 状态。盘点阶段只允许读取 Skill/Reference，以及必要时至多调用一次 `list_data_sources`：

- `OPEN_WEB`：发现已配置的 `web_search`、`WebSearchToolkit`、通用网页搜索供应商或相关行业数据库，才允许继续搜索。
- `URL_ONLY`：没有通用搜索但用户提供相关 URL，只抓取用户给定地址。
- `LIMITED`：没有通用搜索且用户未给 URL，后续联网工具调用集合必须为空，直接输出固定受限结果。

进入 `LIMITED` 后，不得调用或展开 `get_WikipediaToolkit_methods`、`get_ArxivSearch_methods`、Wikipedia/Arxiv 搜索、`url_fetch`、`get_content`、`get_contents`；不得使用 `httpbin.org`、`example.com` 或任何首页做测试。`list_data_sources` 已确认没有通用搜索时，该结果就是停止条件，不再调用任何窄域工具复核。

在 LazyMind 的广泛市场研究中执行硬门：若工具盘点只有 `WikipediaToolkit`、`ArxivSearch` 和无发现能力的 `url_fetch`，且用户未提供相关 URL，则从工具名称和说明即可判定覆盖不足。不得调用它们搜索本题，不得使用 `httpbin.org`、`example.com`、Baidu、Wikipedia 首页或其他测试端点检查连通性，不得凭模型记忆猜测 Statista、媒体或研究机构页面 URL；立即按“有限工具”输出受限结果。工具暴露只证明“存在”，不证明调用成功，降级答案不要编造成功或失败测试。只有出现已配置的通用网页搜索、行业数据库或等价发现工具时，才继续下面的搜索流程。

按以下路径判断：

1. 有通用网页搜索工具且返回相关候选：继续打开支撑关键结论的直接页面。
2. 只有 Wikipedia、单站点检索、论文库或其他垂直窄域搜索：仅使用其真实覆盖范围。广泛市场研究所需证据超出覆盖时，固定写“当前会话存在联网工具，但其检索范围或主题相关性不足，未完成本题联网核验。”，不得称为完整搜索路径。工具名称或说明已经表明它是窄域工具时，先判定覆盖边界，不要为了验证而连续改写同义词查询；只有覆盖范围仍不明确时，最多执行 1 次诊断查询，结果不相关或不足后立即停止该工具。
3. 没有搜索工具，但用户给出 URL 且有网页抓取工具：只读取这些 URL，并把覆盖范围限制为用户提供的来源。只有抓取工具但没有相关 URL 或发现路径，不等于具备搜索能力。
4. 只有结构化金融或行业工具：仅使用其真实返回范围，不把它描述成全网搜索。
5. 上述路径均不可用：明确写“当前会话未提供可用联网检索工具”，列出待检索问题和首选来源，不声称完成最新资料核验。

能力检查优先读取工具名称、说明和配置状态，至多调用一次 `list_data_sources`；不得展开窄域 Toolkit，也不得抓取搜索引擎首页、Wikipedia 首页或其他通用首页来“证明联网”。网页抓取只用于用户提供的相关 URL，或 `OPEN_WEB` 状态下相关搜索结果发现的直接来源。抓取通用首页即使成功，也不得计入本题能力或证据覆盖。

搜索结果明显偏题时，不得继续打开或抓取该页面来测试工具，也不得在同一窄域工具中连续尝试近义查询。记录“工具调用成功但主题结果无效”，停止整个工具而不只是停止单个查询，并改用其他真实可用路径；没有其他路径时按“有限工具”降级。网页抓取成功打开无关页面，只能证明抓取技术可用，不能证明本题联网核验完成，也不能反过来声称抓取工具不存在。

只有工具在当前任务中成功返回内容，才能使用“已联网检索”“已打开原文”或“截至当前日期已核验”等表述。

### LazyMind 通用搜索执行映射

LazyMind 中的 `web_search` 是工具组，运行时由 `WebSearchToolkit` 选择首个已配置供应商。不要假设最终函数名固定，也不要要求 NeoData、WeStock 或 WorkBuddy 的 `WebSearch` 名称存在。

1. 调用当前暴露供应商的 `search` 方法，每次查询只表达一个搜索意图。
2. 从返回项中筛选标题、URL、摘要与本题相符的候选；摘要只用于筛选。
3. 对关键候选调用同一供应商的 `get_content` / `get_contents`。若这些方法不可用或未取得正文，再对返回项中的原始 URL 调用 `url_fetch`。
4. 正文路径最多切换一次；仍为空、截断、需要登录或主题不符时停止该 URL，不循环重试。
5. 只有正文支持目标主张时写入证据矩阵。工具成功但无相关候选、候选正文不可读和证据覆盖不足必须分别记录。

## 2. 按证据问题设计查询

不要用一个宽泛查询包办整个行业。把任务拆成可验证问题，例如：

- 行业定义和统计边界是什么？
- 最新历史市场规模对应哪一期间？
- 预测值的起点、终点和方法是什么？
- 主要参与者的收入、份额或客户覆盖口径是否一致？
- 公司披露中的经营指标对应哪个报告期？
- 哪个事件改变了供需、竞争、监管或成本结构？

每个问题优先搜索“主题 + 单一指标或事件 + 地区 + 数据期间 + 首选来源机构或官方域名”。需要最新信息时，从当前环境日期推导当前年份、上一完整年度或最新完整报告期；不得复制模板中的固定旧年份。先执行官方定向查询，无有效结果时再扩大来源类型；只有存在明确同义术语或期间差异时才调整一次查询，仍无有效候选便记录缺口。最终仍以打开的原始页面为准，详细来源地图和查询形态见 `references/public-web-source-playbook.md`。

## 3. 搜索、打开与记录

对每条可能进入结论的证据执行：

1. 使用当前可用的通用搜索供应商搜索，并识别最接近原始事实的来源。
2. 优先用该供应商的 `get_content` / `get_contents` 打开直接页面、公告或文件；失败时再对搜索返回的原始 URL 使用 `url_fetch`。搜索摘要只能用于发现线索。
3. 记录标题、发布者、发布日期、数据对应期间、URL、来源层级和适用口径。
4. 摘录支持结论的事实位置；不要复制大段原文。
5. 把证据状态标为“已核验、冲突、缺失或仅可推断”；搜索命中但正文未打开时只能标为“仅发现线索”。

来源记录最少包含：

| 字段 | 要求 |
|---|---|
| 主张 | 该来源直接支持的最小事实单元 |
| 发布者 | 机构或公司全称 |
| 发布日期 | 页面、公告或报告发布日期 |
| 数据期间 | 数字实际对应的时点或期间 |
| 来源层级 | 一手、方法透明的二手、新闻或线索 |
| URL | 直接页面或文件，不使用搜索结果页 |
| 口径说明 | 地区、币种、行业边界、历史或预测 |
| 核验状态 | 已核验、冲突、缺失或仅可推断 |

## 4. 一手来源优先

关键结论优先使用：

1. 政府、监管机构、统计部门、中央银行和交易所；
2. 公司年报、季报、公告、招股书、投资者材料和电话会记录；
3. 行业协会、标准组织和学术论文；
4. 方法、样本和口径透明的研究机构；
5. 可靠媒体对事件的补充报道。

聚合页、转载、搜索摘要和无方法说明的图表只作为线索。公司宣传可以证明“公司作出了某项表述”，不能自动证明该表述客观成立。

## 5. 时间与版本控制

- 同时区分发布日期、数据期间和访问日期。
- “最新”结论必须核对当前日期，并优先选择最新完整报告期，而不是最新发布但数据更旧的文章。
- 更新研究只检索上次截止日期之后的新增材料，同时复查旧结论依赖的数据是否被修订。
- 对政策、产品状态、管理层和市场价格等易变化信息使用绝对日期。
- 预测值必须标注预测发布方、预测起点和预测终点，不能与历史值混成一列。
- 建议检索式中的年份也必须与当前日期和目标报告期一致。降级答案默认写 `[当前年份]` 或 `[最新完整报告期]`；只有用户指定历史期间，或当前环境日期明确且确有必要时，才写具体年份。发送前扫描所有四位年份，删除与目标期间无关或沿用模板记忆的旧年份。

## 6. 交叉验证与独立性

重大市场规模、份额、财务和估值结论尽量使用两个独立证据路径。以下情况不构成独立验证：

- 多个网站转载同一份报告；
- 新闻引用同一家公司新闻稿；
- 数据聚合商与公司披露实际来自同一底稿；
- 同一研究机构的摘要、图表和新闻解读。

数字冲突时先比较定义、地区、期间、币种、是否含税、历史或预测、样本覆盖和汇率。不能统一时并列呈现，不做无依据平均。

## 7. 引用覆盖与结论强度

- 外部数字、时间敏感事实、公司状态和具体事件在首次出现处就近引用。
- 每条关键结论至少绑定一条直接证据；重大结论优先绑定一手证据和独立补充证据。
- 推断必须紧跟证据并说明传导机制；来源只支持事实时，不把分析判断归因于来源。
- 来源质量、口径一致性或覆盖率下降时，相应降低措辞强度。
- 无法打开正文时写“仅发现线索，未完成原文核验”，不得引用搜索摘要中的数字作为已核验事实。

## 8. 联网失败的固定降级

出现无搜索工具、无有效 Key、网络错误、页面不可访问或正文解析失败时：

1. 保留用户输入和已经成功打开的资料；
2. 删除依赖失败来源的事实与数字；
3. 输出已完成范围、未核验问题、影响到的结论和下一步首选来源；
4. 将完成度标记为“阶段性”或“受限”；
5. 不反复调用同一失败工具，也不改用模型记忆补齐最新信息。

待检索问题和建议检索式同样受证据边界约束：不得凭模型记忆新增具体公司、产品、政策、技术趋势或市场事件。用户未给出且本轮未核验的实体不写具体名称，改写为“参与者识别”“监管变化”“技术变化”等中性问题。用户没有指定历史年份时，降级答案中任何具体四位年份都视为失败，必须替换成 `[当前年份]` 或 `[最新完整报告期]`。触发 LazyMind 联网硬门时，使用根文档中的固定中性骨架，不增加示例。

降级答案直接使用一次性成品结构：

1. 完成状态：只有窄域工具或覆盖不足时写“受限”；没有联网工具、调用失败或来源不可访问时写“阶段性”；
2. 能力检查：准确区分无工具、有限工具、调用失败、结果偏题或原文不可访问；
3. 已知边界：只写本轮真实取得的范围；
4. 待检索证据问题；
5. 建议检索式：默认使用 `[当前年份]` 或 `[最新完整报告期]`，不硬编码过期年份，不加入未核验实体。

不得先完整总结一遍，再写“最终输出如下：”后重复或停止。最后一项写完即结束，结尾必须是实质内容。
