# 交付质量门

提交前依次执行。任一关键项失败时，补充研究或在报告中明确降级。

## 0. 封闭数据最终写入硬门

用户要求“只依据所给数据”“禁止检索”或同等限制时，本节优先于其他质量门。先写草稿，再逐句扫描；以下任一项失败都不得发送，必须删除或改写后重新扫描：

- [ ] 没有写“正相关”“相关趋势”“高度一致”，只在确实核对后写“本样本内数值顺序同向/不同”。
- [ ] 没有写“市场定价”“估值分层”“估值溢价/折价”“估值中枢”“估值合理性”或任何倍数差异原因。
- [ ] 没有写“表现最优”“表现稳健”“面临挑战”“经营质量较高/较低”“首选”等综合评价。
- [ ] 样本均值和中位数只称“样本均值/样本中位数”；某公司等于该数值时，不改称“估值中枢”。
- [ ] 最大值/最小值只称“本样本最大值/最小值”；不改称“溢价/折价、高估/低估”。
- [ ] “估值解读”明确写出：当前数据不能解释倍数差异原因，也不能推出相关性或因果。
- [ ] 最后一段准确写明：`事实与数值仅来自用户输入和成功的脚本计算；上行/下行情景为定性假设；数据缺口均待验证。`

允许的核心句式是：`收入增速、毛利率和 EV/Sales 在本样本内的数值顺序同向；这只是顺序观察，不能推出相关性、因果或市场定价逻辑。`

## 1. 执行完整性门

- [ ] 最终答案没有展示 Skill 加载、Reference 读取、脚本调用或自检过程，除非用户明确要求。
- [ ] 只有收到当前回合的成功结果后，才声称脚本已执行或文件已生成。
- [ ] 未生成附件、报告文件或 PPT 时，没有暗示这些文件存在。
- [ ] `scripts/` 中的文件通过 `run_script` 执行，没有伪装成 Reference 读取。

## 2. 范围门

- [ ] 行业、地区、时间范围和研究目的清晰。
- [ ] 行业定义与主要数据口径一致。
- [ ] 完整研究已覆盖行业、竞争、可比公司和候选标的。

## 3. 证据与数值门

- [ ] 每个关键数字都有来源和数据日期。
- [ ] 重大市场规模、份额和财务结论已尽量交叉验证。
- [ ] 关键页面或文件已阅读全文，而不是只使用搜索摘要。
- [ ] 历史事实、预测、模型计算和推断已区分。
- [ ] 冲突数据已经解释口径差异，没有被静默删除。
- [ ] 每个业务数字、比例、倍数、评分权重和情景阈值均可追溯到用户输入、已核验来源或明确计算。
- [ ] 封闭数据模式下没有加入外部事实、虚构公司状态或无依据的具体阈值。
- [ ] 封闭数据模式下已逐个检查阿拉伯数字或中文数字表示的业务数量、百分比、年份、倍数、阈值和评分；全部存在于用户输入或本回合成功计算结果中。
- [ ] 封闭数据模式下的情景只改变用户已提供的字段，没有用自拟数字，也没有夹带政策、行业、客户、盈利或公司状态断言；估值方向无证据时明确不可判断。
- [ ] 使用了情景假设时，没有声称“未引入任何假设”。
- [ ] 收尾已分别说明事实/数值的来源、情景的假设属性和数据缺口的待验证属性，没有笼统声称“所有内容均来自输入”。

## 4. 行业与竞争门

- [ ] 市场边界、细分、规模、增长和价值链互相一致。
- [ ] 利润池判断有毛利、议价能力或控制点证据支持。
- [ ] 份额数据使用相同地区、年份和行业边界。
- [ ] 所谓壁垒包含支持证据和证伪信号。
- [ ] 竞争变化说明了原因和可观测指标。
- [ ] TAM、SAM 和 SOM 没有混用，历史值与预测值已经分开。
- [ ] 单个时点没有被描述为增长、放缓、修复、承压或份额变化。
- [ ] 利润池判断有利润、单位经济性、议价能力、控制点或现金转化证据，不只依据参与者数量。

## 5. 财务与估值门

- [ ] 可比组有明确入选和排除逻辑。
- [ ] 币种、单位、财务期间和估值日期一致或已解释。
- [ ] 负利润公司的市盈率标记为 `N/M`。
- [ ] 离群值经过解释，没有为得到理想结果而任意删除。
- [ ] 开放数据完整研究中的估值差异解释有增长、利润、资本效率和风险证据；封闭数据小样本没有解释溢价、折价或定价原因。
- [ ] 没有把脚本未计算的相关系数、回归、目标价或排名归因于脚本。
- [ ] 样本过小时没有使用缺乏计算支持的“高度相关”等统计结论。
- [ ] 横截面小样本的同向顺序没有被解释为市场定价逻辑、估值合理性或驱动因素；单期水平没有被写成趋势变化。
- [ ] 每列排序已经逐项核对；观察到同向顺序时没有误写成“不单调同向”。
- [ ] 统计量同时披露有效样本数和被排除公司，没有推广到未覆盖样本。

## 6. 候选标的门

- [ ] 每个候选都能追溯到行业和竞争证据。
- [ ] 每个候选都有催化剂、风险、证伪条件和跟踪指标。
- [ ] 好公司与好价格没有被混为一谈。
- [ ] 缺少核心维度或认可权重时，使用分维度画像而非强行总排名。
- [ ] 只有少量用户给定指标时，即使用户要求排序，也没有使用“首选”或综合投资顺序；经营指标顺序与估值倍数顺序已明确分开。
- [ ] 只有少量经营指标时使用“按已提供的经营指标”，没有包装成完整“经营质量”。
- [ ] 每个分维度顺序已标明由高到低或由低到高，文字方向与实际排列一致。
- [ ] 如生成总排序，已展示权重、证据质量和敏感性。
- [ ] 没有使用确定性收益语言或个性化买卖指令。

## 7. 联网证据门

- [ ] 在任何联网工具调用前已确定 `OPEN_WEB`、`URL_ONLY` 或 `LIMITED`；能力盘点除 Skill/Reference 读取外，至多调用一次 `list_data_sources`。
- [ ] `LIMITED` 状态下联网检索调用集合为空：没有展开 WikipediaToolkit/ArxivSearch，没有调用 Wikipedia/Arxiv 搜索、`url_fetch`、`get_content` 或 `get_contents`。
- [ ] `list_data_sources` 已显示没有通用搜索时立即停止，没有再调用窄域 Toolkit 或测试 URL 二次确认。
- [ ] 只有当前任务中的网页搜索或抓取工具成功后，才声称已联网或已打开原文。
- [ ] 通用搜索可用时，已按 `WebSearchToolkit` 当前暴露供应商执行；没有依赖固定供应商函数名，也没有要求 WorkBuddy、NeoData 或 WeStock 工具存在。
- [ ] 每次搜索查询只表达一个证据意图；行业定义、市场规模、竞争参与者、公司财务和近期事件没有被塞进一个混合查询。
- [ ] 搜索摘要只用于发现来源，关键事实来自实际打开的直接页面或文件。
- [ ] 关键候选优先通过搜索供应商的 `get_content` / `get_contents` 读取正文；失败时仅把搜索返回的原始 URL 交给 `url_fetch`，没有猜测或拼接地址。
- [ ] 对单个 URL 的正文读取路径最多切换一次；失败后已停止该 URL，没有无意义循环抓取。
- [ ] 外部数字、时间敏感事实、公司状态和具体事件在首次出现处就近引用。
- [ ] 来源记录区分发布日期、数据期间和访问日期。
- [ ] 所谓交叉验证来自独立证据路径，不是多个转载同一底稿。
- [ ] 联网失败时删除依赖失败来源的结论，输出待取证问题并标记阶段性或受限。
- [ ] 已分别检查工具存在、调用成功、主题相关性和问题覆盖；技术成功但结果偏题没有被计为有效检索。
- [ ] 只有 Wikipedia、单站点或其他窄域工具时，已写“存在有限工具但不足以完成本题”，没有误写成通用搜索可用或完全没有联网工具。
- [ ] 窄域工具的覆盖已可从名称或说明判断时，没有连续改写同义查询；范围不明确时最多执行 1 次诊断查询，并在结果无效后停止整个工具。
- [ ] 没有抓取通用首页来证明联网；网页抓取对象来自用户 URL 或相关搜索结果。
- [ ] 降级清单没有凭记忆新增具体公司、产品、政策、技术或事件，建议检索式没有过期年份。
- [ ] LazyMind 只有 WikipediaToolkit、ArxivSearch、url_fetch 且用户未给 URL 时，未调用三者搜索或抓取，已直接输出 `完成状态：受限` 和固定能力说明。
- [ ] 未使用 httpbin、example.com 或任何通用首页测试 url_fetch；硬门降级答案使用固定中性骨架，没有具体四位年份和未核验实体。
- [ ] 没有打开明显无关候选来测试工具；抓取无关页面的成功没有进入证据表。
- [ ] 最新研究和建议检索式中的年份来自当前日期或明确报告期，没有沿用模板中的固定旧年份。
- [ ] 没有把公开网页搜索描述成实时行情、K 线、资金流、共识预期或结构化金融数据库；相关工具缺失时已省略或列为待补数据。

## 8. 可视化门

- [ ] 定量图表没有调用文生图模型。
- [ ] 图表数字、标签、单位和期间与邻近表格逐项一致。
- [ ] 饼图明确完整市场或已覆盖样本等分母；象限坐标有来源或透明方法。
- [ ] 缺失值没有补零，历史值与预测值没有混在同一序列而不说明。
- [ ] 受控直出只用于简单单序列趋势/柱状图或构成图，数据点不超过限制，且没有声称脚本已执行。
- [ ] 同一图表任务最多调用一次脚本；`parameters error` 后没有改名、改路径、调用 `--help` 或重复提交。
- [ ] 图后解释区分直接观察、分析推断和数据限制。
- [ ] 脚本失败后只在仍满足受控直出条件时生成固定模板 Mermaid；复杂图条件不足或渲染失败时已降级为表格。

## 9. 表达门

- [ ] 执行摘要能够独立回答研究问题。
- [ ] 表格包含单位、期间和数据日期。
- [ ] 每个表格或图示后解释了意义。
- [ ] 使用绝对日期描述时间敏感信息。
- [ ] 已披露数据缺口、方法局限和结论敏感项。
- [ ] 回答直接从结论或交付物开始，没有冗长的“现在开始”式过程叙述。
- [ ] 最终答案及模型自行生成的工具前后说明使用用户主要语言，没有中文请求夹带英文计划或英文数据边界。
- [ ] 没有重复写“总结”与“最终输出”，也没有以冒号、过渡句、空标题或“最终输出如下”结束。

## 10. 降级规则

如果以下条件出现，明确降低交付级别：

| 条件 | 降级方式 |
|---|---|
| 缺少可靠市场规模 | 给出可验证区间或方法，不给伪精确单点 |
| 缺少市场份额 | 使用参与者地图和定性定位，不计算集中度 |
| 缺少一致财务数据 | 给出业务比较，不形成估值排名 |
| 只有少量用户给定指标 | 给出已提供经营指标顺序、估值倍数位置和证据缺口，不生成综合候选排序 |
| 缺少行情工具 | 省略技术分析和筹码分析 |
| 缺少网页搜索工具 | 使用用户资料或已知 URL；否则输出阶段性研究和待取证清单 |
| 搜索可用但原文打不开 | 仅保留线索，不把摘要数字写成已核验事实 |
| 缺少图片生成工具 | 省略非数据插图，不影响表格和 Mermaid 图表 |
| 图表脚本失败但仍满足简单直出条件 | 使用固定 Mermaid 模板，并保留同源 Markdown 表格 |
| 复杂图条件不足或 Mermaid 无法渲染 | 输出同源 Markdown 表格 |
| 缺少演示工具 | 输出逐页演示大纲，不生成 PPT 文件 |
| 关键来源互相矛盾 | 展示不同口径并降低结论置信度 |

最后给研究完成度标记：完整、阶段性或受限，并用一句话解释原因。
