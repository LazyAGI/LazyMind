PROTOTYPE / ZHICE

知策：从计划确认走到报告版本确认

交互原型 v2.0｜概念原型 / draft｜使用 PRD v1.0 的拟议规则；尚未获得业务批准。原型内所有研究内容是本地虚构示例，不发起联网研究。

在当前 HTML 的“体验原型”中，可以创建计划、推进示例证据、暂停/恢复、模拟局部失败、切换角色复核，并验证旧版本保留。

1. 运行方式与验证目标

点击本报告中的“体验可点击原型”，在独立弹窗中操作。无需安装依赖，不加载外部脚本。状态仅存在当前页面内存，刷新或重置后恢复初始值。

本次验证：用户是否理解计划确认、过程控制、来源缺口和版本复核。非目标：验证实际研究准确率、采集速度、服务器权限、多人并发、持久化与生产级导出。

原型保留“任务状态”与“报告状态”两个不同标签。角色切换只是体验测试入口，不是登录功能，也不能证明真实权限安全。

2. 屏幕与主要路径

屏幕入口与操作对应需求
SCR-01 新建与计划填写问题、自家说明、三个示例竞品、比较维度；生成计划FR-001、FR-002
SCR-02 过程与证据确认后逐条返回本地示例；暂停、继续、整体失败、重试、取消FR-003、FR-004、FR-005
SCR-03 报告与复核查看带缺口的报告；负责人确认/退回，创建者修订后再提交FR-006、FR-007、FR-008、FR-010
SCR-04 版本记录确认版不可原地改写；新建草稿；选择旧确认版并下载FR-009、FR-011

主路径：输入有效资料 → 生成计划 → 确认计划 → 返回三条示例证据 → 生成报告 → 切换负责人 → 确认该版本 → 下载本地示例。

关键分支：执行中暂停再继续；部分来源失败后保留缺口；整体失败后重试未完成部分；负责人填写理由退回；创建者修订再提交；取消后不能恢复原任务，只能重置开始新的示例。

4. 行为与规则映射

原型动作规则依据可见反馈

5. 评审者可以尝试的任务

  • 任务 T1：清空研究问题，尝试生成计划；补齐后开始，观察计划与已填信息是否一致。
  • 任务 T2：返回一条证据，暂停再继续；模拟第二条来源失败，完成其他来源，观察缺口是否保留。
  • 任务 T3：切换负责人，先不勾选缺口知晓尝试确认，再勾选完成；观察确认版本与时间。
  • 任务 T4：由创建者修改确认版，切换只读成员；确认成员看到的仍是旧确认版，不是草稿。
  • 任务 T5：负责人尝试空理由退回，再填写理由退回；创建者修改并再次提交。

6. 限制与后续补齐

本原型没有真实模型调用、来源抓取、登录、数据库和服务器权限；不保存输入、不上传内容，也不执行正式业务审批。甲、乙、丙是虚构的示例竞品。

尚需验证或补齐：全部 AC 的真实验收、来源冲突与排除操作、保存/导出失败、跨团队权限、并发版本冲突、在途结果处理、归档恢复、无障碍完整检查和最终品牌规范。

核心规则尚未接受，故保持概念原型草稿。可用于讨论流程，不能作为已完成软件或可直接上线的证明。
