## 4. 对照：研究启动前 vs 启动后应如何处理

以下**“原文规则”**列严格来自上述出处；“说明”列是我的解释。

| 时点 | 原文规则（含出处） | 说明（我的解释） |
|---|---|---|
| **启动前**（任务处于“待确认”） | 创建者在计划页确认对象、维度、来源范围；确认后**锁定计划版本**并进入执行中。（`prd.txt` §[section-4] 状态表“待确认”行；§[section-5] FR-002） | 这是**唯一**可以“改范围 + 重新确认”的窗口。改完再确认，确认即锁定。 |
| **启动前**（尚未确认时） | 未确认不访问外部资料。（`prd.txt` §[section-5] FR-002 异常栏） | 改范围不会产生外部副作用，因为研究还没起步。 |
| **启动后**（已进入“执行中”及之后） | **应复制配置创建新任务，不在原运行中静默替换。**（`prd.txt` §[section-4] 状态表后段落） | 原任务的计划版本与已产生证据保持不动；新范围 = 新任务。 |
| **启动后** | **运行中改范围需新建任务。**（`prd.txt` §[section-5] FR-002 异常栏） | 与上一行同义，属 PRD 内部互相印证。 |
| **研究列表侧** | 支持“**复制配置**”这一操作。（`design.txt` §[section-4] 研究列表行：新建、复制配置、归档） | 暗示“启动后改范围”的落地入口是复制配置，而非在原任务上重确认。 |
| **启动后 + 暂停/重试** | 已暂停→继续、执行失败→重试，均为“**范围不变 / 同范围**”恢复未完成部分。（`prd.txt` §[section-4] 状态表；`design.txt` §[section-3]） | 恢复路径也不改范围，进一步支持“启动后范围不可变”。 |

**综合（我的解释）**：原文规则合起来是一条清晰的两段式——**启动前：改范围 → 重新确认 → 锁定 → 执行；启动后：范围不可变，改范围 = 复制配置新建任务**。评审建议在方案该处补的那句“**启动前重确认；启动后创建新任务**”，正是把这条两段式写回被指出的出处 A。

## 5. 为什么当前写法可能被误读

**原文已给出的判断**（`review.txt` §[section-3] R-05“影响”栏）：
> 脱离上下文阅读时可能把执行中改范围理解为原任务重确认

**我的解释（三种具体误读路径，均非原文断言）**：
1. **字面歧义**：出处 A 只说“改动范围后须重新确认”，既没说“在哪个状态改”，也没说“确认后是原任务继续还是新任务”。若只读方案、不读 PRD 出处 D/F，最自然的推断就是“再确认一次即可”。
2. **缺少时点限定词**：出处 B、C 中的“确认”都绑定在“待确认→执行中”这一时点；出处 A 的“改动范围后须重新确认”却把“确认”放到了状态迁移之后，读起来像“执行中的再确认入口”，与出处 D 直接冲突。
3. **与暂停/重试恢复路径混淆**：出处 D 之后紧接着“已取消任务不恢复执行；再次运行用新任务”，而暂停/继续、失败/重试又是**原任务恢复**；两套“改 vs 重启”语义相邻出现，容易被合并理解，从而把“改范围”也当成一种原任务恢复。
4. **章节号偏移放大风险**：评审 R-05 指向“方案 §3 / PRD §3”，但实际文本分别在 `design.txt` §[section-4] 与 `prd.txt` §[section-4]/§[section-5]（见第 1、2、3 节）。按评审给的编号去查，读者可能翻到别的章节，反而更容易只看到出处 A 的一句话。
