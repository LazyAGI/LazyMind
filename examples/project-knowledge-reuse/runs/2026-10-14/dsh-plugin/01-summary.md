## 1. 用户与任务

**这是什么**：“知策”是一个**面向产品团队的竞品研究 Agent** 的概念方案，主张“让每条竞品结论，都能回到证据”；定位为目标可确认、过程可控制、结论可复核。

（来源：`design.txt` §[section-8]；`prd.txt` 文档 ID `doc_bc9879c116ae6e5b264200dc3f09378b` §[section-3]。）

**核心任务与场景**：
- G1 研究结果能回到具体证据；G2 人工可控制范围、复核与异常；G3 确认版本不会被静默改写。（`prd.txt` §[section-2]）
- 三个场景：S1 每周竞品研究；S2 新功能专题对比；S3 负责人复核报告。范围来自案例设定，**真实需求强度待验证**。（`prd.txt` §[section-2]）
- 价值主张：减少“整理后还要重做一次核验”的工作，**不承诺替团队作最终产品决策**；用户是否愿为此流程付费**仍待验证**。（`design.txt` §[section-2]）

## 2. 主要流程

**五步主路径**：提出问题 → 确认计划 → 收集证据 → 复核结论 → 确认与导出。
（来源：`design.txt` 首屏与 §[section-8]；五个交接点分别标为用户发起 / 用户确认 / Agent 执行 / 人机协作 / 负责人确认。）

**状态机**：任务状态与报告状态分开管理，另有暂停、失败、取消与确认后修订出口。（`prd.txt` §[section-4] 与状态流转图）
- 主链：待确认 →（创建者确认计划，锁定计划版本）执行中 →（完成报告与基础校验）待复核 →（负责人确认该版本）已完成。
- 异常链：执行中 →（创建者暂停）已暂停 →（继续，范围不变）执行中；执行中 →（整体阻塞）执行失败 →（重试）执行中；任何非终态 →（取消）已取消。
- 修订链：已完成 →（创建者发起修改）待复核，新增草稿，**旧确认版本不变**。
- 关键约束：**计划启动后要变更竞品、维度或来源范围，应复制配置创建新任务**，不在原运行中静默替换；已取消任务不恢复执行；非法转换必须拒绝并说明当前状态。（`prd.txt` §[section-4]）

**页面组织**：研究列表 + 任务详情（概览 / 过程 / 证据 / 报告）；桌面“左侧过程、右侧报告”，移动端顺序展示且矩阵可局部横向滚动。（`design.txt` §[section-4]；`prd.txt` §[section-6]）

**四个核心对象**：研究任务、证据、结论、报告版本。（`design.txt` §[section-1]、§[section-3]；`prd.txt` §[section-4]）

## 4. 版本与导出规则

**版本规则**（`design.txt` §[section-3]、`prd.txt` §[section-4]/FR-009、`review.txt`）：
- 报告版本状态：草稿 → 待复核 → 已确认；退回则为草稿。
- **已确认版本不可原地改写**；修改已确认报告 = 新建草稿，旧版本、原证据和确认记录保留。
- 版本唯一；确认记录人、时间、版本号。
- 版本冲突时提示较新版本，**禁止静默覆盖**；保留本地未提交文本，重新载入后人工合并，再次确认需走复核。
- 证据状态：已记录、待复核、已排除；排除须保留理由，**历史引用不消失**。
- 证据片段**不是完整网页存档**；链接失效后仍保留片段与日期，但必须提示无法重新访问，**不能声称已完成最新核验**。（`design.txt` §[section-3]）

**导出规则**（`prd.txt` §[section-3] 权限表、FR-011）：
- 格式：HTML 与 Markdown。
- 文件须包含版本、状态、观察日期、来源和缺口；草稿及部分结果带明确标签。
- **不发送给第三方**、不发送邮件、不公开分享链接；导出失败可重试且不影响报告状态；导出前再次校验版本与权限。
- 确认后**不自动对外发送**（`design.txt` §[section-3] 状态转换表：负责人确认 → 报告已确认、任务已完成、不自动对外发送）。

**归档与恢复**：归档只隐藏任务、不删除内容；执行中拒绝归档；**首版无永久删除入口**，保留与删除政策待定。（`design.txt` §[section-5]；`prd.txt` FR-012、§[section-9]）
