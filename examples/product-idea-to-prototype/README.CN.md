# 一个产品想法，逐步长成方案、PRD 和原型

[English](README.md) · [全部案例](../README.CN.md)

> 把“我想做一个……”推进到能拿出来讨论的文档与界面。

一个想法刚出现时，目标用户、使用场景和功能边界通常还没有定清楚。直接开始写 PRD，容易把尚未确认的假设写成需求；直接画原型，又容易先纠结界面，后补产品逻辑。

这条演示从需求追问开始：先明确范围，再把竞品分析、产品方案、需求文档和原型串起来。每个阶段都有可以查看的成果，方便在继续推进前修正方向。

## 想法怎样逐步变得具体

| 阶段 | 帮你回答的问题 | 可以拿来讨论的内容 |
| --- | --- | --- |
| 需求澄清 | 为谁做，优先解决什么问题？ | 明确的产品方向与范围 |
| 竞品与生态位 | 已有方案覆盖了什么，还有哪些空间？ | 对比分析与定位讨论 |
| 产品方案与 PRD | 核心场景、功能和规则如何组织？ | 可阅读、可编辑的方案与需求文档 |
| 交互原型 | 用户进入产品后，怎样完成核心任务？ | 可展示的界面与流程 |

## 视频里的看点

约 00:19 可以看到用于确认范围的追问界面；随后展示工作流中的多个产物入口，以及包含功能、角色权限、异常恢复等栏目的一份方案文档。后段继续展示阶段编辑与原型界面。

这些成果让讨论有了具体对象：团队可以指出某个范围不对、某条规则缺失，或者某个页面需要调整，再继续完善。产品经理、创业团队和需要把新需求讲清楚的业务同学，都可以从这个场景入手。

## 开始体验

按[快速开始](../../docs/quick_start.CN.md)进入 LazyMind，选择产品方案相关能力。准备你想解决的问题、目标用户和已知约束，先让追问帮助你补齐范围，再逐步检查各阶段成果。

视频适合快速了解整个过程；做自己的任务时，为关键产品判断留出审阅时间。
