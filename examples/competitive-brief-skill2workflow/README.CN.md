# Competitive Brief：真实 Skill2Workflow 兼容性实验

[English](README.md) · [复现](REPRODUCTION.md) · [评估](EVALUATION.md) · [实现审计](AUDIT.md) · [来源](SOURCES.md)

**状态：兼容性实验，不是自主执行成功的 Showcase。** 本案例实际安装、自动转换并发布了 Anthropic 的 competitive-brief Skill，也实际启动了 Workflow。首次外部任务在五个步骤中的第三步失败。通过官方接口限定重试步骤的交付范围后，该步骤恢复成功；原始失败记录予以保留。生成的 Workflow 没有被手写版本替换。

后续有干预推进完成了会话并交付报告。但报告仍有事实边界问题，两条编辑接口测试均失败，人工审核仍未完成，因此以 Draft 兼容性报告投稿。

## 产品经理要解决的问题

为一个 20 人软件团队比较 Linear 与 Asana，覆盖产品研发协作和跨职能发布计划。报告要求包含七个章节、功能与定位对照、按年付费的单价和 20 人年度费用、内容缺口假设、3–5 项建议，以及事实、推断、未知信息和待人工审核的明确边界。

原 Skill 提供研究方法。转成 Workflow 的动机是分别检查研究、定位分析和报告，并在失败时复用已有产物。本实验验证这些能力实际如何工作，不把有面板等同于更可靠。

## 已执行的范围

- 原始 Skill 在 Codex CLI 中完整运行三次，实际报告和工具记录位于 [baseline](evidence/baseline/)。
- SKILL.md 的 `/blob/` URL 安装失败；改用相同 commit 的目录 `/tree/` URL 后，经正式外部任务入口完成安装、Preflight、模型转换、发布和执行。
- 自动生成五步：需求整理、竞品研究、定位分析、报告综合、可选战卡。首次自动执行完成前两步，第三步因中间 JSON 被按最终 Markdown 报告验收而失败。
- 官方重试和后续推进属于**有干预恢复实验**，与首次自动执行的结果分开报告。详见 [评估](EVALUATION.md) 和 [问题记录](ISSUES.md)。

两种模式都使用同一份任务和七张官方资料卡。资料获取阶段真实联网，模型执行阶段明确为**离线回放**；资料卡是研究者选择的公开网页事实摘要，并非完整网页镜像。没有使用付费数据库、私人材料或登录竞品账号。

## 能说明什么

可以说明这个 Skill 的自动转换链路确实被执行、步骤与产物可以观察，以及本次失败如何通过官方接口恢复。不能说明端到端自主执行稳定、报告必然更好、成本更低或已完成人工审核。实际部署的 Core 缺少 VCS 信息，不能把本地部署运行结果等同于被审计 main commit 的 E2E 结果。

本案例适合评估可检查研究流程的产品经理，以及排查 Skill 兼容性的维护者。它区别于已有 Product Solution Delivery 的人工适配，也区别于 Superpowers 案例：这里保留了独立 Skill 来源、真正自动生成的包、原 Skill 的固定资料基线，以及失败和恢复证据。
