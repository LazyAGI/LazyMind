### 1. 大纲错误在当前工具内纠正

修改 `workflows/ppt-workflow/runtime/scripts/run_stage.py` 的 `cmd_outline`：

- 先使用已有容错解析和字段规范化；页码等表示差异仍优先由代码整理，不额外调模型。
- JSON 无法解析、页数不符合要求、标题缺失、字段类型不合法等错误，将具体错误和上一版输出交给模型纠正。
- **最多三次尝试总计：首次生成 + 最多两次纠正**，不是失败以后再加三次。
- 不退出到外层 Agent，不新建 deck，不重跑需求分析、素材或其他上游步骤。
- 保留内容大纲路径；旧的样式与大纲组合路径一旦得到有效样式，后续纠正只处理大纲，复用该样式。
- 所有尝试失败时不覆盖已有大纲文件，保留后续重试所需内容。
- 不强制 `submit_deck_outline` 等工具 schema，继续使用当前文本 JSON 模型通道。

**触发证据：自动化回归已模拟并触发 JSON 纠正；目前检查的实际端测日志没有可确认的内部纠正记录。内部 attempts 未保留到最终生成日志，因此不能断言从未触发。目录、参数与文件权限重试不属于此机制。当前新流程在最终生成阶段执行这套结构纠正。**

纠正仍要求模型返回完整的修正后 JSON。“局部”指执行范围留在当前步骤，不代表只传一个字段的补丁，也不能保证模型绝不改动其他内容。

供应商错误不进入这套内容纠正循环：`ModelClientError` 直接报告失败，其他异常沿现有错误路径传播。内容纠正调用关闭模型客户端额外重试，避免纠正次数与底层重试叠加。原 `OUTLINE_SN_TEXT_RETRIES` 不再控制此路径。

每次纠正使用同一开始时间计算剩余超时额度，不为每次尝试重新分配完整超时。需要注意底层流式 HTTP 通道可能把 timeout 解释为无数据超时；这不是独立线程强制终止的绝对墙钟上限，不能承诺整个工具严格在该秒数内退出。

### 2. 生成成功与发布成功分别判断

修改 `workflows/ppt-workflow/scripts/tools.py`：

- 批量返回新增 `unpublished_pages`，明确列出没有发布成功的计划页，包括被前面的失败页阻挡的后续页。
- 只有无生成/发布失败且计划页全部发布，批量结果才为 `ok`，并清理对应重试检查点。
- `ppt_generate_pages` 再核对本次大纲中的页面集合与本次成功发布回执，不只相信文件数量、`published_count` 或工具调用没有抛异常。
- 删除“零发布但已有生成结果，就扫描目录发布所有页”的兜底分支，避免把残留旧页面当作本次结果。继续由现有批量逐页发布和按页恢复处理。
- 修复单页路径：HTML 生成成功但返回的发布结果失败、或者存在 `publish_error` 时，`ppt_run_stage(page-html)` 报告失败，不再返回成功。

**核查结论修正：现有 `_stage_tool_result` 已经把批量 `partial` 转为工具失败。因此不能说当前正常批量链路一直会把 partial 当作成功。** 本次全量检查是额外的防御性保护；单页生成成功但发布失败的结果转换则是实际修复点。

`_publish_one_page` 原本就检查 HTML 和讲稿两个保存动作。本次保留并补充回归，任一动作失败都不能算该页发布成功。

没有引入完整 `execution_state.json` 系统。继续使用本地 `.page_retry_NNN.json` 输入与输出指纹：已有有效 HTML 的页面重试时不再调模型，重新执行发布。可能重新发布同一批里之前已成功的页面，但不会重新生成它们；这并不是完整的“已发布页跨进程永久跳过”方案。

### 3. KB 参数适配放到实际代理入口

参考产品 PR #4 的实现，修改 `algorithm/lazymind/chat/engine/tools/lazy_kb.py`：

| 输入 | 处理 |
| --- | --- |
| 真正的字符串数组 `['ds_example']`（Python 对象） | 正常走现有数组校验 |
| JSON 文本 `"[\"ds_example\"]"` | 在代理工具入口解码为数组，再做原有校验 |
| Python 字面量文本 `"['ds_example']"` | 不做宽松解析，仍拒绝 |
| 数字数组、对象、单个字符串、null 的文本形式 | 不转换，交给原有 schema 拒绝 |

通过 `__tool_input_adapters__` 注册在 Agent 实际看到的 `lazy_kb.KBToolkit.kb_search` 上，正式参数仍为 `Optional[List[str]]`。没有使用 `eval`，没有把接口放宽为任意字符串，没有修改配置或权限控制。

新增测试通过真实 ToolManager 注册与调用，验证字符串数组确实被解码并传到下层；下层检索服务使用替身，不向真实知识库发请求。因此能确认入口链路适配有效，不能据此宣称实际知识库服务端已经端到端验证，也没有将问题归因到某次重构提交。

### 4. 素材检索停止与每页图片限制

修改 `scenario/state.yml` 和 `runtime/prompts/page_html.md`：

- 核心资料足够即停止继续检索；提示词设置一次素材步骤最多 6 次检索调用，包含失败和参数修正重试。
- 达到限制后记录现有证据和缺口，不为相同缺口重新执行整段素材收集。
- 普通增强图片缺失可用无图排版、CSS/SVG 或有依据的图表继续；明确指定的人物、产品或参考图缺失时必须说明，标记相关页待补充，不能静默假装满足。
- 搜索/生成素材按计划页数分配，每页至多一张内容素材；页面 prompt 明确一张、只放置一次、不额外拼接其他素材。
- AI 底图仍视为单独背景层，不计入该内容素材数量。

以上检索次数和图片数量是**提示词约束**，不是执行器硬限流或 HTML 图片计数拦截。已有三页流程实测，但不能据此保证模型在所有场景永远遵守。页数较多时，6 次检索预算也可能触发缺图降级；该数字是本次实施选择，不是孙奇提供的测速结论。

## 二、对应孙奇案例的回归结果

使用替身模拟“5 页中第 2 页首次失败，其余页面生成成功”：

1. 首次返回 `partial`，生成成功 4 页，发布成功 1 页，未发布页为 `[2, 3, 4, 5]`。
2. 用同一 deck 再次调用，第 1、3、4、5 页复用已有 HTML，只重新生成第 2 页。
3. 第 2 页成功后，按顺序发布全套页面，不丢失被阻挡的后续页。

另外覆盖：生成全部成功但发布失败后只补发布；讲稿保存失败不能算整页发布完成；目录中旧的第 99 页不能代替计划中的第 1 页；回执缺失或 partial 不能通过整套完成检查。

这些是自动化模拟场景，没有复用孙奇的真实会话数据，也没有解决模型供应商 `data_inspection_failed` 本身的原因。
