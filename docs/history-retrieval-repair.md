# 历史检索与正文阅读：开发期兼容性变更

本次将 LazyLLM 通用文件工具的默认读取坐标改为真实物理行号。`read.offset` 从 1 开始，`limit` 按物理行计数，与 `grep` 的行号一致。不保留此前每 1024 字符计为一行的模式，也没有行内分页参数。

`read` 的每行显示内容最多 2000 个 Unicode 字符（换行符用于保留记录边界），并受原有 UTF-8 字节预算限制。`line_unit=physical`、`offset/end_line`、`truncated_lines`、`eof` 和 `next_offset` 一起描述实际窗口。EOF 只表示没有后续行；被截断的行尾需要已授权的、有界 Shell 提取，不能通过下一行 offset 找回。读取会分块丢弃长行剩余内容，不先加载整个长行。

`grep` 返回最多 1000 字符的命中附近片段。片段截断与整体搜索缺口分开表达：`snippet_truncated`、`output_limit_reached`、`skipped_records`、`search_incomplete`。单条 rg JSON 记录的解析上限为 16 MiB，超限记录被丢弃后继续处理后续记录。工具不解析任何特定 Agent 的历史格式。

历史目录中的 `reader_logical_lines` 引用不批量迁移。打开目录供 Agent 使用时移除失效的 offset，保留路径并提示重新定位。新窗口使用 `physical_lines`，Core 合并读取证据时整体替换窗口元数据。完整的用户/助手消息记录可以成为消息读取证据；截断记录不能。任意 Shell 输出保持 `unparsed`，不通过猜测命令获取资源身份；这表示自动采集未知，不表示 Agent 没有读到 Shell 显示的内容。

正常 Main Chat 的重复检测跨工具批次生效，按工具、规范化参数及实际结果识别。第二次相同结果发出提醒；提醒送达后连续两批全部为已见结果，才请求最终回答。新结果、参数变化、上下文压缩以及不合格批次会重置连续计数。失败、未执行、授权等待和轮询不会触发自动收敛。Workflow 和隔离侧聊不启用新的自动收敛条件。

重复提醒优先进入模型上下文，覆盖事实省略零计数并限制可选定位信息。运行时元数据上限由 2048 调整为 4096 字符，配套预留 1024 tokens，防止提醒被大段覆盖事实挤掉；这不扩大正文存储上限。

最终回答沿用上下文压缩及预算校验，包含原问题、已有证据、最新工具批次和执行事实，不再只截取最近 8 条短消息。最终请求不提供工具定义；取消和模型失败仍按失败/取消处理。

测试及真实运行的原始记录位于 `data/directory-poc/history-repair-20261014/`。该目录是本地验收产物，不作为产品数据或新的历史检索服务。
