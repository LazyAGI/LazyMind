# 外部 Agent 使用 LazyMind 模型与工具

LazyMind 可以把当前用户明确授权的模型和工具，通过统一 MCP 入口提供给 Codex、Cursor、WorkBuddy、商汤小浣熊、TRAE Work 和 DeepSeek Harness。模型 API Key、MCP Token 等凭证始终保存在 LazyMind 服务端，外部 Agent 只能列出和调用能力，不能读取或修改原始连接配置。

## 1. 启动 LazyMind

开发环境在仓库根目录执行：

```bash
make local-up
```

服务就绪后打开 LazyMind。标准本地端口下，页面地址为 `http://127.0.0.1:8091`。请先登录，再进行后续配置。

## 2. 配置并验证模型

1. 打开“设置 → 模型服务”。
2. 添加 OpenAI 兼容供应商地址和 API Key。Base URL 通常填写到 `/v1`，例如 `http://10.119.20.126:8000/v1`。
3. 获取或填写模型名称，例如 `Qwen/Qwen3.8-Flash-Next`。
4. 完成连接验证并启用模型。

只有“已配置、验证通过且启用”的模型才能授权给外部 Agent。API Key 不会出现在外部能力列表、调用结果或调用记录中。

## 3. 配置并验证工具

### MCP 工具

1. 打开“设置 → MCP”。
2. 点击添加服务，填写服务名称、传输方式和 MCP 服务地址。
3. 如服务需要认证，在 LazyMind 中填写 API Key 或请求头。凭证只由 LazyMind 服务端使用。
4. 保存并验证连接，等待 LazyMind 发现服务提供的工具。
5. 选择允许使用的具体工具，并启用该 MCP 服务。

可开放的不只生图工具。任何已经在“设置 → MCP”中成功发现、验证、启用并被该 MCP 服务允许的工具，都会进入外部授权候选列表，例如搜索、浏览器操作、代码执行、数据库查询、文件处理或业务系统工具。实际可用范围取决于已接入的 MCP 服务。

### LazyMind 内置工具

本期已经提供 `image_generator` 外部适配器。它会使用 LazyMind 中当前选定且验证通过的图片模型执行生图。后续内置工具需要先实现安全的外部适配器，才会出现在授权列表中；LazyMind 不会默认把所有内部工具自动开放。

## 4. 按 Agent 授权能力

1. 打开“设置 → 助理”。
2. 在“外部能力授权”中选择 Codex、Cursor、WorkBuddy、商汤小浣熊、TRAE Work 或 DeepSeek Harness。
3. 分别开启允许该 Agent 使用的模型和工具。
4. 在同一 Agent 卡片中完成“使用 LazyMind MCP”的连接。

模型与工具默认对已接入的外部 Agent 开放。配置模型连接及 Key、验证通过后，兼容的 LLM/VLM 模型默认开启；图片模型仍通过生图工具使用。工具仅限当前用户可用、验证通过、启用且具备执行上下文的工具。新增符合条件的能力也默认开放。设置页不再展示模型/工具逐项授权列表，只保留能力说明和调用记录、统计及结果。后端仍保留按“当前用户 + 外部 Agent + 具体能力”的授权接口，已有显式关闭设置继续生效，不会因刷新、重启或重新发现而覆盖。关闭 Codex 的某个能力不影响 Cursor 的设置。原始 Key 仍由服务端保管。

## 5. 在外部 Agent 中调用

完成连接后，建议在外部 Agent 中新建对话，使新的 MCP 配置生效。LazyMind 对外提供四个统一工具：

| 工具 | 用途 |
| --- | --- |
| `model.list` | 列出当前 Agent 已获授权且仍然可用的模型 |
| `model.chat` | 通过 LazyMind 服务端代理调用指定模型 |
| `tool.list` | 列出当前 Agent 已获授权且仍然可用的工具及输入结构 |
| `tool.call` | 通过 LazyMind 服务端执行指定工具 |

可以直接对 Agent 说：

```text
请先调用 LazyMind 的 model.list，选择 Qwen/Qwen3.8-Flash-Next，
再用 model.chat 回答“你好，请简单介绍一下你自己”。
```

调用工具时先列出能力，再按返回的 `id` 和输入结构执行：

```text
请先调用 LazyMind 的 tool.list，找到 image_generator，
再通过 tool.call 生成“一只草地上奔跑的小狗”。
```

外部 Agent 看到的是 LazyMind 能力 ID、名称、说明和参数结构，不会得到模型或工具的 API Key、Token、认证请求头及原始连接配置。

## 6. 在 LazyMind 查看调用结果

打开“设置 → 助理”，在“外部调用记录”中选择对应 Agent：

- 顶部显示总调用数、模型调用数、工具调用数和失败数。
- 明细显示调用方、能力、状态、Token 或结果大小，以及调用时间。
- 点击“查看结果”可查看模型回答或工具返回值；本地生图结果会同时显示图片预览。
- 内置生图的调用记录保存稳定资源路径，读取当前用户的记录时重新签发短期图片链接；旧记录中的过期链接也会自动刷新（包括多张图片及 Markdown）。签名校验仍然保留；页面长时间停留导致链接过期时，刷新调用记录即可。外部 Agent 已收到的旧链接不会自动改变，需要重新获取结果链接或在有效期内保存图片。
- 失败调用显示经过安全处理的失败原因和处理建议，不回显上游原始错误或凭证。

结果记录仅用于当前用户审计。LazyMind 不保存外部调用的请求正文；结果预览会递归移除常见凭证字段，并限制字符串、数组、对象和总存储大小。超出限制时页面会明确标记为截断预览。

## 7. 取消授权或停用能力

以下变更都会在下一次外部调用时立即生效，不影响 LazyMind 内原始配置：

- 在“设置 → 助理”关闭某个 Agent 的模型或工具授权；
- 停用或删除模型、模型供应商或 MCP 服务；
- 模型或工具连接验证失效；
- 从 MCP 服务允许列表中移除某个工具。

已经开始的请求可能继续完成，但 LazyMind 不再接受新的调用。调用方会收到“未授权”或“能力不可用”提示，可重新执行 `model.list` / `tool.list` 选择当前可用能力。

## 8. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| Agent 中看不到 LazyMind 工具 | 在“设置 → 助理”确认该 Agent 的 MCP 连接已启用，然后新建 Agent 对话 |
| `model.list` 返回空列表 | 确认模型已验证、启用，并在当前 Agent 的“外部能力授权”中开启 |
| `tool.list` 返回空列表 | 确认 MCP 服务已验证、启用、发现了工具，服务允许该工具，并对当前 Agent 授权 |
| 调用提示未授权 | 授权按 Agent 隔离，请确认设置页当前选择的是实际发起调用的 Agent |
| 调用提示连接不可用 | 回到模型服务或 MCP 设置重新验证连接；外部调用失败不会自动修改原连接配置 |
| 页面没有结果 | 点击调用记录右上角“刷新”；执行中的记录会在调用结束后写入结果或安全错误信息 |

## 9. 安全边界

- 不支持导出明文 API Key、Token 或 MCP 请求头。
- 不自动共享用户的全部模型和工具。
- 外部 Agent 不能通过能力网关新增、修改或删除 LazyMind 连接配置。
- 调用日志记录用户、Agent、能力、时间、状态、用量和脱敏后的结果预览，不记录请求正文或明文凭证。
- 模型和 MCP 的实际网络请求始终由 LazyMind 服务端代理完成。

实现与安全校验的技术说明见[外部 Agent 能力网关架构](architecture/external-agent-capability-gateway.md)。
