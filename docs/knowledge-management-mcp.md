# 知识库管理 MCP

本实现由 Core 资源服务负责事务、权限、冲突和回执，页面与 capability 复用服务。MCP 只负责协议映射；Chat/Work 宿主负责可信身份、文件授权和业务确认。

## 工具与权限

内置管理连接仅加载 `knowledge.list`、`knowledge.document.list`、`knowledge.document.aggregate`、`knowledge.create`、`knowledge.folder.create`、`knowledge.resource.update_metadata`、`knowledge.resource.move`、`knowledge.resource.delete`、`knowledge.document.upload`，共 9 个工具。公开连接另保留原有 `knowledge.document.get` 和 `knowledge.search`。

工具继承账号功能权限、知识库 ACL、来源访问策略和可信执行约束。模型不能填写用户身份、批准状态或执行凭据。内置连接在实际派发出口校验来源与工具白名单；显式空白名单不加载任何工具。原生 KBToolkit 保留五项读取能力，固定历史 Workflow revision 通过实例级兼容路径读取原查询工具。

创建、上传、元数据修改和同库移动不额外审批。LazyMind 内删除和跨库移动必须确认具体资源、路径、数量和影响；确认绑定参数摘要与资源快照，提交事务内再次校验。公开 MCP 没有 `confirmed` 参数或额外确认工具，由调用方决定交互。

## 工具参数说明

已移除 MCP `knowledge.options`；前端 `GET /knowledge/options`、页面调用和后端共享配置查询保留。公开连接共 11 个知识库工具（上述 9 个加原有读取、搜索）。外部客户端需重新连接并执行 `tools/list` 刷新缓存。

9 个管理工具的参数说明均由 MCP `inputSchema` 提供，包含嵌套资源引用、分页、上传文件、阅读能力配置和按资源类型区分的更新字段。工具总说明只交代用途、执行边界和结果含义。询问参数时直接读取工具定义，不需要调用额外配置工具。

- 列表：来源、场景、权限、匹配与排序可选值；过滤条件组合；父目录省略/空值与递归语义；默认每页 20 条，续页必须沿用原查询参数。
- 统计：筛选字段、分组维度和预算；无分组时只返回总量；多标签可以出现在多个分组，但总量不重复。
- 创建与更新：名称和标签限制、场景/能力 key、处理级别、默认算法、自定义预设条件；创建省略处理级别自动选择，更新省略则保持，更新传空字符串报错。
- 目录与资源操作：相对目录路径规则、各资源类型必需的 Core ID、标签追加/替换、目录标签递归条件、移动的逐根事务与跨库 ID 变化、删除和物理清理的区别。
- 上传：共享文件系统绝对路径、格式和大小限制、显示名称及标签规则；保存原件不等于解析完成。

固定枚举直接列在参数描述中；自定义预设 ID 和部署算法 ID 必须使用已知有效值，不猜测或硬编码当前账号的目录。处理能力和跨库移动预算仍以服务端实际可用性为准。仅修改说明，不改变业务校验、字段类型和必填关系。

## 原件与结果

上传仅接受同机共享文件系统上的绝对普通文件路径：

```json
{"knowledge_base_id":"ds_...","files":[{"path":"/absolute/path/paper.pdf","display_name":"paper.pdf","tags":["论文"]}]}
```

每次最多 20 个文件，单文件 500 MiB、总量 1 GiB。Core 先检查目标权限，再打开文件，用同一文件描述符检查并流式复制、哈希和验证；目录、设备、FIFO、空文件及不匹配的内容被拒绝。MCP 的 `files` 和 `files[].path` 参数说明直接列出限制与格式；可保存不等于存在对应解析器。前端继续通过 `GET /knowledge/options` 获取上传限制、场景、算法与解析器配置。

不再接受 `source.kind`、`file_ref`、URL 或 Artifact ID。调用方先把聊天附件定位到原始路径，把 URL 下载到会话工作目录，把 Artifact 导出为文件；目录/ZIP 在调用方显式枚举或解压，配合目录工具上传。读取引用 `fr_...` 不是上传路径。CLI 直接传路径，不再要求 MCP roots 或转发文件字节；Chat 继续执行已有宿主文件授权。远程不共享文件系统的 agent 不在此契约支持范围。

页面传字节，MCP 传路径，最终均经过 OriginalService 的原件绑定和处理流程。知识库原件独立保存，删除源文件不会影响已入库文档。会话工作目录、Artifact 存储和知识库原件目录保持原有职责，没有新增存储体系或清理任务。

创建支持必填非空标签、场景、已有自定义预设、算法、处理级别和阅读能力，知识库记录及阅读配置同事务提交。默认场景 `general`，论文场景 `academic_papers`（接受旧 `paper_collection` 别名）；自定义预设使用 `scene=custom`、`profile_id`。显式能力覆盖场景默认；更新场景应用场景默认能力，单独修改能力保留场景身份。处理默认由服务端计算：关闭解析为 stored、向量模型就绪为 indexed、其余为 chunked；显式不可用配置返回错误。

工具返回后立即报告真实状态，不固定 sleep，也不自动轮询。用户要求查看进度时才查询；论文速览可以使用附件已有文本。模型输出不承担页面导航：工具返回资源引用，Chat 将可信结果保存为入口卡片，前端用当前路由打开，刷新恢复并按调用 ID 去重，删除项不显示失效链接。

资源状态、处理状态和回收状态各自返回。未知处理阶段为 `unknown`，stored 为 `not_requested`，不能把 uploaded/moved 当成 ready。独立根目录分别提交、分别返回结果；单根整树失败不留下部分目录。确认之后新增的后代、源或目标变更会拒绝提交。

同一操作键绑定用户、租户、动作和参数摘要。已提交回执优先于源资源查询，删除/移动后仍能核对真实 ID；无法确认提交结果为 `unconfirmed`。超时、断线和取消不代表已经提交的项回滚，也不会自动整批重试。

## 分页与统计

保留原有 `items/page`、`items[].id`、默认列表行为及 path 上传相对目录含义。`logical_path` 表示逻辑目录路径。`parent_id` 省略表示全库范围，空字符串表示根目录。多库结果在 Core 统一排序和分页，游标绑定用户与查询。

统计扫描、分组维度和组数有界；超出返回 `QUERY_TOO_LARGE` 及实际值、上限和缩小范围建议。删除/移动使活动映射失效，原生检索、公开 get/search、扩展节点、图片和引用都校验当前映射；迟到发布与历史回填不能复活已移除文档。

## 发布开关与预算

原管理能力已在之前的隔离 8091 验收中默认启用；本次契约变更的验证记录见 `docs/plan/knowledge-mcp-page-parity.md`。设置 `LAZYMIND_KNOWLEDGE_MANAGEMENT_ENABLED=false` 可关闭新增管理入口和宿主加载；未知配置值也按关闭处理。跨库移动仍要求目标部署提供已校准预算，默认开放管理能力不会绕过此门槛。

完成目标部署的性能测量后，通过私有运行配置设置 `LAZYMIND_KNOWLEDGE_MOVE_BUDGET_JSON`：

```json
{"max_resources":100,"max_bytes":33554432,"prepare_seconds":30,"copy_bytes_per_second":1048576}
```

此处数值仅展示格式，不是测量结论。配置必须全部为正，准备时限为 4–300 秒；运行剩余时间更短时取较小值，并预留三秒提交与回执核对时间。校准应覆盖资源/空目录数量、实际原件复制、数据库事务与来源策略调用；直接 SQLite 测试不能代替部署中 SQLite proxy 的验证。

内置凭据有效期五分钟，账号与运行在调用时校验；慢准备之后、事务开始前刷新账号，事务内锁定运行归属并复核任务/attempt/lease。通知只提供真实调用开始/结束；最终结构化结果始终是资源与处理状态依据，不报告伪造的逐文件百分比。

## 验证与已知边界

阶段证据见 `.superpowers/sdd/knowledge-management-mcp/`。资源故障注入、竞态检测、双数据库迁移、真实 Work 双写产物、宿主白名单、确认卡、MCP 结构化结果及进度绑定有定向测试。整体 Core 套件仍有独立确认的基线失败及间歇 sidecar 超时，不能称为全绿。

外部 KB provision 成功而 Core 创建事务失败时，可能保留外部孤儿。没有做可能误删同键并发创建结果的补偿删除；需要独立核对后回收。大规模异步移动、原件替换和第三方 URL 自动 OAuth 不在本期。

8091 部署必须使用专用运行配置与隔离入口；先对受影响数据库进行原生一致性备份，并保存原件、索引和必要配置。不得触碰 8090，不能以健康检查代替登录、页面、Chat/Work、CLI 和检索端到端结果。

本次 8091 使用 128 个资源、32 MiB、15 秒准备时限和 4 MiB/s 预算估算。三次真实 121 资源 / 32 MiB 整树移动耗时 0.79–0.82 秒；这是本机串行测量，不是生产并发容量或 p95。同步删除和同库移动也受资源树规模限制；超限需缩小显式选择范围，本期不提供后台批量任务。
