# PDF paper reading

The original-PDF reader can parse formulas with the selected official MinerU service and show a LaTeX preview on hover. The formula marker also supports click and keyboard activation. The card exposes the recognized source for copying and opens a study dialog over the PDF with an interactive equation and a short explanation.

## Reading workspace

The paper workspace has a single header with a collection-back action and reader tools at the upper right. A compact chapter rail opens an animated outline over the rail itself; entries use source headings, omit page numbers, and remain open after chapter navigation. The original PDF stays centered on a white canvas at every zoom level. Bilingual comparison and the separate navigation/focus-reading controls are no longer exposed.

Floating tool buttons overlay the workspace without taking width from the reader or assistant. The assistant defaults to a sidebar; its layout menu supports left/right docking, a movable floating panel, and fullscreen. Closing or changing layout retains the conversation and drafts. At the displayed 100% zoom, paper PDFs use a 120% base scale and fit within the visible reading pane when the assistant is docked. The canvas renders at no less than 1.5 device pixels per raster pixel, capped at 2, to keep text crisp without increasing the page's layout width. Paper information and notes use the existing academic-library attachment association and write permissions; a selected quote can be transferred into a note draft before saving.

Selecting PDF text opens a compact question/note composer with translation and explanation actions. Questions prepare the assistant draft with source context without automatically sending; adding a quote without a question preserves existing draft text. The selection toolbar no longer offers download-and-import for references. Vocabulary still uses the existing feature switch: enable `LAZYMIND_VOCABULARY_ENABLED` in Core and `VITE_VOCABULARY_ENABLED` when building the frontend. The document vocabulary list is available in the paper information panel when this feature is enabled. Non-paper documents retain independent Translation / Chat switching, including unfinished translation text across panel changes. Formula, table, and visual studies open over the PDF rather than resizing the reading pane.


## Enable and use

Configure and select an official MinerU OCR credential in external-service settings. Open an original PDF in a knowledge document or paper attachment and enable formula parsing. Browser fingerprint validation requires HTTPS or localhost; insecure remote HTTP displays an explicit unsupported-context message. Parsing runs as a durable background job; the reader polls its status. Once ready, hover over an equation or activate its formula marker. Dragging to select document text keeps the existing text-selection behavior. Escape dismisses the formula card.

Parsing requires document write permission; existing results require read permission. The initial read does not upload the document. Local or custom MinerU services are currently reported as unavailable for this feature and are never silently redirected to the official service. Only the original PDF is supported; translated or regenerated PDFs must not reuse original coordinates.

## Formula study and navigation

Formula generation uses a compact, model-independent response contract: summary, symbol meanings and source IDs; the server supplies provenance flags and metadata. It normalizes the known purpose-field alias `explain` to `summary` and symbol-field alias `text` to `meaning` before applying the same content validation, without another model call. For supported DeepSeek V4/Flash routes on ZenMux, DeepSeek and AIHubMix, formula requests explicitly disable reasoning without changing the saved chat configuration. At the ZenMux transport boundary, a disabled reasoning feature is sent as `reasoning.enabled=false`, because omitting the parameter restores the provider default. DeepSeek and AIHubMix Chat Completions use `thinking.type=disabled`; unrecognized routes and models keep their existing reasoning parameters. Structured generation logs each actual attempt and its elapsed milliseconds without recording source text or credentials. Formula calls disable nested transport and JSON-generation retries. If the first call fails validation or returns an upstream error, or is still running after six seconds, its shared flight starts at most one backup call and returns the first fully validated explanation. Fast completions use one call. A slow or initially invalid completion can incur two provider charges; cancellation stops local waiting but does not guarantee the provider has stopped billing. If both calls fail, the old explanation remains readable and no partial result is saved.

Choose Explain on a formula card to request an explanation from the selected chat model. The light study dialog puts the repaired, interactive equation and a one-sentence purpose first. Its symbol cards show meanings without a source jump in the main view; reasoning, citations, warnings, and the formula catalog remain available in expandable details. Evidence buttons there can navigate to the original page and highlight the recorded region; Return restores the previous reading position and closes the study dialog. Keyboard focus stays within the dialog; Escape first dismisses an active symbol card, then dismisses the dialog. The formula catalog includes unnumbered equations. Inline `Eq. (n)`, `Equation (n)`, and `式 (n)` references navigate only when the IR contains a unique explicit matching formula tag. Ambiguous or missing numbers retain their original behavior. Native PDF internal links are intercepted only for a positively matched formula reference; external links and text selection remain available.

Explanations use nearby PDF IR, not retrieval results or embeddings. The selected model receives the recognized formula, the nearest section heading, up to two prose blocks before it, and up to three after it. Prose is limited to 1,500 Unicode characters per block and 5,000 in total; the formula and heading have separate limits. Selection stops at section boundaries and keeps post-formula definitions such as “where …”. Model input contains source IDs and text, without page or geometry metadata. The prompt requests all semantic terms in one concise response, including named operators such as `Attention`; it permits standard mathematical knowledge when the paper does not define a familiar operator, while requiring such explanations to be marked inferred and not attributed to a source block without support. Evidence text and coordinates are reconstructed from the IR on the server, never accepted from model-generated positions or quotations. Symbol associations and non-verbatim explanation steps are marked as interpretations even when they cite supporting text. This does not establish that the model's mathematical reasoning is correct.

The server caches explanations per user, source, parser, formula LaTeX, source text, and language. It rebinds current page geometry on a cache hit and coalesces simultaneous requests for the same key into one model call; one cancelled caller does not stop another caller's in-flight result. The browser retains up to 64 recent explanations for five minutes across popup reopenings, clearing them on user change. Switching the selected model preserves saved explanations and their generating-model attribution. Regenerate uses the current model and bypasses both caches. Closing the panel or switching formulas cancels the browser request. Access and source identity are checked again after generation. Successful responses expose `X-LazyMind-Formula-Cache` (`hit`, `miss`, or `shared`) and `Server-Timing` for latency inspection. Source passages can contain MinerU markup, which is displayed as plain text rather than executed.

The complete rendered equation supports selecting semantic symbols by pointer or keyboard. Identifier subscripts, superscripts, and accents stay attached to their variables; compound exponent expressions expose their inner variables separately. Model definitions for plain function names match the corresponding LaTeX operator wrappers. A selected symbol opens its precomputed meaning; clicking does not make another model call. If the model omitted a common `Attention`, `softmax`, or `ReLU` operator, the dialog shows a clearly labeled general mathematical meaning. Other missing or conflicting meanings remain explicit rather than guessed. Operators and punctuation retain their mathematical layout; unsupported or excessively nested syntax falls back to the original LaTeX. The raw LaTeX is collapsed by default. Only internally generated KaTeX interaction classes are trusted; PDF/model-supplied HTML commands are not enabled.

## Tables and related passages

Click an original table or its marker to open the table reader. Structured cells retain merged rows and columns, support keyboard navigation and selection, and display available source-designated headers without inventing header roles. The grid scrolls independently; source links locate and highlight captions or paragraphs in the original PDF. Formula and table studies share one panel and reading-position return behavior.

Table numbers and captions use the retained layout geometry. When MinerU groups several captions under one table, the projection requires a consistent caption side and an unambiguous adjacent table before reassigning them. Conflicting labels remain unnumbered. Explicit numbered references are linked only to unique table numbers. Where no explicit reference exists, a separate, unverified data-match clue may identify a paragraph containing at least three distinct decimal values, uniquely matching that table most strongly. Such clues do not establish a semantic relationship and are labeled separately from explicit references.

The additive `projection_version: 3` includes `block.table` with safe text cells, bounded `row_span`/`col_span`, captions, footnotes, optional number, and related block IDs. Caption source blocks include original page geometry. Existing source-matched IR can upgrade locally from its retained MinerU ZIP; every existing block is compared before an atomic cache replacement. This preserves original block IDs and avoids a new upload or parsing job. A missing or inconsistent ZIP leaves the older formula IR usable and reports an upgrade warning.

## Figures and contextual explanation

Numbered figures appear before unidentified image regions in the visual catalog. Image blocks carry captions, footnotes, optional numbers, and explicit paragraph references when attribution is unambiguous. Uncaptioned fragments remain regions rather than invented figure numbers. The visual reader links to the original highlighted region; a table can also open its structured cells.

Visual explanations use recognized captions, table cells, and surrounding source passages. They do not analyze image pixels. Distinct observations cite authoritative source passages, and table comparisons request the reported dataset, metric, and matching experimental conditions. Unsupported visual details and statistical significance must not be invented.

## Retrieval preparation status

The PDF chat preparation banner describes the separate retrieval pipeline. A formula result can be ready while retrieval preparation is still running or has failed. The banner checks the current remote parser task instead of treating a historical local running flag as authoritative. Remote failures expose retry; a completed reparse with readable roots can recover from an earlier upload failure. Roots without a task version are not treated as completion while the current worker still reports working, since they can belong to an older parse.

If retrieval preparation fails, inspect the parser worker and its OpenSearch and Milvus dependencies. Restoring those services and explicitly retrying preparation is preferable to changing document states by hand. Compose uses restart policies for both stores; this does not remove their health or storage requirements.

## Independent document structure

The PDF IR subsystem owns original-source blocks, formula/table/figure geometry, and evidence-linked reading. Retrieval indexes, full-document translation jobs, translation-provider settings, and vocabulary storage/synchronization remain separate domains. The reading workspace embeds their existing entry points; geometry and evidence features must not mutate those domains' configuration or data. Changes to those domains should be integrated through their respective modules rather than duplicating their stores or provider configuration in the reader.

PDF IR does not call the retrieval parser, create text chunks, or update vector indexes. It does not depend on the document's retrieval processing status. The original PDF is snapshotted for upload without modifying the stored source. Its SHA-256 fingerprint binds the result to those exact bytes; the browser checks the displayed PDF against the same fingerprint before enabling formula hit regions.

The backend retains the raw MinerU ZIP and a versioned IR JSON under the document's artifact directory. These are durable files next to the uploaded document, so that directory must be on persistent storage. Internal filesystem paths and credentials are not part of the reader response. Job payloads contain document identifiers, source fingerprints and parser revision, not credentials. Jobs resolve the selected credential at execution time.

The IR preserves returned block types, normalizes equation blocks to `formula`, and includes LaTeX, source text, page and geometry. The raw ZIP remains available server-side for information outside the current reader projection, including original image assets. This is not a complete semantic graph of the paper.

Coordinates use `normalized_top_left`: `[left, top, right, bottom]` in `[0,1]`, relative to the original visible page with its intrinsic rotation. Page indices start at zero. Invalid or missing boxes are omitted instead of guessed. Native text selection does not provide formula identity; pointer hit testing uses the independent formula regions. Browser zoom and page scaling do not change stored geometry.

## API

`GET /api/core/datasets/{dataset}/documents/{document}/pdf-ir` returns the current result without starting a job. `POST` to the same path starts parsing; `{ "force": true }` requests a new parse after a completed result. An active job is reused. Responses use the `data` envelope and statuses `not_requested`, `queued`, `running`, `ready`, `failed`, or `unavailable`. A ready response includes `document`, with `version`, `source_sha256`, `parser`, `coordinate_space`, `pages`, `blocks`, and optional `warnings`.

`POST /api/core/datasets/{dataset}/documents/{document}/pdf-ir/formulas/{block}/explanation` accepts `{ "force": false, "language": "zh" }` (`en` is also supported). Its `data` contains `summary`, `symbols`, `steps`, authoritative `evidence`, `warnings`, and `model`. Evidence pages are zero-based and boxes use the IR coordinate space. Non-success responses expose an actionable `data.error_message`. The endpoint requires read access and a current source-matched IR.

An optional `focus_symbol` requests one symbol's meaning. It must be a nonblank, exact substring of the source formula, at most 500 Unicode characters. The response must contain one symbol; its identity is bound to the requested source substring and its meaning remains an interpretation. Focused and general explanations have separate cache entries.


`POST /api/core/datasets/{dataset}/documents/{document}/pdf-ir/blocks/{block}/explanation` supports image and table blocks and returns `summary`, `observations`, authoritative `evidence`, `model`, `warnings`, and `source_sha256`.

`POST /api/core/datasets/{dataset}/documents/{document}/pdf-ir/blocks/{block}/translation` translates an authoritative text block and returns `block_id`, `translated_text`, `language`, `model`, and `source_sha256`. Text blocks are limited to 8,000 Unicode characters. The endpoint remains available to integrations, although the reader no longer exposes the bilingual comparison view.

Both reading endpoints accept `language` (`zh` or `en`), `force`, and an optional expected `source_sha256`. The reader supplies its displayed PDF fingerprint. A changed source returns 409 before cached content or model output is used, and the browser also checks the returned fingerprint. Invalid hash values return 400. Translation and visual caches are separate and scoped to the authenticated user and source. Translation retains its model-specific cache. Visual explanations reuse source-matched saved results before loading model credentials, independently of the currently selected model; explicit regeneration uses the current model. The original generation model is preserved on cache hits. Compatible legacy model-specific entries migrate on first access when that model configuration is available.

Complete model-defined function calls and norms are interactive as a unit: a meaning for `L(w)` or `\|\delta w\|` selects that whole expression instead of unrelated inner letters. Equivalent LaTeX delimiter notation is normalized only for matching; the original formula rendering remains unchanged. Regenerating a visual explanation retains its existing same-source result during updates, failures, and cancellation. A source mismatch discards that result.

## Limits and correctness

The reader targets detected standalone equations. Interactive symbols belong to the rendered study equation, not individual glyph hitboxes in the original PDF. It does not promise inline formula detection, complete cross-paper reasoning, or definitive links for references without unique identifiers. Recognition and rendering are separate: valid LaTeX can still contain an OCR error. Users should compare critical equations and table values with the original PDF. Missing geometry prevents hover rather than placing a misleading hit region. A mismatched source fingerprint prevents reuse and requires parsing the displayed original again.

The official parser currently uses the `vlm` model. Source PDFs are limited to 128 MiB, result archives to 256 MiB, and serialized IR artifacts to 32 MiB. An oversized IR fails explicitly instead of publishing a successful but unreadable artifact; an oversized projection upgrade preserves the existing usable artifact. Malformed formula syntax falls back to the original LaTeX without making the reader fail. Restarted or retried work may incur another service request; the remote provider does not share the application's job transaction.

## Registered structured model tasks

Formula and visual explanations use the existing internal `/api/chat/llm-task:run` endpoint. They no longer use the rewrite endpoint's `learning` task. The registered tasks are `paper.formula.explain` and `paper.visual.explain`; their versions preserve the previous formula/visual cache versions so existing saved results remain readable. Block translation and other rewrite/learning consumers retain their original interfaces.

The algorithm package `algorithm/lazymind/structured_tasks/` separates schemas, paper prompt definitions, a static registry, and the shared executor. A request supplies `task_type`, `input.data`, `options.task_version`, and the model configuration resolved by Core. Registered tasks reject caller instructions, skills, tools and arbitrary execution options. The executor validates inputs, prepares the server-owned prompt, makes one model attempt, and validates the output object. Known field aliases and Markdown fences are normalized locally; malformed JSON does not start another call. Native provider JSON mode is not required. The existing model adapter owns provider-specific request handling.

Core's `algo.RunStructuredTask` sends this contract and returns an output object with execution metadata. It does not fall back to rewrite or retry invisibly. Core retains document authorization, context selection, citation binding, source freshness checks, cache identity, and formula shared-flight/cancellation behavior. Formula flights may start their existing second attempt; visual tasks make one attempt. Optional formula repair suggestions still undergo Core's discard-and-preserve sanitization, so an oversized repair does not discard otherwise usable meanings.

To add a small feature, define its input/output schemas and prompt, register a versioned `TaskSpec`, and call `algo.RunStructuredTask` from its business handler. The new business handler must specify source/permission validation and cache policy. Adding a task must not require editing the generic executor or loading the conversation/Agent pipeline. Add contract tests for invalid input/output, model routing, one-attempt behavior, and any local aliases; keep existing rewrite and workflow regression tests passing.

Algorithm start/completion diagnostics record the task ID, registered name/version, model attempt count, elapsed time and safe failure code, without prompts, source text, generated content or credentials. Success metadata also identifies the configured model when available. Counts describe model attempts, not confirmed billed requests; token/cost values remain absent when unavailable. A transport failure without algorithm metadata has an unknown count (`-1` in Core diagnostics). Core cancellation ends its waiting, but the algorithm's bounded model call may still finish and incur provider billing.

## Figure and table study

Figure and table explanations use the same light study dialog as formulas. The original image can be enlarged in place. Tables offer interactive cells with row/column context and an original-image view, alongside the generated explanation. Captions and detailed provenance are expandable; source units and table footnotes remain available. The progress indicator is indeterminate and shows elapsed time, not an invented completion percentage. Cancelling or failing regeneration leaves the previous same-source explanation readable.

The browser retains up to 64 source/account/language-scoped results for five minutes, clearing them on account changes and logout. Reopening a cached study needs no network request. Server responses expose `X-Paper-Cache: hit|miss`. Visual context prioritizes the target and explicit references, with at most eight blocks and 12,000 characters total; the target receives up to 6,000 characters and other blocks up to 1,500 each. Supported DeepSeek routes use the formula reader's request-local low-latency setting without changing saved chat settings. There is one model attempt per visual request, without speculative parallel billing.

Opening figure or table study preserves the current PDF scroll position. An offscreen figure selected from the catalog is rendered for its preview without navigating the reading pane; only an explicit source-location action moves the PDF. Table dialogs expand to a responsive 1,120-pixel maximum and show dense rows without a separate short vertical viewport. Copy-table exports tab-separated cells, quoting embedded tabs/newlines and preserving merged-cell positions as empty slots; selected cells can also be copied independently.
