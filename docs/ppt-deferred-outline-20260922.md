## 改动后的流程

新工作流的大纲阶段，由当前规划 Agent 直接撰写供用户阅读的 Markdown，每页一个二级标题；`ppt_build_outline(outline_markdown=...)` 只保存与发布文字，不再嵌套调用模型生成页面 JSON。

每页提示词阶段读取用户当前选中的 `deck_outline`，按标题拆成可编辑的逐页文字卡片，不生成内部页面结构。

最后 `ppt_generate_pages` 才执行：

1. 读取当前选中、按用户顺序排列的逐页卡片，保留用户编辑。
2. 执行 preflight，把文字转换成内部 `outline.json`，处理页数与字段规范、素材绑定及局部纠正。
3. 准备 asset plan、统一样式，并发生成页面 HTML 并发布讲稿。

文字大纲仍需规划 Agent 生成，所以前面不会变成零耗时。避免的是前面额外一次结构化模型调用与校验等待；总耗时需要新一轮端测衡量，不能仅凭移动步骤宣称提速。

## 编辑、兼容与恢复

- 下游使用当前已确认的内容，不使用最初文字文件覆盖用户编辑。结构转换提示词要求保留标题、事实、条目与顺序。
- 转换检查点记录确认内容、任务与素材输入及输出摘要。生成失败后，只要这些内容没变，就复用已生成结构；编辑内容或输出变化后重新转换。
- 结构转换失败停在生成阶段，不继续 asset plan/HTML，不要求重新跑素材、底图或前面的大纲阶段。
- 现有单页编辑和插页入口保留。旧调用方不传 `outline_markdown` 时保留旧结构化大纲 API；新工作流提示词明确要求传入该参数。历史会话的旧配置可能继续使用旧路径。
- 前面的二级标题仅用于文字卡片分段，不要求用户提供内部 schema。
- 大纲删页后重新发布逐页卡片会清理尾部旧卡片；素材和底图与大幅改页之间的关联仍沿用既有流程，不能据此宣称任意改页均已端测。
