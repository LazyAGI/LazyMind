# 对话组与整理自由对话

## 产品约定

对话组是用户独立的导航和归属容器，不共享聊天上下文。组名称去除首尾空白后为 1–24 个 Unicode 字符；同一用户不允许大小写不敏感的重名。收录范围选填，最多 500 字。用户可以创建空组或单成员组，至少三条仅约束算法候选组自动创建为正式组。

组内首条消息创建会话时同时写入归属，打开组内输入界面不创建空记录。移除组只解除归属，不删除聊天内容，也不改变置顶、归档状态。修改收录范围只影响后续整理，不移动已有成员。

自动整理从侧栏“最近对话”旁启动，成功后自动应用，再提供即时纠错、撤回与确认保留。关闭抽屉只隐藏界面，不取消任务或确认结果；确认保留后禁止整轮撤回。

侧栏按置顶对话、置顶对话组、普通对话组、最近未归组对话展示，全部共用一个滚动区域。仅当前打开的组详情或对话使用浅灰底标记，不同时高亮父组。主聊天页不显示额外的组面包屑、对话标题、归属说明或调整归属按钮；归属操作通过侧栏和组详情的对话菜单完成。组名点击展开/收起，默认展示最近五条非置顶成员，可逐步加载更多；进入组详情使用组菜单。组置顶和手动组顺序由后端按用户持久化，刷新和其他设备读取相同状态。组内按最后活跃时间降序，拖动对话仅改变归属；对话置顶保留原组归属。搜索覆盖组名、成员标题和初始意图摘要，搜索中禁用拖动，整理范围仍以全部符合条件的自由对话为准。

自由对话、侧栏组内对话和组详情的归属操作共用二级菜单：顶部按组名搜索，列表最多显示十行并支持滚动；当前组标记且不可重复选择，点击其他组直接移动。底部保留移回自由对话（已归组时）及新建组并归入入口，只有新建组打开表单。

整理进行中点击入口打开进度抽屉，取消在抽屉中二次确认。待确认结果占用同一入口且阻止重复启动；失败可查看原因及重试。确认、撤回、取消后恢复整理入口，下一轮重新冻结当时的自由对话。空范围禁用启动。页面刷新、窗口重新聚焦和定期状态同步恢复服务端状态。

## 快照、锁与并发

启动时冻结当前用户全部非任务、非临时、未归档、未删除、未归组的主会话及开场输入。结果覆盖完整冻结名单；分组输入仅包含可用标题和初始意图摘要。ready 和有实质摘要的 provisional 均参与分组，不要求执行资料齐全。新增会话留待下次。置顶不排除整理，子会话不独立参与。

锁定范围与分析快照独立：开始整理时已有的全部自由主会话均纳入持久化锁，包括元数据未 ready 的会话；新建会话不锁定。分析到自动应用完成期间，锁定成员禁止删除、归档及手动改变对话组归属，包括批量和级联操作；批量请求包含被锁成员时整体拒绝。仍可查看和继续聊天。前端禁用对应操作，后端在同一用户事务中强制检查。使用持久化业务锁，不在 LLM 调用期间持有数据库行锁。取消和最终失败释放保护，后台恢复从已验证检查点继续。

应用前再次校验会话与正式组版本。已归档、删除、手动归组或正式组范围改变的建议不覆盖当前状态；结果说明跳过原因，并重新计算新组最小数量。自动应用要么事务成功，要么没有正式组和归属的部分写入。

撤回只恢复仍由本轮应用或本轮结果面板纠错控制的成员；不覆盖独立后续修改，不恢复删除或归档会话。只删除本轮自动创建、未被独立修改且已经为空的组，保留用户手动新建组。

## 算法约定

纯 LLM，不依赖 embedding。通过用户默认模型配置调用，禁止在生产代码中固定实验服务地址。正式组包含名称、收录范围和有限代表样本；有用户范围时优先遵循，为空时允许保守不匹配。算法不能改写正式组元数据。

界面显示“正在整理第 n/N 批”，不附加会话完成数量；最后一批结束后直接校验并应用。会话按每批最多 50 条串行处理，共享候选目录；完整保留本批标题和摘要，不按 token 估算限制输入，也不向模型传入输出 token 上限。小候选保留至结束，批次内合并后仅至少三条的候选可自动建组。范围变更和候选合并复核全部受影响的旧成员，不增加每组强制二次审查。

目录按每块最多 50 个组分块匹配和去重，不静默丢弃正式组；不再执行独立的全量最终两两复核；实际发生范围更新或候选合并时，受影响旧成员仍按每批最多 50 条检查。非法输出有限修复，仅模型服务实际返回输入或输出超限时缩小当前会话批次；失败响应不提交候选状态。模型调用复用公共设施，候选状态仍是独立业务模块，不引入统一承载全部规则的基类。

## 验收边界

正式验收在容器内完成。结构约束、并发保护、迁移兼容和用户界面流程需要自动化验证；真实模型语义质量独立报告，不能用结构校验代替准确性判断。

## 摘要准备与完整结果

按冻结范围、准备摘要、分批分组及候选合并、本地完整性校验、应用结果顺序执行。准备期间显示“正在准备会话摘要 n/N”；N 只统计需要补齐或等待复用任务的会话，成功、无任务、失败均推进 n，零准备项不显示 0/0。准备检查点带版本逐条持久化，全部终态后封存分析快照，刷新与重试不重复计数。

已关闭窗口的 done 摘要仅在原 evidence 未变化时复用；其他摘要必须 done 且匹配当前冻结输入 hash。无消息、确认仅问候的会话不进入模型；其余缺摘要会话复用开场提取和模型接口补齐。匹配冻结输入的现有任务复用；写回检查输入证据及元数据版本，不能覆盖后续消息的新版本。单条失败继续其他会话，取消后不派发新任务，迟到结果不能落入已终止的整理任务。

结果包含所有被冻结会话。unassigned_reason 区分 no_matching_group、below_min_group_size、no_messages、no_task_intent、summary_failed、unsupported_conversation；summary_failed 附带 summary_error_code。skip_reason 仅用于应用冲突。free_count 包含全部未归组会话，skipped_count 为应用冲突计数。手动归组后隐藏原未归组原因；未进入分析的冻结会话也可纠错与撤回。没有分析输入时直接生成完整结果并解锁。旧任务 preparation_json 为空时仍使用旧快照和结果语义。

## 流式执行与取消确认

每个分组步骤通过 Chat 的独立受控进程执行，复用现有模型配置、LazyLLM 流解析和 stream sink。Core 接收 NDJSON 状态及最终结构化结果，不传输或展示思考文本。记录等待/生成/校验状态、首个有效内容时间、最后有效内容时间、已接收字符数和耗时，前端沿用轮询读取持久化状态。

首个有效模型内容等待上限为 300 秒，生成中连续无有效内容上限为 120 秒；心跳不重置模型活动时间。底层网络读取 310 秒仅作为后备超时，不限制持续有内容的完整生成时间。Core 不再用 305 秒限制整个步骤，仅监测 Chat 通道连续 30 秒无事件。

传输异常不进入输出修复循环；只有 invalid_output 可修复。重试前必须收到上一执行的终态，或通过取消接口确认其进程已经退出。取消先进入 canceling 并保留本轮锁，确认后才能终结任务和解锁。取消无法确认时不创建下一次执行，后台继续确认；取消墓碑阻止迟到的启动请求。执行标识随流状态持久化，恢复同样先确认旧执行结束。

Chat 使用独立进程，是因为取消 asyncio.to_thread 不会停止阻塞中的模型 HTTP 请求。终止进程会关闭客户端模型连接；父进程退出也会终止子进程。这里只能确认本地执行停止，远端推理服务是否即时中止计算取决于其断连处理，不宣称已确认远端 GPU 停止。新逻辑仅适用于组织分组，摘要准备沿用已有机制。

## 业务场景粒度（v3.2）

分组以日常检索习惯和稳定业务场景为依据，不要求具体动作相同。“邮件处理”可包含读取、检索、总结和发送；“代码仓库维护”可包含克隆、拉取、更新及分支操作；PPT制作可跨主题。实际使用与开发、测试对应功能仍分开。候选更新与合并允许从动作范围调整为连贯场景，受影响成员检查采用相同标准。已有正式组的明确scope仍受保护，不自动重写已有归属。规则版本升级后的新整理使用新粒度，不能混用旧规则检查点。

空组详情返回 conversations: []，前端在接口适配层兼容旧版 null，详情页及侧栏共用该归一化结果。

协议 v2 不恢复 v1 的未完成检查点。旧已完成结果仍支持查看、纠正和撤销；旧未完成任务在升级恢复时结束，用户重新发起整理。

### 整理结果确认

成功状态 `succeeded` 表示结果已应用、待用户处理；新增 `confirmed` 终态表示确认保留。复用现有状态字段，无数据库结构迁移。最近一轮结果待处理时，新建返回该结果，重试被拒绝。确认和撤销均通过用户事务串行化；确认接口幂等，确认后不再允许整轮撤销。旧历史成功记录只以最新一轮已完成结果为准，避免确认后重新暴露旧结果。

前端原整理按钮显示查看整理结果，关闭面板不改变状态。确认保留及撤销均要求二次确认，处理后恢复整理入口；移除本地已查看标记与历史结果菜单。

## PR #701 修复：协议 v2（2026-09-09）

Chat 使用当前解释器启动独立 `organizer_worker` 模块，不加载 HTTP app 的后台生命周期。stdin 的首行传请求，其后保持父进程专有写端；worker 用原始 fd 监听 EOF，避免 daemon 线程持有 Python buffered-reader 锁而在正常退出时崩溃。Linux 额外设置并检查 parent-death signal。协议 stdout 与日志分离，接收线程持续排空输出；最终结果和 settled 都必须等进程确认退出。

stream/cancel 必须路由到同一个 Chat 进程；当前协议只支持单 Chat 进程、单副本。Core 为每次 execution 固定发起时间，Chat 接收窗口为 60 秒加最多 30 秒时钟余量，拒绝早于本实例启动时间的请求；取消墓碑保留至少五分钟，并仅清理非活跃 execution。远端 provider 是否停止推理仍取决于断连处理。

run 标记 protocol_version=2；snapshot-item 保存 ordinal、冻结输入（包含输入 hash/evidence/revision）、准备状态、原因和 assignment。run 的 preparation JSON 只保留计数，checkpoint 只保留 cursor、下一 ordinal、身份摘要、阶段及当前待审核提案。候选目录按 run 分表保存有界示例、数量、版本与 aliases。正式组快照固定，不能由算法修改。

每轮仅传当前最多 50 条会话和分组目录；输入身份绑定 snapshot hash、算法/提示词版本及模型配置。Core 校验提案后暂存，范围更新/合并的旧成员通过 ordinal 分页审核；全部通过后 assignment、候选变化、cursor 在同一 lease-fenced 事务提交。候选合并不重写历史 assignment；结束时汇总一次完整 proposal。目录扫描与重复范围审核仍可能随组数增长，不宣称整体严格线性。

整理活跃期间，同用户的新建组和组名修改被后端用户事务锁拒绝，覆盖普通创建与结果纠正创建。侧栏、详情页、归属菜单及新建表单同步禁用。收录范围修改及删除仍允许，由 apply 重新验证。SQLite 的 Start/Retry 使用 `asyncjob.EnqueueInTransaction`，避免在 BEGIN IMMEDIATE 内再次开启事务；独立入队仍使用原 Enqueue。

### 升级与降级

停止旧 Core 的任务领取及执行，并停止旧 Chat/worker，再成套启动新 Core/Chat。新 Core 在启动 runner 前执行 RecoverLegacyRuns，先确认持久化 execution 已 settled，再在事务中结束旧未完成 run/job 并释放锁；已完成结果不改变。不能只改数据库状态后宣称旧模型进程已经停止。旧 failed/canceled 任务不能重试旧协议，需重新整理。

新增 dev migration 同时支持 PostgreSQL/SQLite，现有 v0.3 aggregate 描述相同最终结构。降级前先停止新版本执行并结束未完成任务，再执行 down；已应用归属及历史纠正/撤销记录保留。旧 JSON 字段继续用于历史结果读取，不做 v1→v2 checkpoint 转换。
