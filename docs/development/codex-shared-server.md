# Codex Workflow 面板控制

## What's new

- **更完整的 Workflow 交互体验**：在可视化 Workflow Panel 中直接继续或停止 Codex 中的 Workflow 执行，让审核与执行控制集中在一处，操作更连贯。

## 整体架构

```text
Workflow Panel
      │ 用户操作
      ▼
LazyMind 控制模块 ──→ 共享 Codex 后台 ←── 桌面适配器 ←── Codex Desktop
```

**Desktop 和 LazyMind 连接同一个 Codex 后台。** LazyMind 将面板操作传给后台，控制对应会话的执行；桌面适配器负责连接后台，并通过工具桥接保留桌面工具和内置浏览器能力。

这条从 Workflow 面板到 Codex 执行后台的控制通道，让用户可以直接在面板中操作，同时保留原有桌面体验。

## 验证与适用版本

已完成以下验证：

- **启动与重连**：无后台启动、已有后台复用、真正退出 Desktop 后后台保留，以及从原图标重开并恢复原聊天连接。
- **桌面能力**：真实调用桌面工具，并通过内置浏览器打开页面、读取标题；退出重开后再次调用成功。
- **Workflow 控制**：Continue/Stop 协议回归通过；本机部署后，用户按约定流程测试并反馈正常。
- **工程检查**：TypeScript 检查、40 项 JS/运行组件测试、3 个相关 Go 包测试及隔离构建通过。

当前验证环境为 **macOS**，工程部署使用 **Codex Desktop `26.1007.71326`**、内置 **CLI `0.162.0-alpha.17.2`**。早期桌面实验版本为 `26.1007.30912（20156）`。当前准备程序限定上述 CLI 版本，其他版本需重新验证。

使用时需注意：macOS 已在代码中接入现有“连接/断开 Codex”流程，首次启用后需重开 Codex；Windows 已补平台实现，仍需实机验收；旧 Workflow 绑定不自动迁移，应新建 Workflow 使用原生中断。桌面工具需要 Desktop 在线，重开后浏览器脚本中的内存变量不会保留；停止执行轮次不保证终止所有已启动的外部命令。异常恢复、长期运行和真实多客户端并发尚未专项验证。

### 多平台工程进展

共享的安装、协议转发和 Workflow 控制逻辑已与系统操作分离。启动协调迁入 LazyMind Go CLI，移除 Python 依赖。macOS 保留原有 Unix socket 和 GUI 启动配置；Windows 增加用户级启动配置、原生入口、独立后台、文件 ACL 和本机令牌认证通信。

Windows 尚未完成真实 Desktop 验收，不能将交叉编译通过视为桌面工具、浏览器或退出保活已验证。首次 Windows 验收按一次正常连接、使用、退出重开和断开恢复流程执行。

本轮工程验证：类型检查和运行包构建通过；49 项 JS/TS 测试、4 个 Go 包测试通过；Windows x64、ARM64 交叉编译通过。测试使用隔离目录与模拟服务，未切换真实 Desktop 的启动配置。
