# 产品 PR #3、#4：研发接入决定与待讨论问题

更新日期：2026-09-22。

2026-09-22 实施补充：根据孙奇后续反馈，已做大纲工具内有限纠正、发布保护、KB 代理入口适配与素材提示词调整。本文保留原讨论记录，最新代码范围及验证结果见 [反馈修改说明](ppt-feedback-implementation-20260922.md)。三套风格 UI 等仍未实现。

本文针对产品编写的 [PR #3](https://github.com/CarlosShaoting/LazyRAG/pull/3) 和 [PR #4](https://github.com/CarlosShaoting/LazyRAG/pull/4)，说明研发准备吸收哪些能力、仍有什么疑问、哪些不采用。所有实现由当前分支的研发完成，不涉及工作分配。

当前代码基准：`cst/user_workflow_ui`，提交 `65abcf12`。参考代码为 PR #3 的 `25e7af80`、PR #4 的 `ea3601f1`。本文是接入方案，所列新增能力尚未实施。

## 一、两个产品 PR 分别提供什么

| 产品 PR | 实际能力 |
| --- | --- |
| #3 | 给大纲发布工具配置终止行为，工具成功后结束当前 Agent 循环，避免继续读取产物或调用模型收尾 |
| #4 | 样式、大纲通过指定工具提交结构化结果，并校验和有限重试；增加三套风格预览及选择步骤；复用样式、预览和关联 deck；增加逐页生成与发布完成凭据；调整素材搜索和结束策略；兼容 KB 参数格式；扩展旧 HTML 锚点与多目标 AI 编辑 |

以上是产品 PR 的能力范围，不表示全部加入当前 PR。下面是统一后的取舍。

## 二、要做什么

### 1. 发布成功后结束，但保留可读的阶段总结

吸收 PR #3 减少无效收尾的思路。大纲生成或插入发布成功后，不再为了重复读取、简单总结而继续调用一轮模型。

阶段结束必须同时有可读总结和正常完成事件。例如“已生成 3 页大纲，可在大纲页查看”，数量和内容取自实际结果；插页则说明实际插入结果，不能套用整套生成文案。

本地已有 `done` 事件及 `summary` 字段，停止 Agent 循环不会天然丢失结束事件。需要补的是返回内容的展示质量：不能直接把工具 JSON、内部路径或产物字段名当成总结给用户。

采用方式：基于已保存产物生成或复用简短总结，再通过现有事件链路展示。只在业务成功且必需产物完整时提示成功，部分成功或发布失败不能显示“全部完成”。不为一句完成通知额外等待模型。

### 2. 增加三套风格预览与选择步骤

吸收 PR #4 的 `style_flow`、`choose_style` 及候选预览能力，保留现有 ask 的风格方向选择。

ask 中增加生成方式：

- **直接生成一套**：按已确认的风格方向确定一套样式，不展示三套候选，也不额外要求用户确认。
- **先看三套方案**：进入风格选择步骤，展示 A/B/C 三套预览，用户确认后继续。

步骤位置固定在**素材收集之后、底图提示词之前**：

```text
需求分析 → 素材收集 → 风格选择 / 确定样式
                     ↓
                  锁定样式
                     ↓
         底图提示词 → 底图（未启用时跳过）
                     ↓
            大纲 → 每页提示词 → 幻灯片
```

风格选择是否展示由生成方式决定，不能受底图开关影响。不开底图，也可以先看三套风格。

预览不是纯文字：PR 通过 `html-slide` 展示 HTML 对比页，其中包含 SVG 绘制的幻灯片示意、名称、推荐理由和配色色块。它是样式示意，不是提前生成三套最终 PPT。

产品 PR 原实现通过文本字段填写 A/B/C；本轮明确改为 **composite 三页翻页预览**：A、B、C 分别占一页，每页展示对应方案的视觉示意、名称和必要说明，用户通过翻页比较。

预览底部放置 **“确认使用”** 按钮，点击后选择并锁定当前展示页对应的方案，再继续后续流程。不再要求手动填写 A/B/C，也不采用三卡片或单选按钮方案。翻页只改变浏览位置，不代表确认；即使默认显示 A，也必须点击“确认使用”才锁定。方案未加载完成或不可用时不能确认。

### 3. 风格确定后锁定，后续全部按这一套执行

风格选择确认后，将所选候选的完整样式保存为 deck 的唯一有效样式。直接生成模式也必须先确定并保存一套样式，才能进入后续步骤。

底图提示词、底图、大纲、每页提示词、幻灯片生成，都使用这一套已经锁定的风格。后续模型不能重新选择全局风格，也不能每页自己换配色、字体或视觉语言。页面布局可以根据内容变化，但必须在该风格内。

大纲继续保留本地的内容优先和规范化处理：读取已锁定的样式，不重新做全局视觉设计，也不为传递风格而输出冗长的视觉规则。

样式锁定与是否生成底图无关。不开底图只跳过底图阶段，不跳过样式确定。三套模式中的默认 A 不代表用户已经确认，不能自动推进下游。

局部修改、插页和失败重试继续使用锁定样式。只有用户明确要求更换风格时，才回到风格确定环节更新，并使受影响的下游结果和缓存失效。普通内容修改不能自动解锁风格。

### 4. 复用候选预览和已选样式

吸收 PR #4 与三套预览配套的恢复能力，接入本地已有的 deck 绑定与样式复用。

已经生成的 A/B/C 候选，在刷新、步骤恢复或输入未变化的重试中应继续使用，不重新生成三套。已经确认的样式，也不能在继续执行或页面失败重试时重新设计。

候选预览、选择结果和最终锁定样式应归属于同一 deck，避免生成出另一套 deck 或两份互相不一致的样式。明确更换风格时才更新相关候选和锁定结果。

### 5. 素材搜索和页面 prompt：每页一张素材图片

在产品 PR #4 的素材收集能力基础上，按研发要求收敛图片数量，不沿用面向整套 PPT 的泛化图片数量上限。

**素材搜索目标按页数分配：N 页 PPT 对应 N 个素材图片位置，每页选择一张。** 搜索结果可以包含候选，但最终为每页选定并传递的素材图片只保留一张，不能把多张候选都交给页面模型自由组合。

后续大纲、每页提示词和页面生成使用同一份页面与素材的对应关系。页面 prompt 明确约束：

> 本页只使用指定的一张素材图片，不新增其他素材图，不重复放置该图片，不将多张图片拼成图片组或图库。文字和排版围绕这一张图片组织。

这里的一张指**内容素材图片**，与单独的 AI 底图配置分开处理：启用底图时，底图仍作为既有背景层使用，不额外授权模型再插入多张素材图。若产品期望“连底图在内全页只能有一张图片”，需要明确改为另一条规则，不能将两种口径混在一起。

如果搜索没有可用图片，不能编造 URL，也不能为了凑数无限搜索。倾向保留 PR 的非阻塞缺图处理，将缺口记录下来继续生成；因此“一页一张”是正常配置目标和每页上限，缺图降级场景不强行塞入无效图片。具体降级口径列入待讨论问题。

这项调整只涉及图片数量、页面分配及 prompt 约束，不代表将 PR #4 的全部 KB/Web 搜索策略一并引入。

## 三、还有什么疑问

### 1. KB 调用是否在后续重构中发生回归？

研发反馈：此前测试 KB 调用没有问题。产品 PR #4 增加 `kb_ids` JSON 字符串适配，但目前不能仅凭该改动认定本地已有同样问题，也不能直接排除它的必要性。后续重构引入回归是待验证的可能原因，不是已确认结论。

**当前状态：KB 部分待测试。** 需要用此前可成功的调用场景核查当前链路，区分工具发现与注册、模型实际传参、参数校验/适配、权限与配置、实际检索返回，确认问题是否存在以及发生在哪一层。若出现 `kb_ids` 为字符串的情况，再检查是否正是产品 PR 的适配所解决的问题。

若当前调用正常，保留现有实现，不为参考 PR 中存在适配代码而重复改造；若确认回归，定位相关重构并修复，再决定采用 PR 的参数适配还是修正其他环节。此前测试正常只能作为对比依据，不能替代当前验证。本次只更新文档，未新增 KB 测试结果。

### 2. 页面完成凭据解决的额外问题是否确实需要？

本地已经处理发布失败、失败页阻挡发布游标、成功页复用和 deck 续跑，不能把这些重复算成 #4 的新增收益。

#4 真正增加的是 `execution_state.json`：为每页记录生成成功、发布成功以及 HTML 哈希，最后逐页核验。

它要防的情况是：HTML 文件已生成，但登记为工作流页面产物失败，用户只能拿到部分页面。这里的发布指向工作流产物系统保存，不是对外发布，也不能证明浏览器已经成功渲染。

疑问在于：现有发布结果和有效产物信息是否已足够识别漏发？是否还有必须靠持久凭据解决的跨进程恢复或审计场景？本轮没有复现当前分支普遍存在“假完成”，因此不直接引入一套新状态文件。

研发倾向先利用现有有效产物核验是否漏发；已有有效 HTML 时只补发布，不重新生成。完整凭据会涉及旧 deck、人工编辑后哈希变化、插入删除和重排的兼容，只有明确缺口后才值得加入。

**当前决定：完整凭据系统不纳入；最小发布核验保留为待讨论建议，不视为已经决定实施。**

### 3. 没有可用素材时，一页一张是否允许降级？

每页只传一张并在 prompt 限制一张的方向已经确定。需要明确的是搜索为空、图片失效或没有符合要求的素材时怎么办。

研发建议不要因此阻塞整套生成：保留缺图信息，使用文字和已有布局完成页面，不伪造图片，不无限重搜。若该页用户明确要求指定图片，则应准确报告缺少素材。正常情况下按页选一张；异常情况下允许零张的规则，需与产品对齐。

## 四、不同意在本轮做什么，以及继续用什么

### 1. 不整体切换大纲的结构化工具提交与三次纠正

本地已有大纲 JSON 容错、字段整理和规范化。#4 增加指定工具 schema 提交与最多三次纠正，有更强约束，但也增加模型通道兼容要求与等待。

本轮没有明确案例证明必须替换当前生成协议。因此继续使用本地大纲实现；后续有具体输出缺口，补对应校验和修复，不整套换掉。风格锁定后大纲读取该风格，不等于采用 #4 的全部大纲生成路径。

### 2. 不重建 deck 失败恢复体系

本地已有 deck 绑定、输入指纹、成功页复用和按页重试。#4 的完成凭据不能替代这些能力，也不能因接入产品代码而退回整套重做。

继续保留本地恢复；新增的候选预览恢复与样式锁定只在现有基础上补充。缺失发布时优先补发布，不重新生成已有效的 HTML，不回退大纲。

### 3. 不直接加入完整的逐页持久凭据系统

不原样加入 `execution_state.json` 作为所有页面完成的强制前提，原因及可能的较小替代方案见第三节。不能让旧 deck 或合法的人工修改仅因没有新凭据而被判失败。

### 4. 不未经验证引入 KB 适配，也不整体替换素材检索策略

#4 的 `kb_ids` JSON 字符串适配先作为候选修复保留，是否采用取决于待完成的 KB 测试。研发此前测试调用正常，需核查后续重构是否产生回归；不预先认定必须加入，也不将 KB 问题排除在后续调查之外。保留现有 KB/Web 配置限制，不因没有配置仍尝试调用。

素材方面本轮明确修改的是每页一张的搜索分配和 prompt 约束；PR 中其他检索规则不作为整包能力默认引入。KB 按第三节先测试、定位，再决定修复；其他搜索策略仍不作为整包能力默认引入。

### 5. 不新增多目标 AI 编辑和另一套旧 HTML 锚点体系

产品 PR 包含多目标 selection 与旧 HTML 锚点扩展，但没有完整配套的前端多选交互。本轮不增加这部分范围。

保留本地短句匹配失败交给模型判断、受限插入、重排后仍可编辑的修复。尤其不能恢复对方版本中仍保留的原始页号一致性限制，导致重排后的页面再次无法修改。

### 6. 不改回现有图片、缩略图和导出优化

两个产品 PR 不提供替代本地方案的完整能力。继续使用 URL 主预览、截图与导出时准备内联图片、持久缩略图缓存。三套样式预览需要正确显示其 HTML/SVG 资源，但不借此重做整套图片和导出链路。
