# 论文阅读与技术攻略写作产品设计

## 1. 背景与目标

LazyMind 已具备知识库、PDF 解析、混合检索、引用问答、PDF 选区对话、学术论文搜索、Artifact 和 AI Writer 等基础能力。本方案不建设完整的“学习平台”，而是聚焦两个高频场景：

1. 用户将论文收录进一个知识库，对论文进行翻译、解释、追问和扩展阅读。
2. 用户围绕一个技术点阅读多篇论文，摘取其中有用的内容，组织成一篇有可靠引用的完整技术攻略。

第一阶段需要形成以下最小闭环：

```text
收录论文
  → 翻译、解释和多轮问答
  → 保存生词或论文证据
  → 搜索并导入相关论文
  → 对比、综合多篇论文
  → 建立攻略大纲
  → 按章节引用证据写作
  → 编辑、核验引用并导出
```

本方案明确不包含阅读进度、学习计划、引用链图谱、知识掌握度、自动出题和复杂知识图谱。

## 2. 核心产品原则

### 2.1 一个知识库就是一个论文资料范围

用户继续使用现有知识库收录和管理论文，不新增“课程”“学习项目”等容器。用户可以在知识库中阅读单篇论文，也可以选择若干论文进行对比、综述或攻略写作。

### 2.2 检索词表和学习生词本完全分离

现有 Word Group / Glossary 用于解决向量召回中的同义词、别名和专有名词问题，属于检索基础设施。

新增“生词本”用于用户后续背单词，属于个人学习数据。二者不能共用数据表、接口或自动同步：

| 对象 | 用途 | 主要内容 | 是否影响检索 |
|---|---|---|---|
| 检索词表 | 提升召回和术语归一 | 专有名词、同义词、别名、领域释义 | 是 |
| 生词本 | 学习和背单词 | 单词、语境释义、例句、例句翻译、论文来源 | 否 |

未来如果用户明确希望将某个专业词加入检索词表，必须通过独立操作完成，不能因为加入生词本而自动改变知识库检索行为。

### 2.3 技术攻略必须以证据为中间层

不能直接让 Agent 检索知识库后一次性生成长文。用户需要能看到和管理“文稿为什么这样写”。在论文和最终文稿之间增加一个轻量的“证据摘录”对象：

```text
论文原文 → 证据摘录 → 攻略章节 → 最终表述
```

证据摘录既可以由用户选区保存，也可以由 Agent 根据写作目标推荐。最终文稿中的关键事实、数据、方法描述和论文观点都应指向一个或多个证据摘录。

### 2.4 复用 AI Writer，不新增第二套文档编辑器

技术攻略写作复用现有 AI Writer 的大纲、分章节草稿、编辑、版本和导出能力。新增内容主要是：

- 论文范围选择；
- 证据摘录管理；
- 大纲章节与证据绑定；
- 写作时的来源约束；
- 引用核验和原文回跳。

## 3. 用户场景

### 3.1 阅读单篇论文

用户打开知识库中的一篇论文，选中一段内容，可以：

- 翻译选区；
- 提取生词并加入生词本；
- 解释段落、术语、公式、图表或实验结果；
- 围绕当前选区继续多轮追问；
- 将当前内容保存为证据摘录。

### 3.2 扩展相关论文

用户可以从当前论文、当前选区或一个自然语言问题出发搜索相关论文。系统展示相关原因和可获得的内容范围，用户确认后将论文加入当前知识库。

### 3.3 对比或综述多篇论文

用户在知识库中选择多篇论文，生成结构化对比或主题综述。所有关键结论都需要保留原文引用；原文没有提供的信息不得由模型补齐。

### 3.4 写一篇技术攻略

用户输入技术主题和目标读者，选择论文范围。系统帮助用户：

1. 理解写作目标并生成研究问题。
2. 从论文中提取可用证据。
3. 按主题组织证据并识别材料缺口。
4. 生成并修改攻略大纲。
5. 为每个章节绑定相关证据。
6. 按章节生成草稿。
7. 在编辑过程中补充、替换或删除引用。
8. 检查关键论断是否有证据支持。
9. 导出完整技术文档。

## 4. 功能需求

## 4.1 论文收录与范围选择

### 复用现有能力

- 知识库创建和权限；
- PDF 上传、解析、OCR 和向量化；
- 文档列表和全文检索；
- KB Citation、父节点和上下文扩展；
- PDF 文件预览。

### 需要补充

1. 为论文维护轻量元数据：
   - 标题；
   - 作者；
   - 摘要；
   - 年份；
   - DOI；
   - arXiv ID；
   - 来源 URL；
   - 全文可用状态。
2. 导入和上传时按 DOI、arXiv ID、标题等进行重复提示。
3. 对话和写作时支持三种资料范围：
   - 当前论文；
   - 用户选择的多篇论文；
   - 整个知识库。
4. 检索接口贯通 `document_ids` 过滤，保证 Agent 不越出用户指定范围。

论文元数据不是独立的文献管理系统，不维护前向或后向引用关系。

## 4.2 PDF 选区阅读

### 复用现有能力

现有 PDF Viewer 已能返回选区文字、页码和 bbox；PDF Temporary Chat 已能携带知识库、文档、页码、bbox 和 segment 信息发起对话。

### 需要补充

PDF 选区浮动菜单增加五个操作：

1. `翻译`
2. `解释`
3. `加入生词本`
4. `深入提问`
5. `保存为证据`

其中翻译、解释和深入提问继续使用现有 PDF Chat，仅使用预设提示词约束输出；不新增翻译或解释后端。

翻译的默认输出：

- 原文；
- 中文译文；
- 需要保留的专业术语；
- 必要的歧义说明。

解释的默认输出：

- 这段内容在说什么；
- 它在当前章节或论文中的作用；
- 涉及的核心概念；
- 更容易理解的表述；
- 原文依据。

## 4.3 学习生词本

### 新增领域对象

新增独立的 `VocabularyBook` / `VocabularyEntry`，不能复用 Word Group。

最小数据结构：

```json
{
  "id": "vocab_xxx",
  "user_id": "user_xxx",
  "term": "grounded",
  "phonetic": "optional",
  "part_of_speech": "optional",
  "meaning": "当前上下文中的中文释义",
  "example": "The answer must be grounded in retrieved evidence.",
  "example_translation": "回答必须以检索到的证据为依据。",
  "source": {
    "dataset_id": "ds_xxx",
    "document_id": "doc_xxx",
    "document_title": "...",
    "page": 4,
    "segment_id": "seg_xxx",
    "bbox": [0, 0, 0, 0]
  },
  "created_at": "..."
}
```

### 最小功能

- 从选区提取单词和短语候选；
- 展示语境释义、原文例句和例句翻译；
- 用户勾选后批量加入生词本；
- 手动新增、编辑和删除；
- 按关键词和来源论文筛选；
- 点击来源回到论文位置；
- 去重时允许同一个单词保留多个不同语境例句。

### 暂不实现

- 熟练度；
- 复习计划；
- 间隔重复算法；
- 自动测试；
- 单词发音和口语评分；
- 生词向检索词表的自动同步。

第一阶段的生词本只负责正确地收集学习材料，为后续“背单词”能力提供数据基础。

## 4.4 多轮论文问答

### 复用现有能力

- PDF Temporary Chat；
- 会话保存与恢复；
- KB 检索和引用；
- 上下文扩展；
- 多文档检索。

### 需要补充

- 在对话顶部明确显示当前资料范围；
- 支持从当前论文切换到选中的多篇论文；
- 后续追问继承当前论文、选区和资料范围；
- 回答区分“论文原文”“跨材料综合”和“模型解释”；
- 点击引用回到原论文的页码或片段；
- 对当前资料无法回答的问题明确提示证据不足。

## 4.5 相关论文搜索与导入

### 复用现有能力

- `paper-search`：arXiv 搜索和读取；
- `sciverse-paper-search`：论文元数据、证据搜索和内容读取；
- 知识库文档上传和解析任务。

### 需要补充

增加从以下入口启动相关论文搜索：

- 当前论文；
- 当前选区；
- 当前问题；
- 用户输入的技术主题。

搜索结果卡片展示：

- 标题、作者、年份和来源；
- 摘要；
- 与当前主题的相关原因；
- DOI、arXiv ID 或原始链接；
- 内容状态：开放全文、仅摘要、需要用户上传。

用户选择结果后：

- 开放全文可直接导入当前知识库；
- 只有摘要时只保存元数据和摘要，并明确标识；
- 无法合法获取全文时提示用户上传 PDF；
- 导入后触发现有解析任务；
- 解析完成后可继续参与问答和写作。

系统不维护引用链，只将参考文献标题、作者、DOI 等作为可能的检索线索。

## 4.6 多篇论文对比与综述

新增两个内置 Skill，复用现有 KB 检索和 Artifact 输出。

### 多论文对比 Skill

输入：

- 论文范围；
- 用户指定的比较问题；
- 可选比较维度。

默认维度：

- 研究问题；
- 核心方法；
- 数据和实验设置；
- 主要结果；
- 优势；
- 局限。

约束：

- 每个事实性单元格绑定来源；
- 未在论文中找到的信息写“未说明”；
- 推断必须显式标识；
- 不允许用摘要证据冒充全文证据。

### 文献综述 Skill

输入：

- 论文范围；
- 综述主题；
- 目标读者和深度。

默认输出：

- 主题与范围；
- 核心研究问题；
- 方法分类；
- 代表性工作；
- 不同路线的差异；
- 主要发现；
- 局限和开放问题；
- 论文列表。

输出为 Markdown Artifact，并保留行内引用。

## 4.7 论文证据摘录

### 新增领域对象

新增轻量的 `EvidenceExcerpt`，用于连接论文阅读和攻略写作。

```json
{
  "id": "evidence_xxx",
  "user_id": "user_xxx",
  "dataset_id": "ds_xxx",
  "document_id": "doc_xxx",
  "document_title": "...",
  "source_locator": {
    "page": 4,
    "segment_id": "seg_xxx",
    "bbox": [0, 0, 0, 0]
  },
  "quote": "论文原文",
  "translation": "可选译文",
  "note": "用户或 Agent 对这条证据的说明",
  "topic_tags": ["RAG", "reranking"],
  "evidence_type": "definition | method | result | limitation | claim | example",
  "created_by": "user | agent",
  "created_at": "..."
}
```

### 创建方式

1. 用户在 PDF 中选区后点击“保存为证据”。
2. 用户在问答引用卡片上点击“保存为证据”。
3. Agent 根据攻略主题批量推荐证据，用户确认后保存。

### 基本操作

- 编辑说明和标签；
- 按论文、主题和类型筛选；
- 回到原文；
- 加入大纲章节；
- 从章节中移除，但不删除原始证据；
- 显示证据来自全文、摘要还是其他来源。

证据摘录不是知识库切片的复制品。知识库切片服务于检索，可能随重新解析变化；证据摘录服务于写作，应保存当时使用的原文快照和定位信息。

## 4.8 技术攻略写作

### 入口

在知识库文档列表增加：

- `写技术攻略`

用户可以先勾选论文，也可以进入后再选择整个知识库或部分论文。

### 创建配置

最少输入：

- 攻略主题；
- 目标读者，例如初学者、工程师或研究人员；
- 期望解决的问题；
- 论文范围。

可选输入：

- 写作风格；
- 期望长度；
- 用户已有的大纲或草稿；
- 是否需要代码示例。

### 写作流程

#### 第一步：材料分析

Agent 根据主题分析所选论文，输出：

- 核心概念；
- 可能的内容结构；
- 可用证据概览；
- 材料缺口和建议继续搜索的内容。

用户可以继续导入论文，也可以直接进入大纲。

#### 第二步：生成大纲

大纲节点至少包含：

```json
{
  "node_id": "section_xxx",
  "title": "重排序为什么有效",
  "purpose": "解释重排序在 RAG 中解决的问题",
  "key_questions": ["召回和精排有什么区别？"],
  "evidence_ids": ["evidence_1", "evidence_2"]
}
```

用户可以：

- 增删和调整章节；
- 拖动证据到不同章节；
- 让 Agent 为某个章节补充证据；
- 查看哪些章节证据不足。

#### 第三步：分章节写作

每个章节只使用以下输入：

- 攻略总体目标；
- 当前章节目的；
- 当前章节绑定的证据；
- 必要的相邻章节摘要；
- 用户编辑过的已有内容。

生成规则：

- 关键事实、数据、论文观点和方法描述必须带引用；
- 可进行综合和解释，但要区分原文事实与作者解释；
- 不得编造论文未提供的数据；
- 证据不足时保留 TODO 或请求继续检索；
- 不按论文逐篇罗列，而是围绕技术问题组织内容；
- 同一证据可被多个章节使用，但应避免重复大段引用。

#### 第四步：编辑与补证据

在现有 AI Writer 编辑器中增加：

- 右侧“论文证据”面板；
- 从证据面板插入引用；
- 选中文稿中的句子查找支持证据；
- 查看某条引用的原文；
- 替换或删除引用；
- 选中段落让 Agent 基于指定证据改写。

#### 第五步：引用核验

在导出前运行轻量检查：

- 事实性论断是否存在引用；
- 引用内容是否支持当前表述；
- 是否将摘要证据表述成全文结论；
- 是否存在引用失效或原文无法定位；
- 是否存在同一来源过度重复；
- 参考论文信息是否完整。

检查结果分为：

- 必须修复：引用不存在、来源无法访问、明显不支持；
- 建议检查：证据较弱、表述范围可能过大；
- 信息提示：可以补充更多来源。

第一阶段只提供检查和一键定位，不阻止用户导出。

#### 第六步：导出

复用 AI Writer 的文稿产物和版本能力，至少支持：

- Markdown；
- 带参考论文列表的完整文稿；
- 后续可沿用现有能力导出或写回其他文档系统。

## 5. 页面和交互设计

## 5.1 知识库文档列表

保留现有页面，增加：

- 论文元数据展示；
- 文档多选；
- `对比分析`；
- `生成综述`；
- `写技术攻略`；
- `搜索相关论文`。

普通文档仍可使用知识库原有能力，论文专属操作只在能够识别为论文或用户主动选择时展示。

## 5.2 PDF 阅读页

保持现有 PDF + Temporary Chat 布局。

选区后的浮动操作：

```text
翻译 | 解释 | 生词 | 提问 | 保存为证据
```

右侧面板提供三个标签：

- 对话；
- 本文证据；
- 本文生词。

第一阶段也可以只保留对话面板，将证据和生词以抽屉展示，避免大幅重构界面。

## 5.3 AI Writer

复用现有工作区，在资料或素材区域增加两类可选择输入：

- 知识库论文；
- 论文证据摘录。

写技术攻略时默认使用适配后的写作流程：

```text
材料分析 → 证据整理 → 大纲 → 分章节草稿 → 引用核验 → 成稿
```

它可以实现为一个内置 Workflow，因为包含多个可人工修改和继续执行的阶段；多论文对比和一次性综述继续使用 Skill 即可。

## 5.4 生词本

新增独立页面，建议放在个人知识或记忆相关入口下，但产品名称必须明确为“生词本”，不能与“术语表”混在一起。

第一阶段页面只包含：

- 生词列表；
- 单词、语境释义和例句；
- 来源论文；
- 搜索和来源筛选；
- 编辑、删除和回到原文。

## 9. Skill 和 Workflow 工作项

### 新增 Built-in Skills

1. `paper-comparison`
   - 对用户选择的论文按结构化维度比较；
   - 所有事实保留来源；
   - 缺失信息不推测。
2. `literature-review`
   - 按主题组织多篇论文；
   - 输出方法分类、代表性工作、主要发现、局限和开放问题；
   - 区分全文证据和摘要证据。
3. `paper-evidence-collection`
   - 根据技术攻略主题从论文中推荐候选证据；
   - 将结果按概念、方法、结果、限制和示例分类；
   - 用户确认后才写入 Evidence。

### 新增 Built-in Workflow

`technical-guide-writing`：

```text
输入主题与论文范围
  → 分析材料
  → 整理候选证据
  → 用户确认或补充材料
  → 生成大纲
  → 用户编辑大纲和证据绑定
  → 分章节生成草稿
  → 用户编辑
  → 引用核验
  → 生成成稿
```

需要复用现有 AI Writer Artifact slot，避免重复实现大纲和草稿文档模型。

## 10. 分期实施

## P0：论文阅读闭环

目标：能够在知识库中顺畅精读论文。

- PDF 选区翻译、解释和深入提问；
- 新增独立生词本；
- 生词候选提取和保存例句；
- 保存论文证据；
- 当前论文和多篇论文范围选择；
- 引用回到原文；
- 相关论文搜索结果展示。

### P0 验收

用户上传一篇英文论文后，可以选中一段内容完成翻译、解释、保存生词和保存证据；保存内容都能回到原论文；后续追问持续限定在当前论文范围。

## P1：相关论文与多篇分析

目标：从单篇阅读扩展到一个技术主题。

- 论文轻量元数据；
- 相关论文一键导入知识库；
- 多论文对比 Skill；
- 文献综述 Skill；
- Evidence 列表和筛选；
- 全文和摘要来源状态区分。

### P1 验收

用户能从当前论文找到相关论文并加入知识库，选择至少三篇论文生成带原文引用的对比表和主题综述；缺失信息不会被模型自行补齐。

## P2：技术攻略写作

目标：从论文资料生成可编辑、可核验的完整技术文档。

- AI Writer 接收论文和 Evidence；
- 技术攻略 Workflow；
- 材料分析和证据整理；
- 大纲章节绑定证据；
- 按章节写作；
- 文稿证据侧栏；
- 引用核验；
- 带参考论文列表的导出。

### P2 验收

用户选择一个知识库中的多篇论文，输入技术主题后，可以完成材料分析、证据确认、大纲修改、分章节写作和引用核验，最终得到一篇可编辑、关键论断可回到原文的技术攻略。

## 11. 明确不做

- 不建设阅读进度和阅读计划；
- 不维护前向或后向引用链；
- 不建设论文关系图谱；
- 不把学习生词写入检索词表；
- 不做背单词算法和自动复习提醒；
- 不做完整的 Zotero 类文献管理；
- 不自动下载无合法访问权限的论文全文；
- 不要求用户先创建新的学习项目；
- 不新建一套与 AI Writer 重复的编辑器；
- 不要求所有普通聊天都进入长流程 Workflow。

## 12. 关键质量指标

### 阅读

- PDF 选区成功进入翻译、解释和问答的比例；
- 生词例句及来源保存完整率；
- 引用回跳成功率；
- 限定论文范围后的越界引用率。

### 多论文分析

- 对比表事实单元的引用覆盖率；
- 综述关键结论的引用覆盖率；
- 摘要被错误表述为全文证据的比例；
- 用户发现虚构论文信息或虚构结论的比例。

### 技术攻略

- 关键事实性论断的证据覆盖率；
- 引用与表述的一致率；
- 引用原文可定位率；
- 用户接受、修改和删除 Agent 推荐证据的比例；
- 用户从大纲进入最终成稿的完成率。

## 13. 最终建议

本需求不需要新增一级“学习”模块。最合理的产品组合是：

```text
Knowledge：论文收录、阅读、检索和来源定位
Vocabulary Book：独立的个人生词学习数据
Evidence：连接阅读和写作的论文证据摘录
Chat / Skill：翻译、解释、问答、对比和综述
AI Writer / Workflow：把多篇论文和证据组织成技术攻略
```

产品建设的重点不是再增加一个通用聊天入口，而是打通两条缺失的链路：

1. `论文选区 → 生词 + 原文例句 → 独立生词本`
2. `论文原文 → 可管理证据 → 大纲章节 → 有引用的技术攻略`

这两条链路完成后，LazyMind 既能支持简单的论文精读，也能支持用户将多篇论文真正转化为高质量的技术写作成果。
