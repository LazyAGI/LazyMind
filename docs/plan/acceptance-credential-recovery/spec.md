# Local / Desktop 验收模型凭据恢复

## 背景与已批准方向

用户报告桌面定时任务失败。两次执行相隔约 32 秒；独立重跑同样立即失败。请求返回 HTTP 500 / 2001405，模型运行配置解密失败。只读核对发现当前验收数据库的一条模型凭据使用 Local 默认密钥，桌面 profile 的设备派生密钥无法读取；此前把同一验收数据库在两种模式之间切换时没有同步密钥。

用户在获知“统一这套验收数据的加密配置，并先审查恢复测试”的方案后回复“修复”。随后用户回复“确认”，批准本批 25 项测试并进入实现和实际恢复。实现及三次跨模式执行已完成，详见 `delivery.md`。

## 范围和设计

- 只恢复 `LazyMind-Notification-Acceptance` 这套明确指定的验收数据，并使该仓库 Local 配置采用同一桌面派生密钥。
- 复用 Core 的 `common/secretcrypto` AES-GCM 编解码和既有 SQLite 驱动，不引入依赖、不自行实现密码算法。目标密钥沿用 Electron 设备身份及 model-provider 用途的 HMAC 派生约定。
- 实现独立的离线维护命令，不挂入启动流程或业务 API，不自动尝试其他密钥，不回退到明文或默认弱密钥。源密钥通过进程环境/内存提供，不放命令行，不输出密钥或提供商凭据。
- 默认只检查，显式 apply 才写入。必须验证路径、设备身份、所有模型密文、Local 配置及服务已停止；拒绝未知状态、活跃进程和符号链接等不安全目标。
- 对指定数据库全部模型连接预检，包含可恢复的软删除连接；源密钥密文重新加密，目标密钥密文保持原字节，无密钥连接保持原样。遇到未知/损坏密文整批拒绝。
- 写入前保留 SQLite 一致性备份（包括 WAL 中已提交数据）、原 Local 配置和原设备身份，限制为当前用户访问。数据库更新使用事务；失败保留原行与原配置。跨数据库/配置文件的恢复次序必须可重复执行，不能把两者描述成单个原子事务。
- Local 的被 Git 忽略的 `local/config.env` 仅更新模型加密键，设为 0600，保留其他配置；不得把实际密钥写入提交的源码、测试、报告或日志。保留桌面设备身份，不修改模型选择、任务、通知规则及其他业务数据。

## 部署边界

维护命令限定本机 Local/Desktop 文件 SQLite，不支持 PostgreSQL/Compose，不修改 SQL migration、数据库结构、服务端 API 或产品默认加密配置。PostgreSQL 的正常模型加密路径维持既有实现，不以本次 SQLite 恢复测试宣称 PostgreSQL 部署验收通过。

## 完成标准

恢复与拒绝路径测试通过；真实恢复前检查零活动任务并停止对应服务、创建受保护备份；恢复后桌面单次任务成功；再验证 Local 使用同一密钥能读取配置和执行任务，并切回桌面。真实通知投递状态单独记录，不把服务 ready 或页面正常当作任务执行成功。

## 不做项

不修复旧默认数据目录的迁移问题、不清库、不重新输入/更换提供商 API Key、不修改通用认证策略、不提交或推送。其他 MCP/OAuth 凭据没有证据显示本次需要迁移，不顺带修改。
