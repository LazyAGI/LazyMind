# 解绑记录与账号标识补充

状态：用户明确要求直接生产、最后测试。按保留历史的推荐方案实施，不执行物理删除，不再重复请求阶段审批。

## 已确认的问题

1. 普通断开与解除绑定已有独立操作，但解除绑定之后没有移除记录入口。已有删除基础方法会删除账号实体，不可直接接到按钮上，因为账号关联会话与消息历史。
2. 列表主要显示 label，详情底部显示 LazyMind 内部 account_id；通知配置下拉框仅显示 label。同名机器人无法直观区分。
3. 注册 SDK 已返回授权人名称、app_id 和 open_id；当前名称用于 label，其余信息保存在加密凭据中。解除绑定清凭据后不能恢复这些信息，也不能由身份哈希反推。

## 实施行为

- 解绑后提供“删除记录”，从连接列表和可选账号中移除，保留历史。删除前展示仍在引用它的任务/默认配置；不自动把这些规则改绑给另一个机器人。后续配置明确要求重新选择。
- 不物理删除历史，不操作飞书侧应用。
- 明确区分已连接、已断开（保留凭据）、已解绑（凭据已清除），避免把解绑记录当作普通暂停。
- 账号卡片显示可编辑备注名、授权人名称和飞书应用 ID 的可辨识部分，详情可查看完整应用 ID；通知配置选择器同步展示，不能仅给设置页加标识。
- 备注用于区分用途，例如“工作号 · 每日简报”。未取得的授权人姓名不杜撰；已清空凭据的旧记录显示信息缺失，可手动备注，重新授权后补齐实际身份。
- 展示信息不含 app_secret、token、二维码授权参数。只允许当前账号拥有者读取和修改。

继续复用现有账号、通知引用查询、集中 qa.read/qa.write 权限、加密和双数据库基础。身份展示信息必须在清密钥后仍可保留，需评估最小持久化字段和旧记录回填，不能用前端缓存代替持久化或重新保存完整凭据。

## 持久化与兼容

新增 identity_metadata（仅应用 ID、授权人名称和应用内用户 ID）与 archived_at 两个可空/有默认值的增量字段。备注复用 label。保留有效凭据的旧记录通过既有凭据解密加载回填标识；解绑前也回填，既已清空的旧记录不伪造数据。新版本解绑后保留的公开应用 ID 可用于定位原应用重新授权，最终仍严格核对原身份。SQLite 与 PostgreSQL 分别采用已有迁移路径，重复初始化不改现有记录。

删除要求 disconnected 且凭据为空。所有权与删除条件在事务内校验，取消进行中的重新授权。归档账号不再出现在可用账号查询、重连和选择器中，也不能通过老授权回调恢复。通知历史保留原关联；任务配置不自动修改。删除后的原应用仍在飞书存在，本次不提供恢复隐藏记录的入口。

回退代码不要求删除增量字段；旧版本会再次显示已归档且已解绑的记录，但没有凭据，无法自动发送。禁止通过清表或删历史回退。
