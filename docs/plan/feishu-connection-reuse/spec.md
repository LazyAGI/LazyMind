# 飞书连接优先复用

## 背景与目标

用户批准“首次创建、重复接入复用、断开后恢复原连接、明确新增才创建多个机器人”的产品方向。用户随后明确批准调整断开语义：暂停保留凭据，恢复免授权；解除绑定清除凭据。方案已确认，用户于 2026-09-18 明确要求“直接实现，最后再测试”，覆盖本批测试后的人工停止点，进入实现与统一验证。

当前每次新会话都调用 SDK register_app(create_only=True)。连接按 app_id 与 owner_open_id 的组合识别，因此同一飞书用户创建不同应用不会被去重。当前断开操作会清除加密凭据、停止运行租约并终止待发送消息；原 DELETE 接口继续保持清凭据语义；飞书界面的普通“断开”改用独立暂停操作。

## 行为

1. 无历史连接时，用户明确选择首次接入并扫码创建机器人。
2. 已有连接时，普通“连接飞书”入口优先显示当前用户的已有机器人；单个仍需显示明确名称，多项必须选择，不能按同名、最近使用或用户名猜测身份。选择已连接项直接复用其 account_id，不生成创建二维码。
3. 普通断开仅暂停收发，保留加密凭据与绑定。凭据有效时恢复原运行实例、机器人与 account_id，不扫码、不新建；解除绑定、旧版本已清空密钥或凭据失效时才重新授权原应用。身份不匹配时拒绝，不自动变成新增。
4. 只有独立“新增机器人”操作进入强制创建流程；已存在的机器人不删除、不合并，通知规则和历史记录不迁移。
5. 暂停保留原加密密钥，不保留额外副本；解除绑定继续清密钥、停止租约和待发送队列。恢复不重发已终止的旧消息。重新授权流程仍需真实飞书验证；不回退到偷偷创建新应用。
6. 复用仅限当前 LazyMind 用户自己已有的连接，不能由登录名、显示名或二维码扫描人推断账户所有权。现有 app_id+owner_open_id 约束保留；跨 LazyMind 用户自动共享机器人不在范围内。

## 设计与范围

复用现有账号查询、连接会话、幂等键、所有权校验、运行租约、通知引用与 SDK 注册适配器。连接入口显式区分复用/重新授权/新建意图；后端必须校验，不能只靠前端隐藏按钮。复用原会话返回结构，避免增加独立服务或架构层。具体契约字段及稳定错误在测试阶段确定并同步 API 文档。

已有 SDK 暴露 create_only 和 app_id 参数；目前适配器固定 create_only=True。重新授权解除强制创建，并优先使用可安全获得的原 app_id；断开后的密文已清空时不得试图反推哈希。以授权返回身份与原记录的严格匹配作为最终限制。

默认不变更数据库 Schema；如调研证实必须持久化新的非密钥标识，则先补充迁移方案与审批。数据库路径同时覆盖文件 SQLite（Local/Desktop）和 PostgreSQL（Compose）。前端范围限飞书连接入口与必要文案，微信/企微保持行为不变。

## 完成标准

重复连接不调用创建注册、不新增飞书应用或本地账号；原账号的通知规则/历史引用保持有效。重连无法验证原身份时安全失败。独立新增操作正常创建。并发/重复请求不触发多次创建。相关双库、API、安全、前端测试通过；真实飞书扫码由用户授权完成，并记录应用 ID 是否保持一致。

## 非目标

不清理既有重复机器人、不跨账号合并、不改变旧 DELETE 清凭据接口、不改微信/企微、不自动提交或推送、不擅自扫描飞书或发送测试消息。

## 本批测试契约

- `POST /channel-accounts/{account_id}:pause`：仅飞书，204；状态 disconnected、停止收发与租约，保留原密文；重复暂停成功。
- `POST /channel-accounts/{account_id}:resume`：仅飞书，200 返回既有安全账号视图；拥有有效本地凭据则恢复，重复/并发恢复只能启动一次运行实例；无凭据或无法解密返回 409 / FEISHU_REAUTHORIZATION_REQUIRED，不自动注册。
- 原 `DELETE /channel-accounts/{account_id}` 对应“解除绑定”，继续返回 204 并清凭据；暂停、解除绑定均保留历史引用。不为微信/企微开放上述暂停/恢复能力，返回 422 / PROVIDER_NOT_SUPPORTED。
- `POST /connection-sessions` 追加严格布尔字段 `create_new`（默认 false，只允许飞书）。有一条已连接记录时默认复用；多条未指定目标返回 409 / ACCOUNT_SELECTION_REQUIRED。指定 account_id 时复用/恢复该记录；已清密钥记录引导重新授权原机器人。create_new=true 才明确新增；不得同时传 account_id；其它渠道不得传 true。
- 首次无历史连接允许原创建流程；相同幂等键/同一进行中流程去重；同一键的新增意图和目标不一致时返回 409 / ACCOUNT_STATE_CHANGED。已解除绑定的记录不算“首次无历史”，不得隐式创建新机器人。
- 暂停与解除绑定并发时，后续恢复不能使已清空密钥的账号复活；所有权不匹配返回 404 / ACCOUNT_NOT_FOUND。

以上是基于已批准产品行为的接口细化，本批测试审查同时审查这些接口。数据库 Schema 默认不改；现有 disconnected 状态配合密钥存在性区分暂停和已解除绑定。


## 实现补充

显式重新授权使用 `reauthorize=true` + account_id，与 create_new 互斥，避免远端撤销密钥后仍只能走本地恢复。普通重连只恢复，不要求再次授权。复用既有加密会话状态保存重新授权意图，不改 Schema；刷新二维码仍授权原身份。重新授权成功通过事务替换原账号凭据和完成会话，绕开仅适用于首次创建的失败清理/欢迎消息，不删除既有记录。暂停/解除绑定取消进行中的原账号授权，避免晚到回调复活连接。接口和稳定错误详见 api/backend/task-notifications.md。
