## R1 默认设置

- [x] 新用户总开关为开，桌面渠道默认开，外部渠道默认关；未授权桌面不标为已发送。
- [x] 成功/失败默认开启且为 `summary`，等待默认关闭且保留 `summary`。
- [x] 关闭最后一个默认事件返回 422 `NOTIFICATION_EVENT_REQUIRED`，数据库设置不变。
- [x] 修改默认值后刷新可读；已有任务不变，普通、批量和对话工具新建任务都继承新默认值。
- [x] 开启外部默认渠道却未选明确目标时返回 422 `NOTIFICATION_TARGET_REQUIRED`，不能默取列表首项。
- [x] 并发设置旧版本返回 409 `NOTIFICATION_CONFIG_CONFLICT`，未知事件/内容值返回 422 `INVALID_REQUEST`。

## R2 单任务配置

- [x] 一个任务可同时配置桌面、飞书、企业微信、微信；每个平台按批准范围绑定一个稳定账号/接收对象。
- [x] 所有渠道关闭可保存且执行计划不变；有渠道无事件返回 422 `NOTIFICATION_EVENT_REQUIRED`。
- [x] 关闭渠道后账号/接收对象仍在，关闭事件后内容选择仍在，再开启恢复原选择。
- [x] 开启状态下目标缺失返回 `NOTIFICATION_TARGET_REQUIRED`，目标失效返回 `NOTIFICATION_TARGET_UNAVAILABLE`。
- [x] 其他用户的任务/账号/投递记录不可读取或修改；对象不存在与越权保持一致的 404 行为。
- [x] 两人读取同一版本并保存不同配置，仅第一位成功，第二位冲突；两数据库都验证。
- [x] 恢复默认只改变目标任务；详情区分未配置、关闭和配置失效，不列入从未配置的渠道。

## R3 执行快照和总开关

- [x] 定时触发、立即执行、依赖等待创建的执行都持久化规则快照；等待恢复后快照不变。
- [x] 执行 A 期间改规则，A 仍按旧快照；执行 B 使用新规则。
- [x] 任务成功输出已可读取时才生成成功通知；子步骤结束不提前通知整任务成功。
- [x] 失败通知含安全失败原因；人工等待通知含待处理事项，不发送未完成结果。
- [x] 相同回调/轮询/恢复产生同一事件标识；新的待处理事项不被错误合并为旧等待事件。
- [x] 有受影响运行时首次关闭返回 409 `NOTIFICATION_CONFIRMATION_REQUIRED` 及任务清单，设置不变。
- [x] 确认关闭时影响范围/版本变化需重新确认；确认成功后任务继续执行。
- [x] 关闭总开关后未领取发送许可的分段不能发送；已开始外部请求按批准边界记录真实结果。
- [x] 关闭期间产生或被抑制的通知记为跳过；再次开启、重启或历史扫描均不补发。
- [x] 总开关读取失败不能安全放行；不会因通知故障将任务改为失败。

## R5 投递与重试

- [x] 通知含名称、执行时间、状态和对应摘要/正文；飞书/微信现有渲染与发送被复用。
- [x] 格式不支持时返回明确降级信息；超过平台单条长度使用既有分段，不能把截断全文标为完整。
- [x] 相同执行事件/渠道/目标的重复交接只生成一条有效通知；重复发送任务监控不会再通知一次。
- [ ] 一渠道失败不阻塞其他渠道，任务结果和运行次数不变。
- [x] 重试记录关联原失败记录；再次点击或并发重试只领取一次，不覆盖原失败历史。
- [x] 明确暂时失败遵守最多 5 次尝试、现有退避上限 300 秒；无权限等永久失败不盲重试。
- [x] 不支持平台幂等时，回执丢失记录 `unknown` / `NOTIFICATION_DELIVERY_UNKNOWN`，不自动重复发送。
- [ ] 分段发送中断能利用已持久化进度恢复；120 秒租约/30 秒续租及租约丢失行为经可控时钟测试。
- [x] Core 事件提交后网关不可用、网关入队后确认丢失、进程重启均可恢复，不丢失或重复生成通知。
- [x] 投递记录准确区分排队、发送中、已发送、失败、跳过及未知，包含安全原因和尝试时间。
