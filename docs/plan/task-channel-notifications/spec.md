## 背景、目标用户与范围

为使用定时任务的 LazyMind 用户提供按任务选择通知事件、平台账号及接收对象的能力。通知失败不得改变任务执行结果。覆盖 Docker Compose 的 PostgreSQL 和 Desktop/Local 的文件 SQLite；渠道网关使用各部署方式已有的独立状态库。

本次交付后端设置与配置接口、渠道账号和接收对象接口、任务执行规则快照、通知投递与重试记录、企业微信适配，以及桌面客户端可消费的通知数据。飞书和微信优先扩展既有实现。

不修改前端页面、桌面自绘界面或算法模块；不接入邮件等额外渠道，不为外部 Codex/OpenClaw 任务增加通用通知服务。2026-09-16 根据用户“除了前端其它继续实现”，追加 Electron 主进程原生通知、故障回归和部署验证。原后端阶段二审批继续有效；新增原生桥接按仓库规则先审方案、再审测试，不将接口通过等同于系统弹窗已完成。

## 能力与行为

### R1 用户默认设置

- 通知总开关默认开启；新任务桌面渠道默认开启，外部渠道默认关闭；桌面是否可实际投递取决于客户端能力和授权。
- 成功、失败默认开启，内容均为摘要；暂停/等待确认默认关闭，保留摘要选项。
- 默认事件至少保留一个。设置按请求即时持久化，返回新版本；失败请求不产生部分设置，不能把原型的本地演示状态当作成功保存。
- 默认渠道和事件只复制到新建任务；普通创建、批量创建和对话工具创建共用同一条初始化规则。修改默认值不重写既有任务。
- 外部默认渠道须有明确可用的默认账号/接收对象；多账号时不以列表顺序或“最近连接”隐式绑定。拟由设置接口保存默认目标，任务可独立覆盖。
- 默认事件内容选择与开关独立保存，关闭再开启恢复此前选择。

### R2 单任务通知规则

- 每个定时任务独立保存三类事件开关和摘要/全文选择，及四种渠道的启用状态。拟每个平台选择一个账号和一个接收对象，符合当前原型；不新增批量广播功能。
- 有任一渠道开启时至少一个事件开启；全部渠道关闭时允许保存，任务照常执行。
- 外部渠道启用时校验账号归属、平台、连接、发送能力、接收对象及其与账号的关系。关闭时保留失效账号/接收对象，允许保存禁用配置。
- 修改账号时返回该账号的默认接收对象供客户端选择，保存时必须明确目标；不得用账号排序索引代替稳定 ID。
- 恢复全局默认只修改目标任务，不影响其他任务。清除通知配置不删除执行结果或发送历史。
- 请求携带独立通知版本，使用数据库比较更新；旧版本返回冲突，不能覆盖较新的设置。通知修改不篡改现有任务定义版本的语义。
- 详情只返回已配置渠道及可用性；未配置、配置后禁用、已启用但账号失效须可区分。

### R3 执行快照、触发与总开关

- 在执行记录创建时固定通知规则、目标身份和版本；包括手动立即执行、定时触发、依赖等待执行。等待后继续运行不能重新读取新版任务通知规则替换快照。
- 修改任务规则从下次执行生效；当前执行仍按快照。通知总开关及账号断开属于实时发送门禁，优先于运行快照。
- 关闭总开关时如有受影响执行，接口先返回任务清单和确认所需版本，不修改设置；确认请求重新检查当前影响范围与版本，变化则重新提示。
- 关闭总开关不会修改任务调度、任务状态、规则或历史。关闭期间应被抑制的通知永久记为跳过，重新开启不补发，包括已排队但尚未开始外部发送的通知。
- 发送门禁的并发边界拟定义为领取该分段发送许可；总开关关闭/账号断开后不能再领取许可，已经开始的外部请求无法承诺撤回。测试应覆盖关闭与领取并发及领取后响应延迟。
- 任务成功通知必须等最终输出可读取后产生，不能因为一个子步骤成功或聊天流暂时结束就提前发送；失败和等待事件使用任务中心可观察状态。
- 等待通知包含待处理事项，不含未完成结果。普通依赖调度的短暂等待不视作人工待确认；可处理的暂停/审批等待才触发，具体状态来源在测试矩阵中列明。
- 每次真实事件有稳定标识：成功/失败按执行去重，等待按新的待处理事项去重；轮询重复、重连或重复回调不能生成新事件。

### R4 账号、目标与重连

- 同平台可有多个账号。新增账号不覆盖已有账号或任务目标；重复连接同一身份执行幂等更新，跨用户占用按现有身份约束拒绝。
- 显式断开前可查询引用任务和运行影响；确认断开后保留账号身份、任务选择及通知历史，停止运行接收器并阻止后续发送；不自动改绑其他账号。
- 重连接受原账号 ID，验证外部身份仍匹配；成功恢复同一 ID 和引用。扫码得到了另一个身份不能静默替换原账号。
- 账号详情提供名称、可用头像、主要接收对象、连接/发送状态、连接时间、最近消息时间和引用任务数量/分页明细。平台不能提供头像时返回空值，Logo 回退由前端完成。
- 接收对象列表只来自该账号已授权且可验证的成员/会话；复用已接收消息中的地址及平台已验证信息，不为通知读取整个企业通讯录。
- 微信按所选账号和收件人查找有效上下文，Secret 留在网关加密存储，不出现在 Core 配置、响应或日志中。连接成功和可以发送分别呈现。
- 企业微信按 D2 实现适配器；推荐方案先覆盖文本对话、既有公共命令路由和任务通知，文件等按已验证 SDK 能力返回支持/降级信息，不新增完整媒体平台。

### R5 投递、展示与重试

- 统一通知内容包含任务名称、执行时间、状态、摘要或最终全文、任务/执行标识。失败必须包含安全的失败原因；等待必须包含待处理事项。
- 优先复用任务输出中的摘要、最终正文和产物信息，不额外调用模型生成摘要。复用公共文本清洗、分段渲染及平台呈现逻辑。
- 飞书用现有卡片/文本能力；微信用已有文本与支持的产物能力；企业微信按已验证能力输出 Markdown/卡片。平台不支持的格式必须明确降级，不能把截断后的内容标为完整全文。
- 每个执行事件、渠道、账号及接收对象形成唯一通知身份。各渠道独立排队、失败、重试；不得修改任务成功/失败结果。
- 外部发送统一复用现有 Outbox、DeliveryWorker、租约、分段进度、确定性发送标识及重试机制。新增通知记录与原会话回复通过用途区分，避免现有任务监控再次发送相同通知。
- 明确被平台拒绝的暂时错误可重试；账号失效、无发送权限、上下文缺失等需要用户处理。平台是否具备请求幂等须逐项验证，不能把请求流水号当成幂等承诺。
- 对不支持幂等的平台，发送成功但回执/落库结果不明时记录 `unknown`，不自动盲重试。人工确认重发只重发通知，保留原通知及尝试关联和重复风险提示。
- 投递记录提供排队/发送中/已发送/失败/已跳过/结果未知、稳定原因、时间、尝试次数和可重试标志；客户端投递确认与系统实际展示需区分。

### R6 桌面通知后端契约

2026-09-14 用户以 macOS 原生通知及 Windows 通知中心两张截图明确展示预期：任务名称作为标题，实际结果摘要作为正文，应用标识使用 LazyMind。截图内容仅作为展示参考，不是待执行任务。

- 产出稳定通知 ID、任务名称标题、实际结果摘要预览、事件类型、执行时间、任务/执行 ID 和站内跳转信息，支持任务完成后及时提醒及点击定位任务的数据需求。正文应让用户直接了解结果；仅有“任务已完成”的通用提示不满足截图预期。失败和等待分别展示安全失败原因及待处理事项。
- 最终客户端效果为 macOS/Windows 原生通知，可按系统设置展示横幅并出现在系统通知中心。应用名称和图标为 LazyMind；布局、时间、折叠分组和可见行数由操作系统控制，无需复制图片像素或自绘通知中心。
- 系统勿扰模式、通知授权和横幅偏好决定实际展示方式；不得绕过系统设置，也不能将系统接受通知等同于用户已经看见。正文可能被系统折叠/截断，点击通知定位完整任务结果。
- 客户端通过受保护的游标查询接口取当前设备适用的通知，并提交展示结果；重连可重复读取相同 ID，客户端按 ID 去重。
- 后端校验用户归属及当前设备绑定，不接受任意用户/设备 ID 扩大发送范围；Local/Desktop 单机部署以其本地运行实例为设备边界。远端多设备广播不在本期推荐范围。
- 桌面未连接或未授权时返回准确的不可用原因，不假报系统通知成功。原生通知中心展示、是否在前台显示、声音、系统权限和唤起行为属于客户端验收；新增主进程桥接范围见下节。
- 总开关关闭后不能让尚未领取的桌面通知在重新开启时弹出；后端仍保留其跳过记录。

### R7 追加的非前端交付方案（2026-09-16 方案和测试获批，原生桥接已实现）

- 复用 Electron 原生 Notification、现有 LazyMind 应用身份和后台常驻生命周期；不新建通知窗口，不增加生产依赖。系统管理横幅、通知中心、声音和勿扰行为。前台与后台均可提交已启用的任务通知，不以窗口焦点隐藏结果。
- 复用已有登录/退出同步入口。仅消费当前登录用户、当前本地运行实例的受保护通知接口；退出、切换用户或停止运行时取消旧轮询，关闭旧通知，阻止旧回调提交和跳转。不把管理员自动登录当成当前用户身份，也不将令牌发给任意服务器或重定向目标。
- 每 5 秒串行查询，单次请求最长 10 秒，故障退避最长 60 秒；按后端最多 100 条分页处理，保持可停止、无重叠轮询。令牌过期只使用现有会话机制恢复，身份无法确认时暂停，不绕过认证。网络恢复后重新读取待处理通知。
- 通知标题及正文直接使用已清洗的后端字段；只有系统接受通知后才提交 delivered 回执，其含义不是用户已阅读。Electron 平台支持检测不等于用户授权；无法判定的系统失败不得伪造 permission_denied 或 delivered。
- 以用户、实例和通知 ID 去重，持久化最小投递状态用于进程重启后的回执补交，不保存令牌或消息正文。系统提交与本地落盘无法形成事务，崩溃发生在该窗口时保留结果未知，不自动重复弹出；在交付报告中披露此限制。
- 点击先验证仍为原登录用户并查询所属任务；存在会话时打开现有完整结果会话，否则打开现有任务列表。当前前端没有按 task ID 打开详情抽屉的路由，本批不新增前端路由或抽屉逻辑。链接仅由受信本地源和经编码的标识构造。
- 打包在独立临时目录验证，保留已有 desktop/build 和 desktop/dist。macOS 可在当前机器验证；Windows 安装及系统通知中心需要 Windows 测试环境。真实微信、企微、飞书消息仅向用户指定的测试环境和收件对象发送；凭据留在已有配置中。

## 设计骨架与最小复用

| 所属位置 | 保存/承担的内容 | 复用原则 |
| --- | --- | --- |
| Core 用户偏好 | 总开关、默认规则、配置版本 | 扩展现有偏好和设置入口，不复制账户设置体系 |
| Core 定时规则/执行记录 | 单任务通知配置、独立版本、执行快照 | 使用既有定时任务与运行模型，普通/批量/手动/依赖路径共享 |
| Core 任务中心 | 持久化通知事件、内容关联、桌面投递记录 | 只增加保证崩溃恢复与可查询性的必要记录，不创建通用消息总线 |
| Channel Gateway | 账号、接收上下文、平台能力、实际外部投递历史 | 原 Outbox 是外部投递状态来源；不增加第二个外部重试队列 |
| Core 与网关 | 按稳定事件 ID 幂等交接、状态查询 | Core 记录事件后通过可信服务边界交接；入 Outbox 后再确认，断点重放仍为同一通知；首批测试拟固化接收接口，后台交接和认证链另须集成测试 |

Core 事件与任务状态/输出在同一数据库事务中持久化；平台调用在事务外执行。状态修正、崩溃恢复或读取派生状态不能成为唯一通知触发入口，需覆盖真正的状态落库路径及必要补偿。跨 Core/网关数据库不宣称事务原子发送；依靠持久事件、Outbox 唯一键和确认后推进游标恢复。

Core 不读取网关凭据表，网关不直接修改 Core 业务表。账号断开影响与通知引用经既有服务边界查询。公共接口继续使用 Kong/auth-service 的集中权限，复用用户/对象归属校验。内部接口须使用现有可信服务认证及网络边界；不能靠调用者任填 `X-User-Id` 获得跨用户读取或投递能力。

## 拟定接口边界

以下为方案接口边界；首批测试细化的请求、返回与存储字段随测试一并 Review：

| 入口 | 操作及关键数据 |
| --- | --- |
| Core `GET/PATCH /user/notification-preferences` | 复用偏好存取，返回总开关、默认规则、版本；关闭确认携带影响清单及版本 |
| Core `GET/PUT /schedules/{schedule_id}/notifications` | 读取、验证和保存当前任务通知配置；强制版本比较 |
| Core `POST /schedules/{schedule_id}/notifications:reset` | 按当前默认值重置指定任务，保留历史 |
| Core `GET /task-center/tasks/{task_id}/notifications` | 运行快照和各渠道投递记录，不触发发送 |
| Core `GET /task-center/desktop-notifications` 及回执操作 | 用户/设备隔离，游标、稳定通知 ID、客户端投递状态 |
| Gateway 现有 `channel-accounts` / `connection-sessions` | 向后兼容增加能力/视图；原扫码协议仍可用，企微凭据模式独立标识 |
| Gateway 账号目标、引用、重连接口 | 可选目标和可用性，断开确认，稳定 ID 重连；Secret 仅写入 |
| Gateway 通知记录重试接口 | 校验通知归属、当前总开关、账号/收件人状态和重试版本；幂等重发且保留关联 |
| Core/Gateway 内部事件交接与门禁 | 受保护的分页事件查询、持久入队确认及发送许可；外部用户不得模拟 |

## 默认值、限制与错误

下列新增阈值为供批准的工程建议，不宣称来自产品原文或平台限额。第三方限制更低时以其上限为准。

| 项目 | 默认/限制 |
| --- | --- |
| 渠道/事件/内容 | 4 种固定渠道、3 类事件、`summary/full`；未知值拒绝 |
| 外部目标数量 | 每个平台 1 个账号、1 个目标；不支持通配广播 |
| 配置请求体 | 最大 16 KiB；账号/目标标识最多 256 字符；Secret 写入请求最大 16 KiB 且不回显 |
| 列表 | 默认 20 条、最多 100 条；稳定游标顺序 |
| 摘要与桌面预览 | 优先使用现有摘要；建议摘要上限 1000 字符、桌面预览 200 字符；全文沿用平台分段且保留完整内容获取入口 |
| 平台发送超时 | 建议 10 秒；连接登录沿用已实现的平台专用时限 |
| Outbox 并发与租约 | 沿用 2 个发送工作线程、120 秒租约、30 秒续租 |
| 明确可重试失败 | 沿用最多 5 次尝试及现有指数退避，上限 300 秒；失败结果未知另行处理 |
| 事件读取 | 建议每批最多 100 条，空闲 2 秒；时序测试使用可控时钟 |
| 历史 | 不主动删除本期通知历史，不补发迁移前执行或总开关关闭期间记录 |

复用 `UNAUTHORIZED`、`INVALID_REQUEST`、`PROVIDER_NOT_SUPPORTED`、`ACCOUNT_NOT_FOUND`、`ACCOUNT_STATE_CHANGED` 等已有错误；拟新增 `NOTIFICATION_EVENT_REQUIRED`、`NOTIFICATION_TARGET_REQUIRED`、`NOTIFICATION_TARGET_UNAVAILABLE`、`NOTIFICATION_CONFIG_CONFLICT`、`NOTIFICATION_CONFIRMATION_REQUIRED`、`NOTIFICATION_DELIVERY_UNKNOWN`。HTTP 422 用于不合法配置，409 用于版本/确认/状态冲突，404 隐藏不属于当前用户的对象。需要在阶段一固化公共结构，统一安全消息、公开字段定位和 `request_id`，不返回异常原文。

## 数据、安全、迁移及兼容

- 规则与快照采用可验证结构和显式版本；快照只保存稳定身份和非敏感选项，不保存平台 Token、Secret 或签名 URL。
- 对外正文先去除内部协议、工具调用/推理块和内部错误细节；失败原因来自稳定映射。必要根因仅记脱敏日志，SDK 原始帧/异常日志不得直接启用。
- 新的持久化分别测试 PostgreSQL 和真实文件 SQLite；包括 JSON 默认值、布尔值、时间、唯一约束、外键保留、并发配置、租约争用和重试领取。SQLite 必须验证实际事务/锁行为，不能仅依赖 SQL 文本替换。
- Core 新迁移使用执行时 UTC 秒级时间戳，同时提供 up/down；目前已有 `v0_3` 聚合，新增对应 dev migration 时同步审查并更新已有聚合。不得修改已合并 dev migration 或新建额外聚合。
- Gateway 复用 PostgreSQL/SQLite 两套初始化升级路径；账号断开的新行为须保留现有数据，尤其不能级联删除通知历史。
- 升级保持飞书、微信现有账号/路由和正常聊天兼容；新通知配置的缺省行为由 D4 决定。回退恢复原有结构与业务数据，并明确新增通知字段/记录的保留或不可供旧版读取的边界。
- 无数据库或平台真实环境时，只报告实际通过的层级，不能把 Mock 发送称为真机接入成功。真实平台发消息需另有明确的测试目标与发送授权，本轮没有发送授权。

## 完成标准

获批的 D1～D4、依赖及方案与测试/实现一致；三渠道通过统一投递路径；规则快照、总开关、断开重连、错误处理、独立重试与去重可复现；双数据库迁移和运行检查通过；前后端契约和错误目录同步。桌面交付明确为后端契约，系统弹窗及平台真机未验收项单独列出。
