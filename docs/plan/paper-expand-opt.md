# 论文扩展 Workflow 优化方案

本版依据用户确认的 [Workflow 方案](https://app.notion.com/p/Workflow-3feb8b30a5b0812a939aff9578ed8d59)、2026-10-27 固定候选实验及默认模型复测。分支 `dya/paper-expand-opt`；以 #863 合入后的实际 main 为最终优化 PR 基线。以下业务流程取代旧稿“五步保持不变”“不改数据库结构”的约束；上下文精简与冻结交接继续纳入同一优化。

## 已确认的行为

开始初步调研即创建可离页恢复的拓展记录，不创建隐藏 Chat。可以只给主题，也可以选择种子；先读可用材料，不以 DOI 补齐作为前置条件。必要问题持久化后结束本次 Agent，用户回答后以新版本继续。方向卡片必须关联真实登记论文，调研深度在启动时固定，不按整轮耗时截断研究。候选方向最多 5 个、不设数量下限；只有一个有效方向且没有待补充问题时自动创建或关联正式 Chat，多个方向由用户明确选择并确认后继续。

| 模式 | 准备上限 | 正式上限 |
| --- | --- | --- |
| 快速 | 120 秒 | 600 秒 |
| 均衡（默认） | 180 秒 | 1200 秒 |
| 深入 | 300 秒 | 1800 秒 |

预算是执行上限，等待回答不计时。自动重试沿用开始时间，不能获得整轮新预算；正式四步按 10%/40%/40%/10% 分配，为整理保留时间。失败保留阶段产物和上一份成功结果；不能把失败步骤标成成功。

## 检索与材料

- 扩展现有 `papers:search`：OpenAlex、arXiv，以及配置有效的 Sciverse；通用搜索用于补漏、落地页和公开副本。支持关键词、前向/后向引用；各方向单独检索，再按服务端身份归并，准备检索成果可复用。
- DOI、arXiv ID、来源 ID 参与归并。强标识冲突不按同题合并，保留待核对线索；网页项目/教程只有完成论文身份解析才进入候选集。完整原始摘要留存，未知摘要为 null。
- 继续使用现有工具配置/凭据解析链路；OpenAlex 配置加入现有数据源目录。来源响应分别呈现零结果、缺配置、鉴权失败、限流、故障，避免模型将缺配置误判为零结果。OpenAlex 托管全文私有 Key 只放在下载请求中，不进入 URL 快照、原件元数据和模型输入。
- 取文复用 `AcademicPaperContent`、异步任务、OriginalService 和解析服务。先使用当前授权文档和缓存，再使用已登记 OA/arXiv/托管内容、公开落地页明确 PDF 链接及已配置的通用搜索。保留 DNS/IP/跳转/大小/权限和 arXiv 版本校验。
- 分开记录下载、论文身份/正文类型、解析质量、实际阅读。补充材料、幻灯片、错误论文和乱码拦截；无法确认身份为待核对，不计入可用正文。记录实际来源、版本、PDF 哈希、解析器版本和各次耗时。
- 普通拓展按需取文；综述为种子和最终清单去重全集补取。至少两篇不同论文的正文通过身份和解析检查才自动转接；失败论文保留在冻结输入。

## 阅读、证据与正式流程

摘要筛选 → 关键词/页范围定位（完整页及相邻页）→ 必要时连续全文。无可靠页码返回可追溯块位置，不能伪称第一页。服务端按实际工具返回位置累计覆盖，区分正文可用与已读；首次和续读都保留任务、权限、来源、哈希和游标校验。

方法继承、效果改善、关键数字和条件提交后进行一次独立定向复核。先补上下文再提交；不支持的结论改成不确定，不无限补查。证据、实际读取和复核留在阶段产物与轮次报告，不扩充共享 WorkflowPaper。重复发布不会再次触发复核。

| 步骤 | slot | 任务 |
| --- | --- | --- |
| 准备参考论文与检索计划 | expansion_plan | 承接确认范围、按方向检索计划和停止条件 |
| 拓展与筛选 | candidate_set | 检索、引用、去重、筛选及实际缺口 |
| 分析论文关系 | relation_analysis | 按需阅读、证据与关键结论复核 |
| 整理研究脉络与阅读建议 | expansion_result + expansion_report | 完整结果、研究脉络、阅读顺序、来源/缺口/用量 |

模型提交分析和组织，题录/种子/重点由服务端解析和发布；`ReviewWorkflowInput` 保持四字段。每轮是完整结果，可删除非种子，保留用户种子和重点。原范围继续沿用记录及 Chat；实质改变方向回详情准备确认；只改组织/顺序重做第四步。下游输入、启动重点及版本冻结，后续轮次不回写。综述/心得/PPT 仍明确是现有 Mock 接收链路。

## 持久化、接口和页面

- `POST /academic/workflow-launches` 创建准备，返回记录和状态、无 Chat；已有结果转下游职责保留。
- `POST /academic/expansions/{id}/preparation` 接受 answer/revise/retry、准备版本、幂等键；旧尝试不覆盖新结果。
- `POST /academic/expansions/{id}:confirm` 校验准备版本、方向和预算；事务内创建/关联 Chat 并排队启动，重复确认返回同一任务。
- 拓展增加准备/预算/读取/报告字段，conversation_id 可空；轮次独立报告，内容独立质量状态。SQLite 和 PostgreSQL 各自升级/回滚，聚合迁移同步最终结构。本次只有可重建开发数据，不维护 PR 内中间协议。
- 详情抽屉展示准备进度、问题、真实代表论文、方向及预算、正式执行和报告；正式运行时准备内容折叠保留。论文卡片显示正文状态、读取范围、贡献和关系、入库状态。分析下载不自动入库。
- 复用持久化通知和桌面/浏览器投递，新增待回答/待确认，按版本去重。论文页铃铛、系统提醒都导航同一记录；点击/已读不改变业务状态。当前记录可直接更新，送达与已读分开。
- 报告冻结准备尝试、阶段耗时、来源调用、取文质量、阅读位置、实际模型及原始 Token/额度记录。没有计费依据时金额未知，不推算总费用。

## 验证与实验依据

原实验 62 候选下载 44 份 PDF，只有 39 份通过基础检查（37 个不同有效内容哈希）。固定 p038/p043/p046/p058/p061 覆盖补充材料、乱码、错误论文与培训幻灯片；新质量检查对旧缓存44份回放通过35份，五个指定异常均拦截。真实 OriginalService 下载/当前源码解析回放62候选，36份下载并解析、31份核验通过；该回放逐候选35秒，不与旧实验成功率直接等同。异常 p043/p058 在新进程原生解析分别得到 37/23 页、79508/92774 字符，旧服务输出异常，优先修复会话隔离并保留质量门槛，未引入新解析库。

默认模型 deepseek-v4.1-flash 六篇×三模式复测，8192 输出预算的 18 次均返回四题答案；定向/全文总 Token 为 32108/100906，降低约 68.2%。CRAG 定向结果正确区分 Self-CRAG/Self-RAG 与 7.0% 比较，RoseTTAFold 明确保留约 1.5 小时搜索前置条件。新独立复核另指出少于 400 个残基的适用范围：完整条件通过，遗漏条件为不确定，错误方法关系及把搜索包含在十分钟内的说法被拒绝。此前 2200 输出预算存在推理耗尽导致截断；报告保留所有失败/中间调用、真实 reasoning 计量，不声称总金额已知。这些是小样本依据，不代替全部事实人工验收。

核心验证覆盖检索分类/身份冲突、材料质量和两篇门槛、定位/续读权限、准备幂等与旧版本、预算重试、报告与历史冻结、通知只导航、页面并发响应。真实网络候选回放报告与默认模型原始输出保存在仓库外私有实验目录，报告不含凭据。

| 拓展详情重复返回交接材料 | `GetExpansion` 直接序列化 `AcademicHandoff`，连同 `input`、`contents`、`mock_result` 返回，前端交接列表只使用任务导航字段。 |

| 字段约束不够明确 | 部分 OpenAPI 返回值使用无明确字段的对象，前端手写类型比实际响应小，新增数据库字段容易无意中进入接口。 |

## 接口调整

### 上下文增加摘要视图

复用 `GET /api/core/academic/chat-context`，增加 `view=summary`，供横幅以及仅需交接身份的内部工具使用。保持现有未传视图时读取任务上下文的入口，避免新增一套上下文接口。

摘要只包含适用的任务类型、交接或拓展 ID、论文集 ID、状态、版本和导航字段。拓展继续返回自动综述目标、全文就绪数等现有状态；交接摘要不包含 `input`、`contents`、`mock_result` 或完整论文。

默认任务上下文返回摘要字段及冻结的 `input`，不再返回内部 `contents`。`academic_handoff_context()` 仍直接读取这份完整业务输入。未知 `view` 返回明确的参数错误。

后端为摘要和任务上下文定义具体响应结构，复用相同的导航字段和现有输入类型。授权检查在投影之前完成，两种视图都校验当前用户、Chat 归属和论文集访问权限；不能因为是摘要而绕过权限检查。

### 拓展详情按用途投影

`GET /academic/expansions/{expansion_id}` 的 `handoffs` 固定返回 `id`、`kind`、`conversation_id`、`version`，由已有查询结果装配，不直接序列化数据库对象。

保留 `record.result`、阶段进度、历史轮次、正文状态、导入状态和个人重点标记。扩展工具还会读取历史用户要求和回答，因此本次不能只按前端类型裁掉轮次输入、`user_updates` 或 `interactions`。

### 回执只保留一份业务输入

所有任务通过同一个有明确字段的回执结构返回：

```json
{
  "kind": "ppt",
  "status": "awaiting_downstream",
  "feedback": "材料已接收，生成能力待对接。",
  "input": {
    "user_instruction": "围绕所选论文进行研究",
    "papers": [
      {
        "paper_id": "<论文身份>",
        "title": "LoRA: Low-Rank Adaptation of Large Language Models",
        "abstract": null,
        "source_provider": "arxiv",
        "source_version": "v2"
      }
    ]
  }
}
```

删除顶层 `papers`。仅心得接续 PPT 且已有有效正文时返回 `reflection_markdown`；直接 PPT 不输出空正文。`input` 始终取自冻结输入，心得仍从现有有效步骤产物取得，不能使用模型重抄的内容替代。

新生成和缓存重放都通过同一响应类型输出，避免旧的原始 JSON 再次直透。缓存读取采用该类型正常解码和序列化，不增加按历史版本分叉的长期兼容逻辑；服务端冻结材料不重写。重复提交仍返回同一组业务事实。

OpenAPI 同步声明具体返回字段和视图参数，复用 `AcademicReviewInput`、`AcademicPaperTaskInput`，移除回执顶层 `papers` 定义，重新生成客户端。内部来源快照不进入对外 Schema。

## Workflow 和模型上下文

论文扩展改为下述四步及对应绑定关系，继续由服务端解析论文身份、锁定来源版本，模型只补充关系分析。复用现有 `academic_submit_relations`、`academic_publish_expansion_result` 和后置检查，不改为模型重抄整份题录，也不增加另一套发布入口。

Chat 注入前缀收敛为任务定位信息和读取指引。扩展通过现有 `expansion_id` 读取当前记录；下游通过 `academic_handoff_context()` 取得冻结输入，避免在每条用户消息前再复制整份论文和摘要。

两个内置交接 Workflow 保留 `task_context` 的 text 类型及现有材料绑定机制，将其内容收敛为任务定位信息，同步调整 driver 和步骤提示。需要材料的步骤显式调用上下文工具。这里只调整内置包，不改通用 Workflow 引擎，也不引入新的远端绑定协议。

提交和全文读取工具通过摘要视图获得当前 Chat 的权威交接 ID。全文续读继续同时携带当前交接 ID 与原样游标，让服务端拒绝来自其他任务的游标。不能为了减少一次 GET，直接信任模型传入的任务 ID、绑定字符串或省略当前 Chat 的任务约束；本次不增加跨任务缓存。

正文仍通过现有读取接口按页获得。当前用户、论文选择范围、来源版本、内容哈希及游标的检查全部保留。

## 页面和产物展示

通用 `handoff_receipt` 继续作为 text 产物，改为简洁的 Markdown：任务类型、用户要求、所选论文标题与版本、笔记或心得是否已携带，以及一次材料接收提示。完整题录和摘要保存在服务端输入中，不再嵌入人可读回执。展示字段从结构化结果派生，不接受模型重新选择论文。

心得接续 PPT 的 `ppt_request` 继续作为结构化 JSON 产物，使用现有 `json-block` 的折叠配置，展开后可检查完整输入；不新增专用渲染器或第二份机器输入。心得正文继续使用独立的现有 slot。

Chat 横幅改用摘要视图。静态交接在进入 Chat、切换 Chat 或窗口重新获得焦点时刷新，不持续轮询。扩展运行期间维持现有更新频率，阻止请求重叠，并在切换 Chat 后忽略旧响应。自动综述模式下，即使扩展已完成但目标 Chat 尚未出现，也不能提前停止刷新；拿到目标后沿用现有导航行为。

## 验证范围

1. **任务主流程**：综述、独立心得、直接 PPT、心得接续 PPT；核对所选论文、用户要求、笔记和上一步心得正确传递。回执成功只表示接收材料，仍不声称正式生成完成。
2. **冻结和幂等**：启动后编辑题录、笔记或继续拓展，已交接输入不变；首次提交、重复提交、已有缓存结果均返回一致业务内容。历史轮次和旧 artifact 不批量重写。
3. **权限和正文**：其他用户、无权论文集、未选论文被拒绝；首次读取及多页读取成功；跨任务游标和内容版本变化被拒绝。请求体变小不能削弱这些行为。
4. **前端行为**：横幅不再下载论文和快照；切换 Chat 时旧响应不覆盖新状态；慢请求不重叠；自动综述仍能等待并跳转；回执正文没有重复提示或完整 JSON 转储。
