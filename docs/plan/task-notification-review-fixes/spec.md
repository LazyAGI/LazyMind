## 背景、目标用户与范围

目标用户是使用定时任务、任务依赖和桌面/外部渠道通知的用户。修复审查列出的四项确定缺陷，排除旧未配置任务的异步工作流回归，并以真实入口和持久化结果验证。

范围为 Core 的任务收尾、会话状态同步、恢复扫描及相关聊天/工作流/依赖接线；Gateway 的通知重试及公共 Outbox；Electron 原生通知和现有会话 IPC、既有 CLI 凭证存储与无窗口续期；相应测试、后端契约和交付文档。用户本次引用的桌面缺陷纳入修复，不改前端页面或新增导航路由。

保留已有未提交的 `docs/plan/pr-710-review-fixes/`，其中工作区修复的审批和执行顺序不适用于本批通知修复。本批不提交、不推送、不打包或发布，不修改生成产物，不增加生产依赖、服务、数据库表或迁移。

## F1 通知持久化故障不得变成任务执行失败（P1-01）

- 已提交可用最终聊天历史后，通知持久化失败属于可恢复的收尾故障，不得调用业务失败收尾、写入“重试任务”原因或发出失败通知。
- 保留任务成功状态、最终输出和通知事件的事务一致性。失败时回滚本次收尾，保留已提交历史和原非终态，不提交缺少事件的成功状态。
- 为这类故障提供可识别的内部错误传播，现有恢复扫描重试收尾；不得静默吞错，不把数据库异常原文返回用户。无需新增公开任务状态或错误码。
- 恢复只读取已提交的权威历史和产物，不再次运行任务或调用模型。同一任务最多一份最终输出，每个事件及目标最多一条通知；恢复后依赖任务能够消费正确输出。
- 单次及持续通知写入故障、重复完成回调、失败通知关闭和开启都要覆盖。真实业务失败、取消、无可用输出沿用原有语义，不扩大为对所有错误一律忽略。
- 恢复时保留当前总开关、归档和取消门禁；关闭期间应抑制的事件仍永久跳过，不得借恢复补发。

## F2 会话同步保留原子终态保护（P2-01）

- 最终执行的条件更新必须拒绝覆盖 `succeeded`、`failed`、`canceled`；同时按已有终态定义保护 `skipped`。不能仅依靠此前查询得到的非终态快照。
- 仅当合法更新实际影响记录时才执行该迁移对应的通知持久化。迟到的失败或等待同步不改状态、结束时间、失败原因、输出或通知。
- 范围覆盖有通知和无通知的会话关联任务，保留归档保护。复用现有事务及通知步骤，不建立新的通用状态机，也不顺带收紧其他入口的业务语义。
- PostgreSQL 使用真实独立连接和屏障控制查询后、写入前的并发窗口；文件 SQLite 独立验证真实写入串行化、忙重试及终态保护，不把 PostgreSQL 的执行顺序强行套给 SQLite。

## F3 同用户凭证刷新保留通知生命周期（P2-02）

- 区分凭证替换与身份失效。新凭证必须经现有认证服务确认属于同一用户、同一本地实例及受信源后，才能继续使用旧通知对象、点击能力和展示回执进度。
- 刷新期间暂停需要身份的操作并使旧网络响应失效；系统 `show` 回调仍须安全保存为待确认进度，验证成功后使用新凭证补交。不得因正常刷新永久留在 `submitting`，不得重复展示已提交的通知。
- 同一会话重复同步幂等；同用户刷新后的点击仍先查询任务归属，并只打开已有本地路由。
- 退出、换号、实例变化或身份校验明确失败应撤销旧通知及回调。不同用户的新凭证不得继承旧用户通知；认证临时不可用时暂停，不能未经验证沿用身份或发送回执。
- 同时修正主进程 IPC 和通知模块。保留凭证写入串行化、最新会话优先、退出及应用关闭后旧同步不能重启通知的保证。
- 保留 IPC 的窗口、主 frame、origin 校验，禁止重定向及现有请求/文件大小限制。通知状态文件继续不保存凭证和正文。
- 已审的 IPC 测试中“登录加退出必须清理两次”断言与本修复冲突。本方案明确允许在测试阶段将这一实现细节断言改为行为验证：退出立即撤销旧通知，待处理同步不能重启通知；其他安全断言不删除、不弱化。新增真实模块与 IPC 联合验证，不能只检查源码字符串或调用次数。

## F4 手动重试按完整通知链决定是否允许（P2-03）

链身份由用户、执行事件、渠道、账号和接收对象共同确定，不能通过选择祖先、兄弟历史或其他用户的记录绕过。检查和新 Outbox 写入在现有事务与锁保护内完成；分段发送仍由公共 Worker 执行。

拟批准的重试规则如下：

| 请求/当前链状态 | 行为 |
| --- | --- |
| 同一原记录与相同 `idempotency_key` 已创建尝试 | 验证归属后返回已有回执，不创建新记录、不再次发送；后续状态变化不破坏幂等回放 |
| 不同 key，链中有 queued/sending | HTTP 409 `NOTIFICATION_STATE_CHANGED`，不新建尝试 |
| 链中已有 sent | HTTP 409 `NOTIFICATION_STATE_CHANGED`，不能点击失败祖先再次发送 |
| 最近有效尝试 unknown，未确认 | HTTP 409 `NOTIFICATION_CONFIRMATION_REQUIRED` |
| 最近有效尝试 unknown，明确确认 | 重新验证总开关和目标后只创建一个新尝试 |
| 最近有效尝试 failed | 重新验证总开关和目标后允许重试；不能复制更早祖先的旧分段进度 |
| 当前有效尝试 skipped 或目标/配置失效 | 按现有状态、开关及目标错误拒绝，不能绕过永久跳过 |

有效尝试按数据库已有的创建序号确定，不能依赖时间戳相等时的排序或调用者提供的 ID。新尝试保留用户点击的 `retry_of` 审计关系，分段检查点从实际有效尝试继承。历史已有分叉时检查全链的活动/成功记录；有无法消除的未知分支风险时要求显式重复风险确认，不据某一条失败历史放行。

原记录、已确认分段、渲染内容及 Provider 状态保持不可变。相同或不同 key 的并发请求分别验证幂等与互斥；不同通知链不得被误判为同一尝试。权限和内容来源校验继续保留。

## F5 旧任务异步恢复与权威输出回归

- 构造通知配置为 NULL 的旧任务，经过真实聊天完成入口，再由真实工作流完成入口结束异步步骤。直接验证数据库任务状态、最终输出和依赖消费，不能只检查详情接口派生出来的状态。
- 如回调不能完成收尾，复用既有恢复扫描覆盖这类任务，保持每批有界及分页公平性。旧配置始终为 NULL、版本不被回填、通知记录数为零。
- 已配置任务保持“工作流仍 active/waiting 时不提前成功”。取消、失败及归档任务不能被恢复成成功。
- 保留共享输出提取逻辑，本批不新增正文清洗规则。补充完整最终正文、混合过程标签、未闭合标签及产物型输出的真实依赖输入回归；展示截断只影响通知预览。若测试揭示清洗语义与原契约冲突，记录差异后确认，不能悄悄改写权威输出。

## F6 无窗口独立续期（用户后续要求）

- 已确认身份的桌面会话在关闭窗口后继续运行；轮询遇到 401，由主进程使用现有 refresh token 续期。窗口存在时沿用前端刷新，避免两端同时轮换同一个 refresh token。
- 续期使用既有凭证文件的跨进程锁、0600 权限和原子写入；只允许原本地来源，禁止 HTTP 重定向。新令牌通过 auth/me 确认原用户且 active 后才能落为有效凭证并恢复通知；不调用本地管理员会话入口。
- 临时请求失败指数退避至 60 秒；已收到的新令牌若仅身份查询暂时失败，保存在主进程内存并重试核验，不重复消耗旧 refresh token；refresh 明确失效或用户不符停止并要求重新登录。退出、换号、应用终止、实例变化不能被迟到续期恢复。
- 待展示通知、待回执和点击能力延续同一用户生命周期，不重复弹出。旧令牌的迟到网络响应不能影响新令牌。
- 重建窗口先等待正在进行的凭证写入；preload 在页面应用执行前通过受信主 frame 的同步内存查询恢复凭证。此 IPC 不做网络或文件访问，不向其他窗口/frame/来源返回凭证。
- 冷启动在创建窗口前通过内部 CLI 读取既有凭证快照。凭证文件只增加原会话 SHA-256 摘要；必须匹配页面持有的原完整令牌对及 origin 才交接新凭证，登出清除快照。没有额外保存旧明文令牌。
- 不新增生产依赖、后端 API、数据库 Schema、前端页面或新的认证服务。本能力是 Electron 常驻进程续期，不承诺完全退出应用后仍接收通知。

## 其他审查建议的处理边界

- **合并 Core 回查：本批建议暂缓。** 当前 claim 只验证发送门禁，未验证事件正文、目标和版本；直接删除 verify 会削弱来源校验。该建议属于可选的跨服务契约优化，不是上述四项缺陷的必要修复；后续若实施，须先补足 claim 的权威校验及兼容测试，再删除重复请求。
- **后台会话过期：用户后续明确要求补齐，纳入 F6。** 无窗口续期在本批直接实施；复用现有认证端点、凭证文件锁和原子写入，不使用管理员自动登录回退。真机长期运行仍须发布验收。
- **系统和渠道验收：不能用自动测试替代。** Windows 真机、macOS 实际点击/勿扰/通知中心、崩溃后历史通知冷启动、真实三渠道及完整 Compose 记录为独立发布验收项。没有环境或指定收件对象时标记未验证；不发送未经用户指定的真实外部消息。
- 既有审批幂等测试、工作区授权和无关渠道实现不在修复范围；相关回归失败须先确认归因。

## 非功能要求与完成标准

PostgreSQL 与真实文件 SQLite 分别执行持久化、恢复、并发和重试链验证。沿用现有临时 Schema/文件 fixture，只清理本次测试资源，不访问业务库。无 Schema 变化，因此不新增迁移；受影响迁移回归仍按实际需要执行。

沿用现有阈值：Core 恢复循环 2 秒、每页 100 条；桌面查询 5 秒、请求 10 秒、退避上限 60 秒、每轮最多 20 页；外部确定失败最多 5 次、退避上限 300 秒；Outbox 租约 120 秒、续租 30 秒。并发和时间测试使用屏障及可控时钟，不长时间 sleep。

完成须同时满足：四项修复及 F5 公开行为被覆盖；新增测试分别在未修复代码上复现并获 Review；实现后两库及桌面相关回归通过；契约和当前交付说明同步；披露环境缺口及平台发布门槛。代码修复完成与正式发布验收分别报告。
