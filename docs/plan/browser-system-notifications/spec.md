# 浏览器系统通知

2026-09-17：用户明确要求浏览器具备系统通知，并确认页面打开时接收（含最小化/后台标签页）、同一浏览器同站点同用户多个标签页只弹一次。用户进一步要求直接实现生产代码、结束后统一测试，本批按该授权执行，不设置测试前审批停点。

## 范围与复用

- Local、Compose 网页通过现有系统通知渠道（配置字段仍为 `desktop`）显示浏览器原生系统通知。Electron 保持原有主进程实现，不同时启动浏览器消费者。
- 复用原事件、运行快照、标题、200 字符结果摘要、全局开关、登录/令牌刷新、任务查询和投递回执。无新服务、生产依赖、数据库字段或迁移；不修改外部渠道投递。
- 通知标题为任务名称，正文为实际结果摘要。浏览器/系统控制应用标识、站点来源、布局、声音、勿扰和展示。点击验证当前会话并查询任务，有会话打开结果，无会话进入任务中心。
- 网页需安全上下文（HTTPS 或浏览器认可的本机地址）、Notification 和 Web Locks；用户点击授权按钮请求站点权限。普通远程 HTTP 明确显示不可用。Chrome/Edge/Safari/Firefox 是否支持，以实际能力检测和真机验收为准。
- 页面最小化不停止轮询；正常每 5 秒，失败退避上限 60 秒，请求超时 10 秒，每页最多 100 条，每轮最多 20 页。后台节流/休眠可能延迟；关闭全部页面停止接收，重新打开可处理仍在服务端 pending 的记录。无 Web Push、Service Worker 或退出浏览器后的投递承诺。

## 隔离、去重与限制

- `device_id=browser` 是固定浏览器消费类别，不是任意设备地址；全部署允许使用，仍经集中认证且按用户所有权查询/回执。`local` 保持原 Local/Desktop 限制。
- 原渠道采用一次完成状态：回执成功后不向其他接收端广播。未扩展成多设备广播，也不承诺浏览器与 Electron 同时在线时跨两种进程绝对去重。
- 同源、同 API、同用户/租户由 Web Locks 串行协调；持久日志只保存通知 ID 和阶段，不保存凭据/正文。最多 5000 项，淘汰已回执项；日志损坏、不可写或未确认记录占满时停止新展示，不回退为无去重弹窗。
- 先记录 submitting 再调用系统。收到浏览器 show 才记录 shown 并提交 delivered；回执失败仅重交。展示结果未知时不自动再次展示。系统调用与日志不能原子提交，不承诺恰好一次且绝不漏发；清除站点存储会移除客户端去重信息（现有退出登录也清理 localStorage）。
- delivered 只代表浏览器发出了 show 事件，不代表用户看到横幅。无授权时不消费/回执，避免误将同渠道原生客户端的通知标记失败。
- 退出开始即暂停；换号、跨标签页退出、页面卸载取消旧请求、旧通知和旧点击，迟到响应不交付给新用户。

## 完成标准

相关前端行为、双数据库公开 API、原生通知回归通过；真实浏览器验证同源锁及标签页接管；发布构建和契约检查完成；系统实际横幅、通知中心、最小化时的时延与实际点击单列人工验收，不能用模拟事件代表。
