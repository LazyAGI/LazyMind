# 编辑任务保存错误修复

任务描述命中现有内容校验时，算法服务的 matched_word 返回对象，Core 原先按字符串解码，导致界面显示服务器内部错误。与接收群选择无关。

创建和编辑共用原有描述校验：仅读取必需的 passed 布尔值，不解析或回传命中详情。明确拒绝返回 HTTP 400 / 2002919（任务描述包含敏感内容，请修改后再保存）；服务故障或无有效判定返回 HTTP 503 / 2002920（任务描述校验暂不可用，请稍后重试）。保留校验，不修改算法、数据库或通知投递行为。中英文提示复用公共错误目录。

验证：scheduler/sensitive_check_test.go 覆盖通过、对象/字符串命中、空值、缺失判定、错误类型、无效 JSON 和依赖故障；schedule_description_test.go 验证创建和编辑错误响应及原任务不变。运行 scheduler 测试、任务通知草稿回归及错误目录一致性检查。通用构造器全仓检查仍存在 acceptance-model-credentials/recovery.go 的既有未登记错误，与此次改动无关。

最终验证：SQLite 文件数据库及 PostgreSQL 的任务描述/通知草稿回归均通过；scheduler 包通过；公共错误码翻译及直接响应目录检查通过。桌面包已重建并完成 ad-hoc 签名，Local 前端已恢复构建，验收环境 15 项服务 running。实际接口复测：命中描述 HTTP 400 / 2002919，原普通描述 HTTP 200。
