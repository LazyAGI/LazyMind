# PPT HTML 页内渐进渲染 Plan

日期：2026-10-21

状态：暂缓，低优先级；仅记录方案，未实施。

## 结论与收益

当前逐页发布已经能够展示生成进度。页内渐进渲染主要改善等待时的可见反馈，不直接提高内容质量、排版质量，也不保证缩短生成总耗时。需要同时调整生成输出协议、事件传递和前端画布，收益暂不足以支撑当前投入。

本轮只保存计划，不修改生成逻辑、工作流步骤、数据库或运行服务。后续如实际用户反馈表明单页等待体验是主要问题，再评估实施。

## 当前实现

- `workflows/ppt-workflow/scripts/tools.py` 的 `_agent_llm_call` 使用 `stream=True` 消费模型输出，但仍合并为完整字符串后返回。
- `_batch_page_html_publish_progressive` 在单页生成完成后，通过 `_publish_one_page` 按页发布；目前是逐页发布，不是页内组件流式生成。
- `frontend/src/modules/chat/components/WorkflowPanel/ppt/SlotHtmlSlide.tsx` 解析完整 HTML 的素材引用，再通过 iframe `srcDoc` 展示。
- 当前没有背景、图片、标题、正文分别生成与更新的稳定协议。仅抽离前端组件不能实现端到端流式预览。

## 目标与范围

仅针对 `html_deck` 路径，在不增加工作流 step 的前提下实现：

1. 页面尺寸、背景色和基础样式确定后，先显示画布。
2. 已有素材的引用及位置确定后，显示图片；位置未定时保留占位，不猜测坐标。
3. 标题、段落等完整内容块生成后逐块显示，不要求逐字显示。
4. 本页完成并通过现有校验后发布正式 HTML，启用编辑并生成缩略图。

左侧缩略图在生成期间只显示页码或占位，不重复截图。`native_pptx` 不转成 HTML、不接入本方案。

## 推荐设计（待验证）

### 一次调用，分块输出

优先保持一次单页模型调用，先输出布局与样式，再按稳定组件 ID 输出完整内容块。后端组装为现有 HTML 产物，复用保存、编辑和导出链路。

不采用每个组件单独调用模型：这会增加调用数量，并引入风格、坐标和上下文一致性问题。不直接按 `<div>` 或 token 切割现有整页 HTML：标签嵌套、未完成属性及后置 CSS 都可能导致错误或布局跳动。

具体分帧格式应在原型阶段确定；先验证当前模型是否能稳定遵循协议，再决定是否推广。协议至少要区分布局、完整块更新、页面完成，并携带 session、page、generation attempt 和递增序号，防止重试或旧请求污染新预览。

### 临时预览与正式产物分离

- 草稿更新走临时预览事件，不逐 token 创建 artifact 或版本。
- 页面成功后才提交正式 HTML；取消、断线或失败不能覆盖上次成功结果。
- 刷新后优先恢复正式产物；草稿恢复不作为首版要求，也不能因恢复预览重新触发生成。
- 未完成页面不参与导出和点击编辑，不把半成品当作已完成页面。

### 共用画布，分离编辑能力

从现有 HTML 展示中抽出共用画布，支持“生成中只读”和“完成后可编辑”。生成阶段只更新完整块，不每次更新整个 iframe `srcDoc`，避免重复初始化、图片重载和闪烁。

采用受控消息或 DOM 更新前，需验证现有 iframe 安全边界；校验消息来源、页面身份、素材引用和 HTML 内容。不要为了流式预览放宽脚本执行权限。更新做合并与节流，不把完整 HTML 或图片 Base64 反复塞进事件。

布局初始阶段应明确内容区域和样式约束。遇到内容放不下仍需在完成前校验或修复，不能承诺分块显示本身解决排版溢出。

## 实施顺序（全部未开始）

- [ ] 测量当前单页等待时间、首次可见内容时间和前端渲染开销，判断是否值得做。
- [ ] 验证现有流式事件链路能否传递单页草稿块；尽量复用，避免另建工作流状态机。
- [ ] 做单页原型：布局、已有图片、完整文本块、完成信号；验证模型协议遵循率。
- [ ] 抽离只读画布，接入草稿更新；正式 HTML 仍走原发布链路。
- [ ] 增加取消、重试、乱序、刷新和失败保护；缩略图只在完成后生成。
- [ ] 通过功能开关小范围验证；协议失败时丢弃草稿，回退现有整页完成后展示方式。

## 验收与停止条件

- 背景、已有图片、文本块能按条件渐进出现，最终内容与导出的正式 HTML 一致。
- 不能因组件未闭合、后置样式或旧请求事件导致错误页面；不能重复发布或改变版本关系。
- 生成中不反复重建 iframe、不重复生成缩略图，不影响已完成页的编辑和导出。
- 取消、失败、刷新与重试后仍保留原有成功产物。
- 用实际生成任务对比首次可见时间、总耗时、布局跳动、事件流量和前端负载。
- 如果为了实现必须大幅改动工作流框架，或首次可见时间改善有限、最终排版稳定性下降，则停止投入，保留现有逐页发布。
