# PPT 生成性能与恢复验证（2026-09-21）

Chrome 中使用相同原始请求、相同模型 `Qwen/Qwen3.8-Flash-Next`、相同思考深度“高”，生成三页《打工人的周末回血指南》。要求米白与绿色、少字、大图、留白、AI 底图与蒙版。时间来自持久化 `sub_agent_steps` 的工具调用起止记录。

| `ppt_generate_pages`（三页并行，含发布） | 233.40 秒 | 147.17 秒 | 减少约 37% |

这是各一次实测，不是稳定性能保证，也不是整轮工作流耗时减少 39%。第二轮启动时另有约两分钟 MCP 连接超时，并在大纲前遇到下述旧模式错误，多次失败重试使本轮总耗时增加。按用户要求未修改 MCP。

## 已实施的优化

- 首次自动风格与大纲合并为一次模型请求。保留风格目录修复、渲染规则、页数校验与图片绑定；已有有效风格时仅生成大纲。已有标准模式样例需要选择时仍保留选择要求。
- 移除大纲提示词中“封面也必须有 3–6 条要点、所有页面必须有长段落”的要求，优先遵循用户的少字、大图和逐页内容约束。减少重复正文，保留明确要求的事实、数据与清单。
- 页面并行生成，图片预览使用签名 URL；图片内嵌打包推迟到导出。已知底图引用遗漏可在 HTML 中定向修复，避免整页重新请求模型。
- 模型侧工作流状态去掉重复的完整编译图，保留实时节点、边条件、审批与可执行步骤，减少状态落盘后的额外文件读取轮次。
- 大纲阶段记录执行类型与耗时；页面生成已有耗时记录。

## 实测发现并修复的恢复问题

1. **旧 `standard` 模式进入不可达的风格样例环节。** 当前工作流没有样例选择步骤，但模型曾把可编辑导出误解为必须使用 `standard`。新建工作流 deck 统一使用自动风格路径；复用旧 deck 时，仅在既没有样例文件也没有样例选择记录的情况下迁移其模式，保留原目录、素材与底图。
2. **改写请求导致断点失配。** 仅以请求参数的哈希寻找失败断点时，模型改写参数就可能新建 deck。现在工作流会话持久绑定 deck；重复初始化返回已有 deck，查找优先使用本会话绑定，改写重试参数也不会从头建立新 deck。不同工作流会话互相隔离。
3. **失败页导致重复生成成功页。** 成功页保留输入/输出哈希断点，重试仅补失败页；全部发布成功后清除页级重试断点。大纲成功但发布失败时可只重新发布。

第二轮使用的是固定版本工作流，发现模式问题时尚未包含上述两项最新恢复修复。测试中就地修复了旧 deck 模式，并将已生成的三张底图复制到模型错误新建的恢复 deck，没有重新请求图片生成。这不能视为最新自动恢复逻辑的端到端验收；自动恢复通过回归测试验证。

## 验证与限制

- Python 相关回归：288 项通过，另有 18 个子测试通过。覆盖并行显示计划、合并大纲、有效风格保留、失败页续跑、旧模式迁移、改写请求重试、重复初始化与跨工作流隔离。原子写入会话绑定后又单独运行存储恢复测试，10 项通过。
- 第二轮三页全部生成并发布，`failed=0`、`retry_count=0`、`published_count=3`。
- 生成文件检查：三页底图引用存在，图片均可在磁盘找到，含半透明图层，编辑锚点无重复，HTML 无 Base64 图片。
- Chrome 发起实测后 Mac 锁屏，已提示用户解锁；后半程通过日志、持久化步骤和产物检查完成，最终页面视觉复核尚未完成。
- 可编辑 PPTX 的完整导出尚未端到端验证：本地此前报告导出能力不可用。图片签名读取和导出图片嵌入逻辑已有独立验证，不能据此宣称整条导出链路已验收。
- 最终修复已在实测结束后重启 Core 与 Chat 服务加载。新会话使用新工作流版本；已存在会话仍固定使用其创建时的版本。


## 后续：缩略图持久缓存与输出规范化

- 已恢复 `cst/user_workflow_ui` 分支上 `before recording rebase` 的 stash，无冲突。
- 缩略图约定存放在当前浏览器、当前站点的 Cache Storage：`lazymind-slide-thumbnails-v7`。键为会话、页面版本或完整 HTML 指纹；刷新页面或重启本地服务后先读缓存，未命中才截图并保存。PNG 为 Base64，截图前依然内嵌素材图片；主预览保持 URL。最多保存 96 个缓存条目。清除浏览器站点数据或换浏览器会失去这份缓存。
- 内存和磁盘缓存共用版本规则；编辑、草稿版本变化、强制重拍会使用新结果；缓存不可用时退回普通截图。并发请求共用截图任务，失败截图不缓存。
- 输出后处理支持清理 JSON 外围说明、思考标签、代码围栏、字符串以外的尾随逗号；统一有序页码、要点对象与空文本。缺少真实内容和截断 JSON 仍报错，不伪造完成结果。
- HTML 发布前检查完整文档，格式或必需图片不合格时最多修复当前页一次；仍失败时不写入成功页面。沿用成功页续跑断点。
- 本轮相关验证：211 项 Python 测试、20 个子测试；24 项前端测试。包含清空 JS 内存后读取持久截图而不再次调用截图器的验证。

## 后续：内容大纲与增量编辑

- `ppt_build_outline` 改为 preflight → content-outline，仅规划内容、页序和素材绑定。全局样式延迟到页面生成前准备一次，已有样式直接复用；保留旧 style/outline 与样例选择接口。
- 大纲断点不再依赖样式文件，生成阶段补建样式不会让成功的大纲失效。一次新版三页实测：内容大纲工具 28.8 秒，子任务总耗时约 54 秒；不能将两者混为模型生成时间，也不能据此承诺总流程同比提速。
- 明确插入 PPT 页面时，把仍在列表顺序中的旧预览与讲稿保存为当前尝试下的有效快照；保留已选中的编辑，不恢复已删除条目。快照与插入写入同一事务。一般工作流失效规则不变。
- AI 编辑以已校验的产物/源文件内容定位页面，允许展示页序与源文件编号不同。调序后仍可编辑原页面，源内容新鲜度检查保留。
- 未命中短句规则时，模型可以选择新增同级条目、删除、替换文字或修改样式；新增位置与文本段数必须通过校验，模型不能重定向到其他元素。
- 删除用户模式的重试次数展示；重试、断点续跑机制保留。
- 最终 Python 回归：220 项通过、25 个子测试通过；Core workflow 包全部测试通过。新增覆盖旧页有效状态、保留用户编辑、删除页不复活、事务回滚、模型语义兜底与页面调序后预览/应用。
- 用户已自行端测生成流程。本轮未再次操作浏览器；完整可编辑 PPTX 导出端测仍不在已验证范围内。
