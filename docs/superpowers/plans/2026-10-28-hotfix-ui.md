# Composer and Settings Hotfix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the composer add menu discoverable and compact, clarify Developer Mode’s dependent state, and link Skills & Plugins settings to Capability Management.

**Architecture:** Keep the change frontend-only and follow existing React/Ant Design/Sass/i18n patterns. Each UI area gets behavior-level regression tests before the smallest production change; stored preferences and backend contracts stay unchanged.

**Tech Stack:** React 18, TypeScript, Ant Design 5, Sass, React Router 6, Vitest, Testing Library.

## Global Constraints

- Work on branch `fix/hotfix` from `origin/main`.
- Do not alter backend APIs, stored preference semantics, or existing capability routes.
- The composer add trigger remains 32 px on pointer devices and 44 px on coarse-pointer devices.
- The compact resource menu uses natural height; model, featured-capability, and conversation-configuration popovers keep `menuHeight` behavior.
- Resource-menu icons use one 28 px fixed icon box.
- Turning Developer Mode off preserves child preferences while making them inactive and visibly paused.
- Capability Management navigation uses browser-history push semantics.
- User-visible copy must exist in both `zh-CN` and `en-US`.
