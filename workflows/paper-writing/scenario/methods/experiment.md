# Data preparation and bounded experiments

Decide whether the task needs preparation of existing observations, an experimental design, or authorized new execution. Read complete bound tables with original values, units, study conditions, row identities and provenance. Existing observations are not newly measured results. Select the relevant table IDs and report their relation; preserve different measurement scopes rather than merging incompatible batches.

For existing data, return experiment={executed:false, plan:Markdown, results:the exact selected bound DataTable/DataBundle, report:Markdown}, code_files=[] and result_meta with execution_status=not_run, data_origin=user_supplied, method=empirical and actual input_table_ids. Use results={table_ids:[actual bound IDs]} to avoid copying observations. Omit seed and column_types: the shared preparation tool supplies the non-execution seed and preserves types from the bound tables. Omit metrics and assumptions when inapplicable. Preserve original numbers; an F3 confirmation does not claim an independent audit or new experiment.

When a new experiment is needed, design a meaningful hypothesis, baseline, controlled variables, metrics, units, repeats and procedure within the authorized research question. Author real computation code, not hardcoded outcome metrics. CPU Python/numpy/scipy/pandas are available; no network, filesystem access from generated code, installation, GPU or external services. Do not silently replace a large requested experiment with a different tiny study. Explain unavailable resources and missing input.

The code package contains exactly experiment.py, config.json, requirements.txt and README.md. experiment.py declares one literal RESULT_COLUMNS mapping names to string/integer/number/boolean and defines synchronous run_experiment(config, input_data), with exactly those two arguments and no defaults. Return a nonempty list of records matching RESULT_COLUMNS. Configuration is a JSON object. README explains real dependencies, procedure, data requirements and limitations. No imports or code are executed merely by preparing a package.

Call paper_run_experiment only with actual current-task permission bound as experiment_execution=allow_local. Supply the exact authored code and configuration. Local execution is limited to 30 seconds. On failure or timeout report the real condition; never replace failed measurements with invented or simulated numbers. After a lost response query the original operation instead of repeating it. New simulation additionally needs paper_execution_policy.allow_simulation=true, visible assumptions and synthetic provenance; writing/analysis requests never grant it implicitly.

Return output.experiment, output.code_files and output.result_meta using the shapes and schemas from paper_prepare_inputs. executed, execution_status, actual results, elapsed time and logs must match the real receipt; include that receipt in receipts. Designs without execution have executed=false and no observed result. Synthetic or absent results require an honest is_demo flag and limitations. Do not submit the old intermediate design/preview schema as the final business object. Check code/config/result identity, units, actual permission and provenance before candidate preparation.
