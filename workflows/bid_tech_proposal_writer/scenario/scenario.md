# 投标技术方案编写

## 场景说明

本工作流用于把一份中文招标文件转化为可追溯、可逐步审阅、可下载的 Markdown 或 Word 技术方案正稿。
它遵循原始 `bid-tech-proposal` 的核心模式，并补充启动前参数预检、独立知识库检索和两个人工审批点，共九步；所有路径、临时目录和工具调用都按 LazyMind
工作流运行时处理，不依赖原 skill 所在目录。

启动前必须提供：招标文件、导出格式（md/docx）、目标总字数，以及是否使用默认 DOCX 投标样式。用户已经明确的值直接绑定；缺项时一次性询问，不自行猜测。字数可使用 5000、10000、20000、30000 或用户给出的其他明确值；DOCX 不使用默认样式时采用 Word 基础样式。

参数问答属于 Session 创建前的 Workflow preflight，不显示为业务节点。只有四项启动输入全部明确并绑定后，才创建 Session 并进入以下九步。

## 九步流程

1. **招标文件解析（`parse_bid_document`）**：规范化已确认参数，并用工作流专属解析器读取 DOCX、PDF、TXT、Markdown、HTML 或 RTF，保留标题、编号、表格和来源元数据。
2. **技术要求提取（`extract_tech_requirements`）**：解析完成后与废标项分析并行执行；机械扫描与专家复核结合，形成 `BG/FUNC/PERF/SEC/SVC/IMPL-NNN` 稳定 ID 池。
3. **废标项聚焦（`extract_disqualification_items`）**：解析完成后与技术要求分析并行执行；区分明确否决条款和高风险提醒，保留原文、出处、指标及应答策略。两路产物齐备后才进入资料检索。
4. **知识库资料检索（`search_reference_materials`）**：仅在会话指定知识库时执行一次单意图项目检索，使用通用检索默认参数，保留来源并将完整证据注入 Writer；未指定或单次调用失败时如实记录并继续。
5. **章节大纲审批（`build_chapter_outline`）**：复用 LazyMind Writer 生成/修改大纲并校验；产出后强制暂停，用户可编辑、AI 润色和保存版本，点击“保存并继续”后才写正文。
6. **完整正文审批（`write_chapter_contents`）**：复用 Writer 生成或修订正文；产出后再次暂停，用户可编辑、AI 润色和保存版本，点击“保存并继续”后才生成配图和交付文件。
7. **架构图与效果图（`generate_proposal_images`）**：不调用文生图模型；使用本地 PIL 代码生成 1 张架构图和 5–10 张不同布局的 16:9 功能效果图。
8. **技术方案导出（`compose_proposal_docx`）**：按确认参数导出 `.md`，或使用默认投标样式/Word 基础样式生成真实 `.docx`。
9. **文档结果校验（`validate_proposal`）**：检查总字数、章节完整性、技术要求覆盖、废标项应答、图像数量和所选交付文件完整性。

## 写作纪律

- 正文主语按语境使用“本投标方案 / 本平台 / 本系统”，不使用“我们”或含糊的“本方案”。
- 不写“招标文件要求……”“本节从……展开”“我们认为……”等对照式或流水账句式。
- 不写“不涉及 / 不包含 / 暂不提供 / 后续版本”等防御性表达。
- 数字、标准、政策和产品能力只可来自招标原文或用户明确材料；不得编造。
- 每个 `bid_requirements_refs` 与 `disqualification_refs` 必须在对应正文中明确覆盖。

## Writer 复用与修订

- 大纲和正文的语言模型规划、流式写作、AI 修改均调用 LazyMind 已有 Writer Toolkit；工作流只保留投标约束适配和文件落盘。
- 指定知识库时由 LazyMind `kb` 框架检索，检索证据与招标要求共同进入共享 Writer 资源画像；工作流适配器另将完整检索证据保留为锁定写作事实，防止通用摘要压缩丢失具体资料。
- 用户可直接编辑 `outline_document.md` 和 `draft_document.md`。后续步骤始终读取最新选中修订，不使用隐藏副本。
- 大纲和正文步骤均为 `human` 审批模式；编辑器保存完成后，“保存并继续”才会推进。选区 AI 润色沿用 Writer 的 `rewrite_selection` 能力。
- 人工改动大纲后，正文步骤会重新构建并校验 `effective_outline`，确保 DOCX、配图和最终校验使用同一版大纲。
- 工作流的选区改写调用 Writer 修订能力生成预览，用户确认后写入同一槽位的新版本。

## 注意事项

- `.docx`、`.pdf` 是推荐输入格式；旧 `.doc` 仅在 LazyMind 运行容器可用 LibreOffice 或 pandoc 时直接支持。
- 图片数量与类型按项目功能选择，最低为 1 张架构图加 5 张效果图，不固定为两张或四张。
- 每一步的产物都可独立审阅；重跑某一步时应复用已选定的上游产物，不要重新解释整个任务。
