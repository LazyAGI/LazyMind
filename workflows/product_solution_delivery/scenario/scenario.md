# 产品方案与交付

## 场景说明

这是从 `product-solution-delivery` Skill 适配而来的内置产品工作流。它把七个原子业务
阶段排列成一张可裁剪的顺序 DAG：产品方向、竞品与生态位、产品方案、PRD、交互原型、
方案评审和研发交付。聊天入口在启动前收齐参数；首个资料检索节点只做确定性规范化，不在
计划中的阶段由 `skip_if` 直接绕过，对应卡片 Tab 通过 `hide_when_material` 隐藏。

因此同一工作流同时支持：

- 单阶段：只运行用户点名的一个阶段；
- 局部链：只运行用户明确授权的最短前向阶段链；
- 全量链：仅在用户明确要求全流程时运行七阶段；
- 中途进入：用户提供等价上游材料后直接从 PRD、原型、评审或交付开始。

详细来源、业务合同映射、LazyMind 原生替代和能力边界见 `SOURCE.md`。

## Workflow 启动前参数

- 显式阶段或阶段链优先，材料只影响依赖满足情况，不擅自增加阶段。
- “当前阶段完整梳理”只表示该阶段采用 `full` 深度，不等于运行七阶段。
- 只有“全流程”“七阶段”或“从零做到研发交付”等明确表达才选择全量链。
- 必须确认产品目标、阶段链和执行深度；文本阶段还需确认每份目标字数，以及参照样例/模板
  或默认结构。用户已经明确的值直接绑定；缺失项通过聊天入口的 `ask_user` 交互卡一次性补问，
  不进入 Workflow 节点。选择已提供样例时绑定对应附件。
- 若必要上游产物既未上传、也不会由本次链的前序阶段生成，则请求补充；用户明确授权时
  可以生成标注缺口的草稿。
- 参数未齐全时不触发 Workflow，也不创建“意图识别/询问参数”业务节点。

## 数据流与人工控制

1. **共享检索**：确定性规范化预检参数并生成跳过标记；对用户附件画像一次，按整条链的
   决策需要检索已选知识库和公开网页。
2. **文本阶段**：方向、方案、PRD、评审、交付分别复用 LazyMind Writer。每个阶段先生成
   可编辑大纲并暂停；用户继续后分章流式写作，再次暂停供全文编辑和 AI 润色。
3. **HTML 阶段**：竞品形成自包含可追溯报告；原型形成自包含交互 HTML，均暂停审批。
4. **跨阶段接力**：后续 Writer 上下文显式画像本次运行中已经批准的上游产物，不只依赖
   控制边；用户修改后的 Markdown 是下一步唯一权威版本。
5. **交付总结**：依据 LazyMind Session、Slot 和 Artifact revision 总结实际完成和跳过的
   阶段、版本、依赖及缺口，不再生成一套容易漂移的平行 Manifest/Workspace JSON。

## 能力边界

工作流不声称登录态产品操作、付费资料访问、浏览器视觉 QA、生产前端实现、技术架构、研发
估时、发布日期或组织审批。runtime trace 和内部路径不展示在用户正文中。
