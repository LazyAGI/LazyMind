# 全阶段双格式富文本呈现合同

适用 direction、competitive、design、prd、prototype、review、handoff。只增强呈现，保留原有章节、字段、顺序、业务结论、证据边界、两层 Router 和工作流。

## 同一逻辑产物

交付默认自包含交互 HTML 与可编辑、可下载 Markdown，共用 Artifact ID、版本、事实、决定、建议、证据、状态和待确认项，不分别自由起草。
文本阶段由同一 Markdown 确定性渲染 HTML；竞品和原型在一次有界交付中成对输出，Markdown 覆盖同一语义范围并提供图形的文字替代。
Manifest 同版登记两种表示。缺失、空白或关键结论不一致时保持草稿；修改任一表示都重新核验一致性。

## 结构与表达

沿用阶段合同或用户样例确定的结构。图表进入最相关的现有章节，不新增可视化专章，不因配图拆分、合并或重排章节。
图形不能替代规则、异常、验收、依据或待确认项。一个章节通常不超过一张主图，不设置机械配图配额，不把结论重复成图、表和长段正文。

| 内容关系 | 表达 |
|---|---|
| 三个以上对象共享字段 | 紧凑 GFM 表格 |
| 多步骤、分支、依赖 | fenced Mermaid flowchart |
| 状态与转换条件 | stateDiagram-v2 |
| 多角色交互顺序 | sequenceDiagram |
| 真实里程碑或阶段顺序 | timeline 或短时间线表 |
| 两个明确的取舍维度 | quadrantChart；无数值时注明定性相对位置 |
| 项目已有真实界面或原型 | Markdown 图片、前后对照 |
| 简单结论 | 摘要或短段落，无须强行画图 |

图中对象、术语、节点、数值、日期、状态、位置与正文同源同版；无真实日期只用 T0、T+1 或阶段顺序。
图片仅使用项目提供且可访问的真实截图、原型或可追溯图表，不生成装饰图、想象截图或无法核验的事实图。
每图只回答一个问题，节点用短语；长流程拆主路径与异常恢复，不缩字号硬塞。图后留一两句重点、异常或待确认说明，渲染/导出失败也能独立理解。

## 阅读、交互与阶段重点

HTML 不依赖外部脚本、字体、样式或 CDN；真实来源 URL 只作普通链接。使用语义表格、内联 SVG 和目录/折叠/源码/打印导出等阅读交互；原型另保留业务交互。
SVG 包含 title、role="img"、aria-label。桌面/移动正文不横向溢出，宽表和大图可局部滚动；关键结论默认可见，仅证据明细、源码和长附录可折叠。
Markdown 用 GFM 表格、图片及 fenced Mermaid，不依赖自定义 CSS/脚本。浏览器或导出不支持交互时保留紧邻文字说明。
方向强调问题链、取舍和验证顺序；竞品强调同口径对比、生态位、证据时间线和定位，继续遵循其专属研究/可视化证据合同。
方案强调任务流、对象、状态和真实界面对照；PRD 强调主/异常流程、状态、权限矩阵、必要时序；原型以实际交互屏幕为主，页面流和状态画廊仅辅助。
评审用影响链、定性风险分布和编号界面证据，标记关联发现及复验方式；交付用依赖图、门禁顺序及需求—页面—验收矩阵，不捏造排期。
方案只呈现实际选中的 light 或 heavy 分支，不为未选分支生成空框、占位或证据区。只写真实采用的证据和决定，不展示 Router、执行深度或判定过程。

## Workflow 完成规则

生成/修订 → 验证 → 保存，文件生成本身不代表完成。调用 validate_product_stage_assessment(value={"stage":"当前阶段","status":"draft",...})，stage 放在 value 内。
遵循 authoritative stage-aware JSON Schema，省略可选空集合，不另造字段层级；一次修复全部错误，只重试一次。规范化 JSON 保存为 <stage>_assessment，未保存不得结束。
检查必须有真实依据，未执行记 not-checked；缺失/冲突的必需输入及未经桌面/移动交互验证的原型保持 draft；仅 handoff 在必需检查和依赖通过后可声明实施就绪。
决定保持 proposed；阶段衔接时 Host 记录默认接受的系统来源，不编造用户 acceptance_ref。契约只加载一次，reference_paths 仅接受包内 references/*.md，不接受产物、工作区或 Writer 路径。
保存后只回复不超过 80 个中文字的自然状态句，不暴露 assessment/Manifest/Workspace JSON、运行路径、章节列表、工具诊断或长总结。
